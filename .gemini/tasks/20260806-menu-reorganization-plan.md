## 1. Phase 0 — 도달 불가 화면에 메뉴 부여 **(결정 불요 · 즉시)**

가장 시급하고 판단이 필요 없는 항목이다. **완성돼 동작하는 화면이 메뉴에 없어 URL 직접
입력으로만 도달한다.**

### 1-1. 로그 화면 3종 + 대시보드

| 화면 | 상태 | 메뉴 |
|---|---|---|
| `/admin/system/logs` (대시보드, 357줄) | 동작 | **없음** |
| `/admin/system/logs/web` | 동작 · **28,104행 수집 중** | **없음** |
| `/admin/system/logs/user` | 동작 | **없음** |
| `/admin/system/logs/privacy` | 동작 · ADMIN 전용 | **없음** |
| `/admin/system/logs/login` | 동작 | 9040340 ✔ |
| `/admin/system/logs/system` | 동작 | 9040350 ✔ |

이 3종은 **2026-08-05 에 내(에이전트)가 배선한 것**이다(#298·#299·#300). API·화면·테스트까지
만들고 **메뉴를 만들지 않았다** — 이 저장소가 반복해 겪은 "완성됐는데 도달 불가" 를
내가 메뉴 계층에서 되풀이했다. `UnreachableServiceLinterTest`(#304)는 `@Service` 만 보므로
이 층은 잡지 못한다.

**제안**: `9040000 감사 및 통계 모니터링` 하위에 4건 추가.
개인정보 로그는 `@AdminOnly` 이므로 `tb_menu_crt_dtl` 권한 매핑을 ROLE_ADMIN 만 부여할 것.

### 1-2. 그 밖의 살아 있는 고아 화면

| 라우트 | 규모 | 판단 |
|---|---:|---|
| `/admin/system/ism` | 430줄 · API 2 | 비공식결재 관리. 백엔드 실재(`InformalSanctionApiController`) → **메뉴 필요** |
| `/admin/stats` | 998줄 · API 2 | 통계 허브. 하위 통계 메뉴 6건은 있는데 허브 자체는 없음 → **검토** |
| `/admin/security/login-policy` | 387줄 · API 1 | `/admin/user/login-policy`(38줄)와 **이원화** → 어느 쪽이 정본인지 판정 필요 |
| `/admin/observability` | 231줄 · API 1 | 9040330 이 `/admin/system/monitoring/hub?tab=observability` 를 가리킴 → **중복 가능** |
| `/admin/system/{network,audit,policies}` | 278~405줄 | 각각 살아 있음. `monitoring/hub` 탭과 관계 확인 필요 |

> Phase 0 은 **화면을 만들지 않는다.** 이미 있는 것에 도달 경로만 잇는다.

## 2. Phase 1 — 기계적 정리 **(저위험 · 결정 최소)**

### 2-1. 테스트 쓰레기 삭제

| menu_sn | 이름 | 경로 |
|---|---|---|
| 8744343 | `test1` | `/admin/community/boards/selectBoardList?bbsId=BBSMSTR_000000000160` |
| 8808554 | `test` | `/admin/community/boards/selectBoardList?bbsId=BBSMSTR_000000000120` |

이미 `use_yn='N'` 이나 **행 자체가 남아 계측·감사에 노이즈**를 만든다.
`tb_menu_crt_dtl` FK 확인 후 물리 삭제 권장(FK 가 있으면 그대로 두고 이름에 `[삭제예정]` 표기).

### 2-2. 카테고리 메뉴를 순수 폴더로

최상위 3개가 **특정 하위 화면을 가리켜** 중복을 만든다.

| menu_sn | 이름 | 현재 route | 중복 상대 |
|---|---|---|---|
| 2000000 | 💬 커뮤니티 및 콘텐츠 | `/admin/community/boards/master` | 9030140 통합 게시판 마스터 콘솔 |
| 9000000 | ⚙️ 시스템 관리 센터 | `/admin/user/manage` | 9020310 계정 및 사용자 관리 |

**제안**: `modern_route = NULL` 로 폴더화. 활성 메뉴 77건 중 **6건이 이미 빈 route 로 폴더 역할**을
하고 있어(`1060000`·`9010000`·`9020000`·`9030000`·`9040000`·`800000000`) 새 관례가 아니다.
`1050000`(전자결재)에 V2_45 로 이미 같은 처방을 적용했다.

> `1000000 🏢 워크스페이스 → /admin/work-hub` 는 **중복이 아니다**(그 경로를 가리키는 다른 메뉴 없음).
> 다만 일관성을 위해 함께 폴더화할지는 결정 사항.

## 3. Phase 2 — 중복 경로 정리 **(판단 필요 · 중위험)**

Phase 1(2-2·2-3)을 적용하면 9건 중 **5건이 자동 해소**된다. 남는 것은 아래 4건이다.

### 3-1. `/admin/collaboration/mail-history` — **4중복, 가장 심각**

| menu_sn | 이름 | 위치 |
|---|---|---|
| 1020000 | 메일 및 통합 메시지 센터 | 워크스페이스 하위(부모) |
| 1020300 | 쪽지함 | 1020000 의 자식 |
| 2020000 | 협업 | 커뮤니티 하위(부모) |
| 9040200 | 발송메일내역 | 감사·통계 하위 |

**같은 화면을 네 이름으로 부른다.** 그중 '쪽지함' 은 별도 화면(`/note`, 메뉴 1020400 💌 업무 쪽지함)이
따로 있어 **이름이 실제와 어긋난다.**

**제안**:
- 1020000 → 폴더화 (2-2 처방)
- 2020000 '협업' → 폴더화 (자식 2020100 스크랩 목록이 있음)
- 1020300 '쪽지함' → **이름 정정** 또는 삭제. 진짜 쪽지함은 1020400 이다
- 9040200 '발송메일내역' → 유지 (감사 맥락에서 같은 화면을 보는 것은 정당)

→ **이름 정정은 정보구조 결정**이므로 사용자 판단 필요.

### 3-2. `/admin/system/monitoring/hub?tab=security` — 3중복

| menu_sn | 이름 |
|---|---|
| 9020100 | 통합 보안 및 접속 정책 (부모) |
| 9020110 | **로그인** ← 무엇을 뜻하는지 알 수 없다 |
| 9040310 | 보안 감사 로그 |

**제안**: 9020100 폴더화(2-3), 9020110 은 **레거시 잔재로 보이므로 삭제 또는 개명**.
9040310 은 감사 맥락이라 유지.

### 3-3. `/admin/stats/user` — 다른 이름, 같은 화면

| menu_sn | 이름 |
|---|---|
| 9040102 | 사용자통계 |
| 9040103 | **접속통계** |

'접속통계' 는 별개 기능이어야 하는데 **대응 화면이 없어 사용자통계로 보내고 있다.**
사용자는 다른 것을 기대하고 눌렀다가 같은 화면을 본다.

**제안**: 접속 통계 화면을 만들 계획이 없다면 **9040103 삭제**. 만들 계획이 있다면 그때까지 숨김.

### 3-4. `/admin/sanctn/forms` — **이미 해소됨**

V2_45 가 1050000 폴더화 + 9030200 숨김을 적용했다. 계측이 미적용 DB 기준이라 아직 보인다.

## 6. 실행 시 지켜야 할 것

1. **메뉴 삭제 대신 `use_yn='N'`** — `tb_menu_crt_dtl(menu_sn, authrt_cd)` 이 `menu_sn` 을 PK 로
   참조한다(V2_12 FK). 물리 삭제는 권한 매핑까지 정리해야 하고 되돌릴 수 없다.
   V2_27·V2_28·V2_30 이 이미 채택한 방식이다. *(test/test1 은 예외 검토 — 진짜 쓰레기)*
2. **부모를 숨기기 전에 자식을 확인** — V2_45 에서 `1050000` 을 숨겼다면 **살아 있는 결재함이
   사이드바에서 사라졌을 것**이다. 부모는 숨기지 말고 폴더화한다.
3. **라우트 파일은 지우지 않는다** — 문자열 URL 참조는 정적 분석 대상이 아니다(V2_30, 13개 오삭제).
   리다이렉트로 처리한다.
4. **각 단계 후 `node scripts/menu-census.mjs` 재실행** — 숫자로 성과를 확인한다.
5. **마이그레이션은 멱등하게** — 대상 `menu_sn` 과 현재 값 조건을 함께 건다.
