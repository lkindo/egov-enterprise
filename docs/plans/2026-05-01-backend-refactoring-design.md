# Backend Refactoring Design: Domain Integrity & Performance Optimization

**Date**: 2026-05-01
**Status**: Validated
**Focus**: Backend Domain Integrity, Query Performance, Implementation Consistency

## 1. Executive Summary
The goal of this refactoring is to standardize implementation patterns across the `api-server`, `business-suite`, and `foundation` modules. Key improvements focus on optimizing data retrieval performance through QueryDSL Projections and standardizing data mapping using MapStruct.

## 2. Architecture & Patterns

### 2.1 Standardized DTO Mapping (MapStruct)
- **Goal**: Replace inconsistent mapping patterns (manual mapping, static factory methods) with a standardized MapStruct approach.
- **Action**:
    - Implement `MapStruct` mappers in all service packages.
    - Deprecate static `from()` methods in DTOs where complex logic is involved.
    - Ensure clean separation between Domain Entities and API DTOs.

### 2.2 QueryDSL DTO Projections
- **Goal**: Resolve N+1 query issues and reduce Service layer complexity.
- **Action**:
    - Extend all domain repositories with `RepositoryCustom` interfaces.
    - Implement search and list logic in `RepositoryImpl` using `Projections.fields` or `Projections.constructor`.
    - Services should call the repository and receive DTOs directly for read-only operations.

### 2.3 Layer Isolation (Enums & Types)
- **Goal**: Prevent domain-specific types from leaking into the Web layer (Controllers).
- **Action**:
    - Replace direct usage of Domain Enums (e.g., `nuri.foundation.domain.user.entity.Role`) in Controllers with DTO-specific Enums or primitive types.
    - Ensure all API inputs/outputs are strictly defined in the `dto` package.

## 3. Validation & Exception Handling

### 3.1 Bean Validation (@Valid)
- **Goal**: Automate simple field validation and reduce boilerplate in Services.
- **Action**:
    - Add Jakarta Validation annotations (`@NotBlank`, `@Size`, etc.) to all Request DTOs.
    - Use `@Valid` in Controller methods.

### 3.2 Global Exception Handling
- **Goal**: Ensure consistent API responses for all failure scenarios.
- **Action**:
    - Maintain the `GlobalExceptionHandler` pattern to wrap all `BusinessException` instances into the standard `ApiResponse` format.

## 4. Implementation Roadmap

1. **Phase 1: Foundation Cleanup**
    - Standardize `UserService` and `UserMapper`.
    - Fix Enum leakage in `UserApiController`.
2. **Phase 2: Business-Suite Optimization**
    - Refactor `BoardService` to use QueryDSL Projections for list/detail views.
    - Move mapping logic from static methods to MapStruct.
3. **Phase 3: Validation Audit**
    - Add `@Valid` annotations to all major API entry points.
    - Remove redundant `required()` checks in Services for simple field validation.
