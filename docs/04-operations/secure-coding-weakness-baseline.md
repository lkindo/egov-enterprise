# 시큐어코딩 보안약점 사전 점검 기준선

행정안전부·KISA의 구현단계 보안약점 49개를 축으로, 항목마다 CWE·OWASP와 이 저장소의 현재 탐지 수단을 대응시킨 기준선이다. 항목별 정본은 [원장](../../config/security/secure-coding-weaknesses.json)이고, 이 문서는 기준·판정 규칙·현재 대응 요약·다음 단계를 설명한다.

## 이 기준선이 증명하는 것과 증명하지 못하는 것

- 증명하는 것: 각 보안약점을 어떤 자동 규칙·하네스·시험이 보고 있는지, 어디가 비어 있는지.
- 증명하지 못하는 것: 보안약점이 "없다"는 판정. 원장의 모든 항목은 `review: pending`(수동 확인 전)으로 시작한다. CodeQL 규칙이 있다는 사실은 그 분류를 분석한다는 뜻일 뿐, 이 저장소의 프레임워크 경로를 모두 모델링한다는 뜻이 아니다.
- 공식 진단이 아니다: 공공 정보화 사업의 보안약점 진단은 「행정기관 및 공공기관 정보시스템 구축·운영 지침」에 따라 인증받은 진단도구와 진단원으로 수행하는 것으로 알려져 있다(조문은 국가법령정보센터 원문으로 확인한다). CodeQL은 그 인증 도구가 아니다. 공식 진단은 [기관 도입 수명](../03-guides/governance-review-lifecycle.md)의 통제로 다루고, 이 기준선은 그 전에 약점을 제거하고 회귀를 막는 데 쓴다.

## 기준(2026-10-20 고정)

| 기준 | 판 | 쓰임 |
|---|---|---|
| 소프트웨어 개발보안 가이드 구현단계 보안약점 | 2021.11 개정, 49개 | 원장의 축. 항목 명칭·분류는 KISA 「JavaScript 시큐어코딩 가이드(2022)」 부록 제1절 「구현단계 보안약점 제거 기준」과 같다 |

| OWASP Top 10 | 2025 | 항목별 대응(판단 대응이며 OWASP가 정한 대응표가 아니다) |

| KISA 시큐어코딩 가이드 | Java, JavaScript(2022) | 백엔드·프런트엔드 항목별 안전한 코딩 기법 |
| CodeQL | 2.26.4, `security-extended`(실행), `security-and-quality`(감사용) | [SAST 정책](../../config/security/sast-policy.json)과 같은 엔진 판 |

## 원장 읽는 법

[원장](../../config/security/secure-coding-weaknesses.json)의 항목은 다음을 가진다.

- `id`: 분류 약어와 번호(IV 입력데이터 검증 및 표현, SF 보안기능, TS 시간 및 상태, EH 에러처리, CE 코드오류, EN 캡슐화, AM API 오용).
- `cwe`·`matchCwe`: 가이드가 정한 CWE와, CodeQL 규칙을 찾을 때만 쓰는 하위·인접 CWE.
- `automation`: 언어별 자동 탐지 수준.
  - `blocking`: required `secure-coding`이 점수 7.0 이상 탐지로 차단한다.
  - `report`: 실행 스위트가 탐지하지만 점수 7.0 미만이라 리포트에만 남는다.
  - `quality-only`: 규칙이 `security-and-quality`에만 있어 지금은 실행하지 않는다.
  - `none`: 이 CodeQL 판에 해당 규칙이 없다.
- `codeql`: 대응 규칙 목록. 규칙의 `external/cwe` 태그가 `matchCwe`와 겹치면 대응으로 보았다. Android·Electron·Angular·JHipster 전용 규칙은 이 저장소에 대상 코드가 없어 뺐다.
- `controls`: 규칙 밖에서 그 약점을 막거나 고정하는 하네스·시험·코드 위치.
- `applicable`: Java·TypeScript에서 성립하지 않는 항목은 `false`와 근거를 둔다.
- `next`: 수동 검토 단계에서 확인할 일.

`codeql`·`automation`은 [대조 도구](../../scripts/secure-coding-weaknesses.mjs)가 고정 판 CodeQL의 두 스위트 규칙 메타데이터에서 계산한다. 판정·통제·수동 검토 필드는 도구가 손대지 않는다.

- `CODEQL_PATH=<CodeQL 2.26.4> node scripts/secure-coding-weaknesses.mjs map`: 원장의 대응이 고정 판 규칙과 같은지 본다. 다르면 항목 ID를 보이고 종료 코드 1이다.
- `... map --write`: CodeQL 판을 올린 뒤(`sast-policy.json`의 `codeqlVersion`) 대응을 다시 만든다. 새로 생기거나 빠진 규칙은 diff로 검토한다.
- `node scripts/secure-coding-weaknesses.mjs summarize <sarif>...`: 감사 SARIF의 탐지를 항목별·규칙별로 센다. 결과는 표준 출력으로만 낸다.

이 대조를 CI 계약으로 묶는 일은 아래 4단계 몫이다. CodeQL 실행 파일이 필요해 운영 계약에서는 돌지 않는다.

## 현재 대응 요약(2026-10-20)

적용 항목 46개(해당 없음 3개: IV-16 메모리 버퍼 오버플로우, CE-03 해제된 자원 사용, CE-04 초기화되지 않은 변수 사용).

| 자동 탐지 수준 | Java | JavaScript/TypeScript |
|---|---|---|
| 차단(`blocking`) | 25 | 26 |
| 리포트만(`report`) | 3 | 3 |
| 품질 스위트에만 있음(`quality-only`) | 5 | 4 |
| 규칙 없음(`none`) | 13 | 13 |

- 차단 기준 미만이라 리포트만 남는 항목: IV-07 신뢰되지 않는 URL 주소로 자동접속 연결, IV-13 HTTP 응답분할(Java), EH-01 오류 메시지 정보노출, IV-06 위험한 형식 파일 업로드(JS). 49개 기준에서는 점수와 관계없이 제거 대상이므로 리포트 결과도 감사 목록에 넣는다.
- 두 언어 모두 CodeQL 규칙이 없는 항목 8개: SF-01·09·12·13, EN-01·02·04, AM-01. 이 가운데 SF-01·09·13은 하네스·시험·gitleaks가 대신 보고, 나머지는 수동 검토나 보조 도구가 필요하다. SF-06 하드코드된 중요정보는 JS 규칙이 설정 파일의 빈 비밀번호만 보므로 소스의 비밀은 하네스와 gitleaks가 맡는다.
- 승인된 CodeQL 예외는 없다. 2026-10-21 기존 6건(IV-11 CSRF 2건, IV-15 보안기능 결정 입력값 2건, 49개 밖 2건)을 코드에서 해소하고 [예외 원장](../../config/security/false-positive-review.json)을 비웠다([해소 기록](sast-findings-review.md#2026-10-21-예외의-근본-해소)).

## 수동 검토 우선순위

규칙이 없거나 규칙만으로 판정할 수 없는 항목부터 본다.

1. SF-02 부적절한 인가: 객체 단위로 타인 자원에 접근할 수 있는지. 하네스는 기능 권한과 선언된 자원 관계 가드를 보지만 모든 소유 판정을 보지는 않는다.
2. SF-01 적절한 인증 없는 중요 기능 허용: 인증 없이 열린 경로 목록.
3. IV-06 위험한 형식 파일 업로드: 업로드 프로필별 허용 목록·크기·저장 위치·실행 권한.
4. EN-01 잘못된 세션에 의한 데이터 정보노출: 싱글톤 빈의 가변 필드, Next 서버 모듈 수준 상태가 요청 사이에 공유되는지.
5. SF-12 쿠키 정보노출: 영속 쿠키에 담는 값과 만료 기간.
6. EH-01 오류 메시지 정보노출: 오류 응답의 메시지 노출 설정과 전역 처리기.
7. IV-01 SQL 삽입: 네이티브 SQL·JDBC 저장소의 쿼리 조립.
8. 기관 통제로 넘길 항목: SF-04 검증필 암호모듈(KCMVP) 해당 여부, SF-14 레거시 비밀번호 해시의 잔존·전환.
9. SF-15 무결성 검사 없는 코드 다운로드: Gradle wrapper 배포 체크섬과 의존성 검증 도입 여부.

## 49개 밖의 OWASP 영역

49개는 구현단계 코드 약점이라 OWASP Top 10:2025의 일부를 다루지 않는다. 다음은 기존 수단이 따로 맡는다.

| OWASP | 기존 수단 |
|---|---|
| A03 소프트웨어 공급망 실패 | OWASP Dependency-Check(주간), `pnpm audit` 정책, PR 의존성 검토, GitHub Actions 커밋 SHA 고정 |
| A06 안전하지 않은 설계 | ADR과 인가 원장. 위협 모델링은 별도 활동이다 |
| A09 보안 로깅·경보 실패 | 감사 원장과 그 수정 차단 트리거(DEC-OPS-357), [관측성 기준](observability-baseline.md) |

## 결과 공개 범위

이 저장소는 공개 저장소다. 조치하지 않은 약점의 위치·재현 방법·영향은 커밋·PR·이슈·공개 산출물에 쓰지 않는다. 미조치 결과는 저장소 밖 비공개 공간이나 GitHub 비공개 보안 권고에 두고, 공개 기록에는 조치한 뒤의 요약만 남긴다. 이 원장에는 탐지 수단과 확인할 일만 적는다.
