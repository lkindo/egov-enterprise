eGov Enterprise Verification Architecture

Harness Pipeline & Verification Tests

개발자 코드 작성부터 병합 적격 판정까지의 실행 경로와 백엔드 하네스 테스트 클래스 카탈로그

상태: 중복 삭제 후보. 새 거버넌스 설명은 Governance Harness Atlas를 사용한다. 이 페이지는 백엔드 하네스 카탈로그를 이해하기 위한 파생 뷰이며 실행 결과나 전수 보장을 선언하지 않는다. 현재 규칙은 AGENTS.md, 실행 태스크는 api-server/build.gradle, 병합 필수 잡은 required-checks.json이 정본이다. 전체 거버넌스 구조와 migration-tool 범위는 Governance Harness Atlas에서 본다.

1부. 하네스 생애주기 파이프라인 (Lifecycle Pipeline)

01

변경 범위 판정

AGENTS.md와 관련 헌법을 읽고 변경 범위에 맞는 검증과 계약 생성물 갱신을 선택

codegen:file AGENTS.md scope verification
02

Git Pre-push 게이트

공용 메모리·문서 링크를 항상 검사하고, source 변경이면 컴파일·lint·codegen·하네스 실행

pre-push compileJava harnessTest
03

GitHub Actions CI

required jobs가 빌드·테스트, 커밋된 계약, secret scan, 실제 PostgreSQL 스키마 검증을 독립 집행

secret-scan Testcontainers mutation-score
04

Required E2E & 병합 적격

Playwright 3개 샤드와 뮤테이션 집계 등 required checks가 모두 성공해야 병합 가능

Playwright e2e-tests main merge
