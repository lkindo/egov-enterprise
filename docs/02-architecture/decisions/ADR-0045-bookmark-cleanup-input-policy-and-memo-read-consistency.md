# ADR-0045 — 즐겨찾기 명시적 정리, 엄격 입력 검증, 읽은 메모 기준 지시

- 상태: Accepted
- 결정일: 2026-10-30
- 승인: 사용자가 도메인 개선 계획의 순차 실행을 요청하고, 즐겨찾기는 “기본 보존 + 본인이 명시적으로 정리”, 메모 지시는 “읽은 본문·첨부 기준으로 저장”, 기존 비정규 입력은 “엄격 검증과 수정 안내 적용 — 기존 값도 저장 시 정정 필요”를 선택했다. 이관 검증은 “추가 대상 없음 — 현재 검증 범위 유지”로 확정했다.
- 관계: [ADR-0016](ADR-0016-explicit-permissions-and-multiple-groups.md)의 인가와 [ADR-0025](ADR-0025-enterprise-completeness-and-durable-operations.md)의 업무 정합성 위에 아래 정책을 추가한다. 기존 원문 결정은 소급 수정하지 않는다.

## 배경

권한 변경으로 보이지 않는 즐겨찾기도 보존되어 30개 한도를 차지한다. 부서 업무 우선순위와 팝업 크기는 문자열로 저장되며, 기존 비정규 값의 조회와 새 저장의 허용 범위를 구분해야 한다. 메모 수신자가 내용을 읽은 뒤 본문이나 첨부가 바뀌면 지시가 어떤 내용을 기준으로 저장됐는지 현재 요청만으로 확인할 수 없다.

## 결정

1. **즐겨찾기는 기본 보존한다.** 사용할 수 없는 항목의 개수와 본인 확인 후 정리 동작을 제공한다. 서버 인가로 숨겨진 항목의 ID·이름·경로는 공개하지 않는다. 기존 본인(esntlId) 경계와 보존된 전체 행 기준 30개 한도를 유지하며, 조회나 권한 변경만으로 삭제하지 않는다.
2. **정리는 확인한 범위에 결속한다.** 화면은 성공한 전체 메뉴·즐겨찾기 조회와 같은 계정·권한 버전에서 후보를 계산하고 확인 전에 다시 조회한다. 서버는 본인 잠금 후 현재 권한을 다시 읽고 권한 버전·서버 숨김 개수·화면이 지정한 본인 항목을 검증한다. 충돌은 전체 409이며 자동 재삭제하지 않는다. 같은 개수의 숨김 항목 교체를 모두 검출하는 이력 버전은 아니며, 권한·메뉴 writer와의 전역 직렬화를 보장하지 않는다.
3. **관련 필드의 새 저장은 엄격히 검증한다.** 부서 업무 우선순위는 JSON 문자열 `1`, `2`, `3`만 받는다. 팝업 폭·높이는 선행 0·부호·소수·지수·공백 없는 100~4000의 정수 문자열만 받는다. JSON 숫자를 문자열로 자동 보정하지 않는다. null·생략의 기존 서비스 의미와 화면 기본값은 유지한다. 기존 비정규 값은 조회할 수 있으며 관련 등록·수정에서 사용자가 직접 정정하도록 안내한다. 해당 필드를 쓰지 않는 담당자 재지정·삭제에 이 제약을 덧씌우지 않는다.
4. **메모 지시는 읽은 본문·첨부를 기준으로 저장한다.** 상세 응답의 내용 비교 토큰을 필수로 제출하고, 수신자 인가 후 저장 시점의 본문·첨부와 비교한다. 같은 첨부 묶음 안의 추가·삭제도 비교한다. 불일치는 409와 무변경으로 끝낸다. 화면은 작성 중인 지시를 보존하고 최신 내용을 다시 확인한 뒤 별도로 저장하게 하며, 배경 재조회나 재시도로 최신 토큰을 몰래 채택하지 않는다.
5. **토큰의 보장은 내용 동등성이다.** 인증 수단이나 실제 독서의 증명으로 쓰지 않는다. 최초 열람 시각·지시 감사 필드는 비교 내용에 넣지 않는다. 기존 수신자만의 지시 권한, 지시 후 본문 수정 금지, 개인 첨부 열람 인가는 유지한다. 저장 시점의 정합성을 보장하며, 영구 역사 사본이나 지시 후 모든 첨부 변경 금지를 새로 도입하지 않는다.
6. **이관 자격은 현재 범위를 유지한다.** 추가 DBMS·버전·JDBC 드라이버 조합을 검증 대상으로 확대하지 않는다. 기존 검증·미검증 구분과 운영 COMMIT 경계를 유지한다.

## 범위와 호환성

스키마·Entity 타입·표준 메타 사전·기존 데이터 DML은 변경하지 않는다. 입력 제약은 요청에 적용하고 기존 비정규 GET 응답을 거부하지 않는다. 기존 즐겨찾기 목록 API는 유지한다. 외부 호출자가 우선순위·팝업 크기에 JSON 숫자를 보내면 이제 400으로 거절하므로 허용된 문자열로 바꿔야 한다. 메모 지시 요청은 서버와 프론트를 함께 변경하며, 토큰 없는 옛 문자열 본문도 400으로 거절한다. 이를 최신 내용으로 보충하는 호환 경로는 두지 않는다.

메모의 첨부 목록에도 기존 파일 조회 기능 권한(`FILE_READ` 또는 `FILE_READ_ALL`)과 개인 첨부 열람 판정을 함께 적용한다. 첨부 묶음이 있지만 목록 작업권한이 없으면, 참여자의 본문 조회와 최초 열람 처리는 유지하고 첨부 정보·비교 토큰은 제공하지 않으며 지시 가능 힌트를 false로 반환한다. 첨부가 없다는 뜻으로 빈 목록을 대신 반환하지 않는다. 화면은 불가 사유와 작성 중인 초안을 보여 주며, 같은 권한으로 성공할 수 없는 재조회 버튼을 내놓지 않는다. 목록 작업권한이 있어도 개인 첨부 열람 판정 자체가 거부하면 상세 조회 전체를 403으로 거절한다. 이 인가 실패나 없는 첨부 묶음·예상 밖의 조회 오류를 잡아 성공 응답으로 바꾸지 않는다. 지시 저장에서도 해당 조회 권한을 다시 확인하며, 다운로드는 기존 경로의 `FILE_DOWNLOAD` 판정을 유지한다.

## 검증 기준

- 즐겨찾기: 본인·타인 경계, 숨김 정보 비노출, 복구 시 보존, 권한 변경 중 잠금 대기, 명시적 정리·취소·충돌, 조회 오류와 0건 구분, 30개 한도.
- 입력: 원문 JSON 타입, 허용 경계와 비정규 값, null·생략, 기존 응답 호환, 사용자 정정 안내, 거절 시 부작용 없음.
- 메모: 오래된 본문 및 동일 묶음 첨부 변경 거절, 수신자만 지시, 개인 첨부 비노출, 실제 PostgreSQL 파일 writer 경합, 초안 보존·명시적 재확인.

실행 결과와 독립 검토 결과는 구현 PR에 기록한다. 이 결정의 승인 상태를 구현·배포 완료의 증거로 사용하지 않는다.
