# ADR-0033 — 메일 자동 복구용 수신주소의 암호화 보관

- 상태: Accepted
- 결정일: 2026-10-18
- 승인: 사용자가 메일 자동 복구 방식으로 “암호화한 접수 당시 주소 보관”을 선택했다.
- 관련 결정: [ADR-0025 D12](ADR-0025-enterprise-completeness-and-durable-operations.md). 최종 배달·exactly-once 보장이나 운영 DB 변경을 승인하는 결정은 아니다.

## 결정과 이유

메일 접수 이력과 발송 작업을 같은 트랜잭션에 저장한다. 자동 복구에는 접수 당시 수신주소를 기존 애플리케이션 암호화 방식으로 암호화해 작업 payload에 보관한다. 일부 이력은 주소 대신 사용자 ID·표시명만 저장하고 직접 주소도 길이 제한이 있어, 이력으로 주소를 재구성하면 원래와 다른 수신자에게 발송할 수 있기 때문이다.

worker는 암호화한 주소를 사용하며 복구 시점의 사용자 주소를 다시 조회하지 않는다. 제목·본문은 이력을 참조한다. 작업이 성공하거나 최종 실패하면 같은 완료 트랜잭션에서 암호화 주소가 담긴 payload를 지운다. 발송에 착수한 뒤 결과가 불확실한 건은 자동 복구로 다시 발송하지 않는다.

주소를 지운 실패 작업은 일반 작업 재처리 API로 재개하지 않는다. 사용자가 명시하는 수동 재발송은 새 접수이며 기존 수신자 해석 규칙을 따른다. 암호화 키 관리·회전은 기존 정책을 따르고, API·로그·공용 메모리에 주소나 암호문을 노출하지 않는다. 별도 주소 이력 보존이나 과거 행의 추측 보정은 추가하지 않는다.

## 검증과 운영 경계

원자 롤백, 재시작 전 미착수 작업 복구, 중복 실행·늦은 결과의 차단, 암호문 보관·완료 후 제거를 격리 테스트로 확인한다. 실행 결과와 운영 리허설은 별도 증거다. 기존 SMTP 시도 내부의 재시도와 수동 재발송까지 exactly-once로 확대 해석하지 않는다. 상세 상태·복구 절차는 [후속 작업 재처리](../../04-operations/durable-work-recovery.md)를 따른다.
