# ADR-0059 — 운영 앞단 프록시가 로그인 요청을 주소당 한 번 더 제한한다

- 상태: Accepted
- 결정일: 2026-11-14
- 승인: 사용자가 2026-11-14 원점 평가의 결함과 개선점을 "모두 고쳐줘"라고 지시했다. 이 결정은 그 평가의 보안 개선점(로그인 제한이 인스턴스 메모리라 다중 노드에서 한도가 배수가 된다)을 집행하는 권고안이며, 결정 지점은 권고안으로 진행한다는 사용자 위임(2026-08-23)을 따른다.
- 부분 대체: [ADR-0035](ADR-0035-login-rate-limit-default.md) 경계의 "버킷은 인스턴스 메모리라 여러 인스턴스의 합산은 하지 않는다" — edge 가 있는 운영 오버레이에서는 edge 가 합산한다. 백엔드 버킷·기본값·조정 변수는 그대로다.

## 배경

백엔드 요청 제한(`RateLimitFilter`)의 버킷은 인스턴스 메모리다. api 를 여러 대 띄우면 한 주소가 쓸 수 있는 로그인 시도가 대수만큼 늘어난다. 운영 오버레이에서 브라우저의 모든 요청은 edge 하나를 지난다([ADR-0019](ADR-0019-client-ip-trust-boundary.md)). 같은 한도를 edge 에서 한 번 더 걸면 api 대수와 상관없이 주소당 한도가 지켜진다.

## 결정

1. edge(nginx)는 로그인·추가 인증·비밀번호 변경 경로를 접속 주소당 분당 N 회로 제한한다. 경로는 `/api/auth/login`·`/api/auth/mfa/`(인증 BFF), `/api/v1/auth/login`·`/api/v1/auth/mfa/`·`/api/v1/users/me/password`(백엔드 직접 경로)로 시작하는 요청이다 — 백엔드 로그인 버킷과 같은 집합이다. 판정은 nginx 가 디코딩·정규화한 `$uri` 로 하고 대소문자를 가리지 않는다. 그 밖의 경로는 제한하지 않는다(전체 한도는 백엔드가 본다).
2. N 은 백엔드 로그인 한도와 같은 변수 `RATE_LIMIT_LOGIN_REQUESTS_PER_MINUTE`(기본 30)에서 온다. 운영 오버레이가 이 값을 `EDGE_LOGIN_REQUESTS_PER_MINUTE` 로 edge 에 넘긴다 — 운영자는 한 곳만 바꾸고, 올리면 둘이 함께 오른다. 버스트는 N 이고 기다리게 하지 않고 거부한다(백엔드 토큰 버킷과 같은 꼴). 그래서 한꺼번에는 N+1 회까지 지나가고 그 뒤로는 60/N 초마다 한 번 열린다 — 백엔드 버킷은 N 회라, api 가 한 대면 N 째 다음은 백엔드가 막는다.
3. 거부는 429 이고 본문은 그 경로의 실패 응답 계약을 그대로 따른다 — 로그인 BFF 는 `LOGIN_RATE_LIMITED` 와 화면의 요청 제한 문구, 추가 인증 BFF 는 그 BFF 의 429 문구, 백엔드 직접 경로는 백엔드의 `C429` 본문이다. 사용자는 백엔드가 막을 때와 같은 안내를 본다.
4. edge 가 없는 형상(기본 compose·격리 E2E)은 바뀌지 않는다.
5. 계정 하나에 대한 대입은 계정 잠금(행 잠금 아래의 실패 횟수, 인스턴스와 무관)이 맡는다. edge 는 주소 단위만 본다.

## 경계

- edge 를 여러 대 두면 다시 대수만큼 늘어난다. 그 형상은 공유 저장소 버킷이 필요하며 지금 템플릿 밖이다.
- 여러 사용자가 한 NAT 주소를 쓰는 기관은 ADR-0035 와 같이 이 변수를 올린다.
- 앞단 LB·TLS 종단이 있으면 `EDGE_TRUSTED_UPSTREAM` 을 줘야 실제 주소로 센다. 주지 않으면 LB 주소 하나로 모여 모든 로그인이 한 버킷을 쓴다(ADR-0019 와 같은 조건).
- edge 의 거부는 백엔드 거절 카운터(`security.ratelimit.rejected`)에 잡히지 않는다. edge 접근 로그의 429 와 nginx 의 `limiting requests` 경고가 원천이다.

## 검증

- [edge 신뢰 경계 계약](../../../scripts/edge-trust-boundary-contract.mjs)이 경로 판정·한도 변수·거부 본문·운영 오버레이 전달을 보고, 거부 본문과 경로가 화면·백엔드의 원본과 같은지 대조한다. 각 위반이 붉어지는 시험을 같은 변경에 둔다.
- 운영 오버레이와 같은 digest 의 edge 이미지에 이 템플릿과 대역 frontend 를 붙여 확인했다(2026-11-14, 한도 5): 로그인 7 번째부터 429·`LOGIN_RATE_LIMITED` 본문·`Cache-Control: no-store`, 위조 `X-Forwarded-For`·인코딩(`logi%6e`)·대문자 경로도 같은 버킷, 추가 인증·백엔드 직접 경로·비밀번호 변경은 각자의 계약 본문, 그 밖의 경로 20 회·로그아웃·다른 주소는 막히지 않음, 뒤 서비스가 보낸 429 는 본문 그대로 통과.
