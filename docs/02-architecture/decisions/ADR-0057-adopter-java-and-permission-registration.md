# ADR-0057: 생성 프로젝트의 Java·권한 추가분 등록

- 상태: Accepted
- 결정일: 2026-11-14
- 근거: 소스 실측 후속 1~6번의 순차 구현에 대한 사용자 지시
- 대체: DEC-OPS-400 ④의 새 Java·권한 코드 전체 미지원 중 아래의 명시적 추가 범위

생성 시점의 구성·소스 결속은 원본 인증 증거다. 도입자가 기능을 추가할 때 그 해시를 덮어써서 기존 승인을 유지하지 않는다. 별도 `adopter-project.json`에 원본 파일별 해시와 현재 추가분을 기록하고, 원본 잠금·투영·기관 승인 원장은 보존한다.

1. 변경 전 `adopter-project.mjs init`은 기존 거버넌스와 하네스 기준선을 검사한다. 원본 파일별 해시의 집계는 기존 투영의 codeScope와 같아야 하며 원본 스냅숏은 교체하지 않는다. 원본 하네스·권한 묶음 스냅숏은 생성 잠금의 해시로 결속한다.
2. `register --reason`은 기존 온라인 모듈의 새 Java 파일과 새 권한 정의를 지원한다. 기존 Java의 수정·삭제, 제거된 원본 파일·타입·권한의 부활, 기존 권한·화면 진입 조건·인가 정책의 변경은 이 절차로 허용하지 않는다. 새 권한은 `defaultGroups: []`이며 새 operation binding은 GET이며 추가한 Java handler와 새 PERMISSION에만 연결한다. 기존 endpoint/service/manual guard는 보존한다. 새 권한마다 기존 역할 묶음에 자동 포함하지 않는 분류 사유를 명시하고 기존 묶음·제외 행은 보존한다.
3. 권한 생성물과 하네스의 소스 모집단·census를 현재 소스에서 다시 도출한다. 하네스 기준선 갱신은 검증한 권한 정책·프로필 두 registry 키에 한정하며 검증 시에도 원본 기준선과 다시 비교한다. 다른 규칙·예외·임계값이 바뀌면 등록을 거부한다. 새 조회 API의 OpenAPI 연산은 추가한 handler 바인딩과 대응하고 원본 연산·스키마·설정을 보존한다. API 생성 타입은 기존 생성기로 만들며 도입자 governance 단계가 임시 재생성과 대조한다. 원본 API 명세와 생성기는 생성 잠금에 결속한다. 도출·검증이 실패하면 해당 호출이 고친 생성물만 복원하고 사용자의 입력 변경은 남긴다.
4. 관리자 초기 시드 검사의 권한·메뉴 기대값은 원본 구성과 카탈로그에서 계속 도출한다. 검증된 도입자 등록만 현재 범위로 검사하며 변조된 등록은 거부한다. `verify:adopter`는 원본과 같은 UI·진입점·백엔드·스키마·타입·lint·build 검사를 실행한다. 벤더 구성은 기존 벤더 통합·차등 경로를 쓴다. 보고서는 `adopter.json`, `certificationEligible: false`, `environmentApproved: false`다. 원본의 `full.json`을 대체하지 않으며 벤더 인증 기록 명령은 도입자 보고서를 거부한다.
5. 명시적 `npm run verify`·`verify:full`은 원래 생성물 인증 경계를 유지한다. 생성 CI와 pre-push는 검증된 등록 유무에 따라 현재 프로젝트의 full/adopter 검사를 선택한다. 이 선택 자체가 기관 branch protection 적용이나 운영 승인은 아니다.

등록은 품질 규칙의 면제가 아니다. 예를 들어 엔티티를 등록해도 필요한 물리 스키마가 생기지 않으며 스키마 검증은 계속 실패한다. 기존 소스 재설계·새 화면·마이그레이션·기본 그룹 변경은 이 추가 전용 절차의 자동 지원 범위 밖이다. 기관별 요구·인가·데이터·운영 검증은 별도로 수행한다. 사용법은 [도입자 추가분 가이드](../../03-guides/generated-project-additions.md)를 따른다.
