# ADR-0016: 복수 그룹과 명시적 기능 권한으로 인가 통합

- 상태: Accepted
- 결정일: 2026-09-10
- 근거: 최소 테이블 전환 설계에 대한 사용자의 “계획대로 진행하고 완료되면 메인에 병합” 요청
- 범위: 소스·테스트·이행 도구·문서 구현 및 검증 후 main 병합. OCI 전환 실행 결과를 의미하지 않는다.
- 부분 대체: [결정 인덱스](../../../.agent/memory/decisions.md)의 DEC-OPS-023 ②와 DEC-OPS-037·042·046·064의 역할 이름에 따른 표시/인가 조건, DEC-OPS-067의 구 권한·롤 쓰기 화면. 각 결정의 소유권·업무 기능·확인 대화·무변경 거부 취지는 유지하며, 현재 기능 권한과 버전 있는 그룹 관리 계약으로 집행한다. 사용자 분류 그룹 화면은 유지한다.

## 결정

인가의 저장 원천을 `tb_authrt_info`(그룹), `tb_authrt_user_map`(사용자와 그룹의 복수 배정), `tb_authrt_grnt_map`(그룹의 OPERATION/NAVIGATION 배정)으로 통합한다. `tb_authrt_chg_hstry`에 같은 트랜잭션의 변경 이력을 남긴다. 기능 사전은 [코드 카탈로그](../../../config/governance/permission-catalog.json)가 소유하고 HTTP 메서드·경로·핸들러 대응은 [정책 원장](../../../config/governance/authorization-policies.json)이 소유한다. 생성된 Java·TypeScript·서버 리소스와 bootstrap은 원본과 일치해야 한다.

그룹 이름·단일 사용자 role·계층·임의 URL 패턴으로 권한을 추론하지 않는다. 여러 그룹의 기능 권한은 합집합이며, 메뉴 노출 권한은 API 권한을 부여하지 않는다. 비밀글·승인 회원·작성자·수신자·결재자 등 자원 조건은 별도로 집행한다. 소유자 외 자료의 관리가 허용된 경우에만 도메인별 명시 권한을 사용한다. SYSTEM 소속의 개인정보 로그 제외와 특정 재귀속 계정의 삭제 금지는 유지한다.

최초 로그인·JWT·refresh·현재 사용자 응답은 같은 현재 DB 배정을 사용한다. 배정이 없으면 빈 그룹·기능 목록을 반환하며 USER 폴백은 없다. 새 가입과 사용자 등록에서만 USER 그룹을 명시적으로 부여한다. 클라이언트는 HttpOnly 쿠키를 유지하며 토큰을 JavaScript로 공개하지 않는다. WebSocket은 정확한 transport 경로의 쿠키 인증과 Origin 검사, 메시지 송수신의 현재 계정·권한 재검증을 사용한다.

그룹 권한 및 사용자 배정의 전체 교체는 `complete=true`인 전체 스냅샷과 버전을 요구한다. 감사 순번을 버전에 포함하여 변경 후 원상 복구된 상태도 이전 저장 요청과 구별한다. 부서 일괄 배정은 전체 명부의 버전을 확인하고 선택한 사용자에게 ADD/REMOVE를 적용하여 다른 그룹을 보존한다. 마지막 활성 권한관리자를 제거하는 관리 변경은 직렬화하여 거부한다. 로그인 실패에 따른 보안 잠금의 기존 정책은 유지한다.

## 물리 이행

표준 용어와 길이는 V2_98에서 등록·검증한다. 기존 두 매핑 테이블의 PK를 먼저 바꾸지 않고 별도 표준 이름의 새 테이블로 복제한다. V2_99는 기존 정책과 프로그램 URL의 예상 상태를 검증하고 초기 기능을 명시적으로 배정한다. 변경 이력에는 이전 배정·메뉴·롤 정책 및 URL을 보존한다.

운영 전환은 구 writer 중지와 백업 후 Expand/seed, 비교, 수동 Contract, 새 애플리케이션 시작 순서의 점검 창을 사용한다. 정상 앱 기동은 구 6개 테이블이 남아 있거나 전환 완료 증거가 없으면 중단한다. 앱 시작이 운영 테이블을 자동 삭제하지 않는다. 격리 E2E와 새 프로젝트의 빈 baseline은 별도의 명시적 bootstrap 경로로 검증한다.

Contract는 `tb_user_authrt_map`, `tb_authrt_role_map`, `tb_role_info`, `tb_role_prgrm_map`, `tb_menu_crt_dtl`, `tb_role_hierarchy`를 제거한다. 사용자 분류 그룹, 메뉴, 프로그램은 각자의 기능 때문에 유지한다. 최종 인가 핵심 3개와 감사 1개, 비인가 3개를 합하면 종전 조사 대상 10개가 7개가 된다.

## 영향과 검증

구 롤 편집과 버전 없는 배정 쓰기는 종료한다. 프론트의 그룹·기능 및 사용자 복수 배정 화면으로 이전하고 외부 호출자는 새 API로 전환해야 한다. 남겨 둔 단일 역할 필드·구 조회는 설명 호환 용도이며 인가와 전체 배정 저장에 사용하지 않는다.

퇴역 엔티티의 CRUD 테스트는 종료 API의 무변경 거부 테스트와 새 실제 PostgreSQL 배정·감사·동시성 시험으로 대체한다. 기존 허용·거부, 역할명만 가진 주체의 거부, 읽기 전용 주체의 쓰기 거부, SYSTEM 혼합 그룹 제외, 소유권과 개인정보, 중간 DB 실패 롤백을 검증한다. 테스트·게이트의 제외나 임계값 완화로 전환하지 않는다.

실제 복수 배정을 개방한 후에는 구 단일 배정 버전으로 무손실 복귀할 수 없다. 새 모델을 이해하는 버전의 롤백 또는 forward fix를 사용한다. 전체 백업 복구는 그 이후 변경의 손실을 포함한다. 적용 절차와 확인 항목은 [전환 런북](../../04-operations/authorization-cutover-runbook.md), 모델·API·조사 범위는 [상세 설계](../authorization-simplification-design.md)가 정본이다. main 병합은 release 또는 OCI 적용과 별개다.
