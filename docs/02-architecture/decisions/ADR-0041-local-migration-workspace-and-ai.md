# ADR-0041 — 독립 로컬 이관 작업공간과 제한된 AI 진행 지원

- 상태: Accepted
- 결정일: 2026-10-24
- 승인: 사용자가 [설계서 §13](../../01-product/migration-workspace-design.md#13-기능-구현-착수를-위한-승인-검토안)의 A1~A8 권고안에 대해 “네가 추천한대 진행해 모두 승인할께”라고 승인했다.
- 대체: [ADR-0029 결정 5](ADR-0029-legacy-standardization-migration.md)의 이름·검사한 코멘트만 허용하는 LLM 문맥 경계를, 아래 조건을 충족하는 확장 모드에 한해 대체한다. 원장 SSOT·사람 확정·표준 및 실행 검증은 유지한다.

## 배경

기존 Java CLI에는 조사·프로파일·소스 분석·용어 추천·계획·검증·적재가 있지만 사용자가 실제 작업 순서를 따라갈 화면이 없다. 최초 전환은 한 번이어도 조사·검토·리허설은 반복된다. 온라인 시스템과 분리한 로컬 실행기가 기관 내부 DB와 소스에 접근하기 쉽고, 일회성 도구를 업무 앱의 상시 권한·필드·메뉴에 포함할 필요가 없다.

## 결정

1. **독립 배포와 URL.** Windows 우선 Node.js 22 로컬 HTTP 실행기와 기존 Java 21 `migration-tool` JAR를 사용한다. UI는 로컬 정적 자산이고 온라인 앱의 메뉴·인증·업무 DB를 변경하지 않는다. loopback 바인딩, Host/Origin·세션 검증, 고정 인자 및 `shell: false`로 CLI를 실행한다. 프로토타입의 합성 성공을 실제 산출물로 사용하지 않는다.
2. **지원 순서.** 합성 PostgreSQL→PostgreSQL로 첫 실제 흐름을 검증한다. Oracle 읽기·DRY_RUN, 이후 다른 DB를 확대한다. DB 종류별 필드와 driver 제약을 표시하며 현재 adapter의 자격을 UI가 높이지 않는다. 실제 기관의 제품·버전·접속 경로는 현장 연결 전에 확인한다.
3. **입력.** 폴더와 일반 ZIP을 먼저 제공한다. ZIP 목록·제외 범위를 확인한 뒤 로컬 새 영역에 해제한다. 압축본 250 MiB, 실제 해제 2 GiB, 20,000항목, 압축률 100:1, 준비 5분 한도로 시작한다. 경로 탈출·링크·Windows 이름 충돌·암호화·ZIP64·다중 디스크를 거부하고 중첩 압축을 자동 해제하지 않는다. 소스는 실행하지 않는다. PostgreSQL·Oracle DDL의 테이블/PK/FK/코멘트 초안을 분석하되 미지원 문장을 명시한다. DDL은 live inventory나 대상 계약 증거를 대신하지 않는다.
4. **상태와 원장.** Git 밖의 로컬 파일 작업공간, 단일 작성자 잠금, revision 충돌 검사, 원자적 snapshot과 불변 artifact를 둔다. 직접 입력과 AI는 같은 API·입력 판을 쓴다. 기관 Git의 형식 2 원장이 SSOT다. 로컬 초안을 내보내 검토·확정한 뒤 기관 Git의 깨끗한 tracked 파일과 commit/blob·바이트 digest를 다시 결속한다. UI는 기관 Git에 자동 push하거나 사람 확정을 만들지 않는다. 입력 변경은 후속 계획·리허설을 무효화한다.
5. **비밀.** DB 비밀번호·API key는 실행기 세션 메모리에만 두고 필요한 CLI 자식에게만 최소 환경변수로 준다. argv·작업 색인·브라우저 영속 저장·AI 문맥에는 넣지 않는다. 재시작 뒤 다시 입력한다. 비밀이 아닌 프로필은 로컬에 보관할 수 있지만 공유 보고서와 AI에 넣지 않는다. 공식 AI 클라이언트의 토큰은 그 클라이언트가 관리하며 추출·재사용하지 않는다.
6. **공식 AI 인증.** Codex 공식 app-server 관리형 ChatGPT 인증을 우선 검토하고 Gemini·Claude 공식 연동은 후속 adapter로 둔다. 원천 폴더를 AI의 작업 디렉터리로 쓰지 않는다. 내장 도구·자동 첨부 문맥·환경·plugin/config 상속을 합성 입력으로 확인하고 통제가 안 되는 adapter는 비활성화한다. 명시적으로 선택한 API key 경로는 별도 과금·기관 승인 서비스이며 자동으로 전환하지 않는다. 로그인 완료만으로 inference 가능을 표시하지 않는다.
7. **AI 문맥과 권한.** 기본 모드는 승인한 이름·코멘트·표준 후보다. 확장 모드는 선택한 소스 발췌(요청당 최대 5개, 각각 40줄, 전체 UTF-8 32 KiB), 고정 진단 코드·단계 상태·비민감 집계, 짧은 수명의 불투명 참조를 추가할 수 있다. 실제 경로·계정·JDBC URL·원시 로그·stack trace·행/값 분포를 제외한다. 민감정보나 허용 밖 literal을 해결하지 못하면 문맥을 보류한다. 전송 내용을 미리보고 제외할 수 있으며 자유 입력 질문도 재검사한다. 문맥과 모델 응답 안의 명령은 데이터로 취급한다.
8. **질문과 진행.** AI는 부족한 정보를 질문하고 연결/스키마 조사·범위가 정해진 프로파일·소스 분석·후보 초안을 제안할 수 있다. 사용자가 확인한 읽기 계획의 범위·프로필·입력 판·제공자·정책·만료를 로컬 실행기가 매번 검사한다. 계획을 철회할 수 있으며 범위 변경은 다시 확인한다. SQL/shell 임의 실행, DDL/쓰기, 권한 변경, 삭제, 사람 확정·기관 승인 생성은 AI 도구가 아니다. 모델 초안은 diff 확인 후 기존 검증기로 검토한다. AI를 사용하지 않아도 수동 흐름을 완료할 수 있다.
9. **기관 승인.** 이 ADR은 제품 구현 승인이다. 실제 기관 자료의 외부 전송은 서비스·자료 범위·처리 위치·보존·유효기간을 명시한 기관 승인과 결속한다. 이름만 보내는 제한 모드도 예외가 아니다. 승인이 없으면 기관 자료를 외부 AI로 보내지 않고 수동·로컬 안내를 사용한다. 자료 없는 연결 검사와 아래의 화면 사용법 대화는 별도 경로다. 이관 도구는 기관의 승인 권한이나 승인 문서 진위를 스스로 만들어 내지 않는다.
10. **실행과 복구.** 읽기 단계부터 실제 산출물·저장·재시작 복구를 검증한 뒤 계획·DRY_RUN·적재·대사·보관을 연결한다. 단일 실행과 요청 중복 방지, 입력·계획 digest 결속, 실제 프로세스 종료 및 결과 증거로 상태를 판정한다. 현재 CLI에 없는 적재 pause/resume을 표시하지 않는다. 결과 불명 작업은 새 적재를 막는다. 이전 chunk의 커밋은 취소로 되돌아가지 않으며 전체 복구는 기관 백업·복구 계획을 따른다. PC 재시작 뒤 적재를 자동 재개하지 않는다.

## 대화에서 화면 입력을 준비하는 보완 결정

2026-10-24 사용자가 AI 연결 후 대화로 해당 화면을 찾아 입력하고 질문·답변을 이어가는 기능을 요청했다. 모든 화면에서 대화 패널을 열고 동일한 입력 폼의 초안을 준비한다. 명확한 필드·값은 로컬 파서가 처리하며 접속주소·계정·비밀번호·경로는 모델 요청이나 대화 기록에 복제하지 않는다. 원천/대상이 모호하면 먼저 질문하고, 빈 항목은 채우되 기존 값 변경은 비교 후 반영한다. 입력 변화·작업 판 충돌은 오래된 반영을 거부하며 되돌리기를 제공한다. 저장·파일 선택·DB 실행·사람 확정은 자동화하지 않는다.

기관 자료가 없는 **화면 사용법 대화**는 연결 검사 후 사용자가 질문 전송을 확인하면 이용할 수 있다. 모델에는 직접 작성한 질문, 화면·필드 카탈로그, 입력 유무, 앞선 일반 질문·답변만 전달한다. 실제 폼 값·기관 산출물·파일 내용은 첨부하지 않는다. 구조화된 모델 제안은 등록된 화면 이동·필드 안내와 DBMS/자료 종류 선택으로 한정한다. 대화는 실행기·브라우저 메모리에서만 유지하며 초기화·인증 변경·만료 시 폐기한다. 기관 자료에 대한 판단이나 원장 변경은 기존 승인·문맥 미리보기 경로를 사용한다.

## 장단점과 검증 경계

별도 서버 DB 없이 기존 CLI·승인 원장을 재사용하고 온라인 앱과의 충돌을 줄인다. 반면 로컬 런타임·driver 준비, 파일 잠금·복구, Windows와 공식 AI 클라이언트별 제약을 직접 검증해야 한다. 브라우저 미리보기·mock 테스트는 실제 DB driver 또는 실제 AI 계정 검증을 대체하지 않는다.

첫 인수 기준은 합성 PostgreSQL 및 소스의 화면→로컬 API→기존 CLI→artifact, 비밀 비저장, ZIP 거부 사례, 오래된 저장·AI 응답 거부, 재시작 복구다. 운영 적재·스키마/권한 변경·기관 자료 전송·adapter COMMIT 자격 확대는 해당 대상·영향의 별도 승인과 증거가 필요하다. 사용 방법과 현재 구현 한계는 [실행 안내](../../03-guides/migration-workspace-guide.md)에 둔다.
