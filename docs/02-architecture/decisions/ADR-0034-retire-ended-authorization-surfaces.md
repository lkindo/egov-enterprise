# ADR-0034 — 종료한 구 인가 API 경로를 걷고 집행 지점 없는 권한을 퇴역한다

- 상태: Accepted
- 결정일: 2026-10-18
- 승인: 사용자가 트랙 D 선택지에서 구 API 표면 "둘 다 정리(권고)"와 "INST_CODE 권한만 퇴역(권고)"을 골랐다.
- 부분 대체: [ADR-0016](ADR-0016-explicit-permissions-and-multiple-groups.md) '영향과 검증'의 "종료 API의 무변경 거부 테스트" 부분(410 으로 남긴 구 롤·권한 쓰기 경로). 그룹·복수 배정·명시 기능 권한 모델과 감사·동시성 시험은 그대로다.

## 결정과 이유

ADR-0016 전환 뒤 410만 돌려주던 구 롤·롤 권한·권한 쓰기 API 12개 operation 을 경로째 걷는다. 410 은 호출자를 새 API 로 옮기라는 신호였고, 저장소의 프런트·E2E 에는 호출자가 없다. 남겨 두면 API 계약·정책 원장·입력 계약 원장이 실제 동작 없는 표면을 계속 센다. 화면이 쓰는 권한 조회(목록·단건·메뉴)는 남긴다.

결재 API 로 대체된 비공식결재(ISM) API 6개 operation 도 걷는다. 화면 별칭 `/admin/system/ism` 은 지금처럼 `/approvals` 로 보낸다. 이 API 에만 묶여 있던 INFORMAL_* 기능 권한 10개와, 쓰기 경로가 없어 집행 지점이 없던 기관코드 쓰기 권한(INST_CODE_CREATE·UPDATE·DELETE)을 원장에서 뺀다. 원장에 없는 권한 배정이 남으면 권한 스냅샷이 fail-closed 로 실패해 그 그룹 구성원의 인증이 막히므로, 같은 릴리스의 데이터 마이그레이션(V2_130)이 기존 배정을 지우고 같은 트랜잭션에 변경 이력을 남긴다.

## 검증과 운영 경계

걷은 경로는 컨트롤러·정책 원장·API 계약에서 함께 사라진다. 원장에 없는 연산은 디스패치 전에 거부되므로 관리자도 403, 미인증 요청은 401 을 받고, RBAC 시험이 이를 고정한다. 권한 상승 시험은 남은 관리자 전용 쓰기 경로로 옮긴다. 권한·결재 DTO 는 남은 조회·결재 API 가 계속 쓰므로 입력 계약 원장과 그 하한은 그대로다. 공유 OCI 적용은 병합 뒤 별도 단계로 하고, 적용 직전에 지울 배정 수를 다시 센다. 기관코드 원장 쓰기 경로를 설계하게 되면 쓰기 권한도 그때 새로 정의한다([GAP-CODE-001](../../../.agent/memory/known-gaps.md)). 적용 절차는 [전환 런북](../../04-operations/authorization-cutover-runbook.md)을 따른다.
