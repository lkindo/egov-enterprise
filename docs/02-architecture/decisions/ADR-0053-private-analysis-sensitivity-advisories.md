# ADR-0053 — 비공개 원문 분석의 민감정보 감지 안내

- 상태: Accepted
- 결정일: 2026-11-09
- 승인: 사용자는 “민감정보 패턴을 감지했다고 중단시키면 안되지, 어찌됐든 원문을 분석하는건데 분석은 완료하고 민감정보가 있으면 별도로 안내를 해줘야지”라고 지시했다.
- 대체 범위: [ADR-0051](ADR-0051-ai-first-requirements-workflow.md)의 비식별 입력·민감정보 차단과 [ADR-0052](ADR-0052-ai-document-to-development-plan.md) 결정 6의 비식별 확인 중 비공개 요구사항 작업공간의 분석 경계. 서비스 전송 동의·저장·최종 확인·기관 인수 경계는 유지한다.

## 결정

1. 인증된 동일 PC의 Git 외부 요구사항 작업공간에서는 민감정보 패턴만으로 등록·판독·요구사항·에픽·개발 작업계획 생성을 중단하지 않는다. 원문과 필요한 근거를 임의 마스킹하지 않으며 원본과 검증된 분석 결과를 비공개 작업공간에 보존한다. 업무 의미에 필요 없는 민감값을 요약·계획에 반복하도록 요구하지 않는다.
2. 감지 종류·분석 단계·항목 수·안전한 필드 위치를 별도 안내한다. 안내에는 실제 값·원문 인용·사용자가 만든 임의 객체 키를 넣지 않는다. 같은 내용이 단계별로 반복 감지될 수 있으며 항목 수는 고유 정보나 사람 수가 아니다. 패턴 감지의 유무는 완전한 개인정보 검사나 이미지 검사 결과가 아니다.
3. 원문에 민감정보가 포함될 수 있는 비공개 분석 방식의 확인과 모델 서비스 전송 동의를 구분한다. 기존 비식별 확인을 보낸 구형 클라이언트는 호환하되 새 UI는 제거했다고 거짓 확인하지 않는다. 동의한 자료 범위·분류·문맥이 바뀌면 종전 동의로 새 자료를 보내지 않는다.
4. 스키마·크기·형식·원문 인용·누락·취소·잠금·revision 검증은 유지한다. 실제 판독 불가나 정책 결정은 기존 절차로 처리한다. 민감정보 패턴 자체는 판독 불가나 blocking 의사결정 이슈가 아니다. 실제 요구사항의 개인정보 처리 정책에 관한 미결정 사항은 별개다.
5. 기본 공유 계약과 저장소 CLI 산출물 검증은 민감정보를 계속 오류로 처리한다. 비공개 UI의 판독 기록·검토 CSV·작업 패키지 다운로드도 원문을 포함할 수 있으므로 공유 전에 검토한다. 비공개 동작은 명시적인 검증 옵션을 쓰며 전역 패턴·공개 검증기를 약화하지 않는다.
6. 새 프롬프트는 `2026-11-09.1`로 기록한다. 민감정보만 더 엄격했던 직전 `2026-11-07.1`의 완료 판독은 원본 해시·모델·effort·분류·유형·현재 근거 지문과 보관 기록이 일치할 때만 재사용한다. 과거 기록이나 프롬프트를 새 버전으로 바꾸지 않는다. 전체 분석 체크포인트의 버전·상위 해시 검증은 유지한다.

## 검증 경계

합성 자료로 원문 등록부터 여섯 AI 단계·최종 확인·작업 패키지까지 완료되는지, 경고에 실제 값이 없는지, 기본 공개 검증이 계속 거부하는지 확인한다. 인증 없는 접근·동의 누락·잘못된 인용·손상된 구조를 허용하는 변경이 아니다. 고객 자료나 모델 원시 오류를 코드·리뷰·CI 산출물에 넣지 않는다.
