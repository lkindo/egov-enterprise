# ADR-0046 — 빈 표 숫자 타입 전환과 로그 밀리초 표준

- 상태: Accepted
- 결정일: 2026-10-30
- 승인: 사용자가 숫자 3개 컬럼은 “A: 빈 표·정비창 한정 예외 승인 후 구현”, 로그 이름은 “처리소요밀리초 / PRCS_REQ_MSEC / 밀리초N19”를 선택했다.
- 관계: [ADR-0014](ADR-0014-deferred-standard-design-alignment.md)의 보류 대상 중 아래 다섯 컬럼의 설계를 구체화한다. [ADR-0045](ADR-0045-bookmark-cleanup-input-policy-and-memo-read-consistency.md)의 입력·API 정책은 보존한다. 두 문서의 과거 구현 범위를 소급 변경하지 않는다.

## 결정

1. 공유 개발 DB의 `tb_dept_task_info`와 `tb_popup_info`가 적용 직전 잠금 안에서도 모두 0행일 때에 한해 정비창에서 기존 세 컬럼을 직접 바꾼다. `prrty_rnk`는 `NUMERIC(10,0)`, `popup_wdth_sz`·`popup_vrtc_sz`는 `NUMERIC(7,0)`이다. 기존 이름·표준 메타·NULL·기본값 없음·PK/FK·감사·버전·인가를 보존하며 데이터 보정과 새 DB CHECK는 넣지 않는다.
2. 이 세 컬럼의 정비창에 한정하여 DB 헌법 제7조의 Expand–Sync–Redirect–Contract 경로를 예외로 한다. 기존/신규 앱을 혼용하지 않고 writer 중지 → 사전 점검 → 원자적 Flyway → 새 앱 검증 → 쓰기 재개 순서로 진행한다. 별칭 컬럼·표준 용어를 만들지 않는다. 이 결정은 다른 환경이나 대상에 대한 포괄적 예외가 아니다.
3. 행이 있는 환경에서는 전환하지 않는다. 같은 Flyway 체인을 사용하는 환경은 배포 전에 두 표의 행 수·스키마·메타·의존성을 읽기 전용으로 점검한다. 조건을 충족하지 않으면 배포를 보류한다. 점검을 생략하면 마이그레이션과 이후 체인이 실패하고 앱 기동도 실패할 수 있다. 행 삭제·조건 우회·Flyway repair로 통과시키지 않고 기존 앱/스키마를 유지하며 별도의 데이터 보존 이행안을 결정한다. 새 빈 격리 시험 DB는 이 전환의 검증 대상으로 사용한다.
4. 외부 API는 문자열과 NULL을 유지한다. 우선순위 `1`·`2`·`3`, 팝업 크기 100~4000의 정규 정수 문자열, JSON 숫자 거부를 유지한다. DB 저장/조회는 정확한 십진 정수 변환을 사용하며 Java int 범위로 좁히지 않는다. 빈 표 전제이므로 기존 문자열의 선행 0 등 표현을 변환하는 작업은 없다. NUMERIC에 들어간 범위 밖 정수는 조회할 수 있으나 관련 저장은 기존 제품 정책에 따라 정정해야 한다.
5. 로그 두 표의 새 물리 표준은 **처리소요밀리초 / `PRCS_REQ_MSEC` / `밀리초N19`**로 확정한다. 단어 밀리초/`MSEC`, 수량 도메인 BIGINT/19를 등록하는 설계를 채택한다. 기존 `PRCS_TM` 표준·밀리초 값·BIGINT·NULL·API 표현은 보존한다. Expand–Sync–Redirect–Contract로 전환하고 구 컬럼 삭제는 별도 승인과 관측 규칙을 따른다.
6. 구현·격리 시험·복구 패킷 준비의 승인과 공유 DB 실행 승인을 구분한다. 실제 메타 등록·DDL·백필은 정확한 SQL·대상·실측·검증·복구 조건을 갖춘 패킷에 대한 최종 승인 뒤에만 수행한다. `ans_lv`의 의미·타입은 보류하며 이 결정으로 여섯 컬럼 정합 완료를 선언하지 않는다.

## 검증과 복구

숫자는 빈 표 정상 이행, 어느 한 표의 데이터·잠금·원형/메타 충돌 거부, 두 번째 DDL 실패 시 전체 롤백, Flyway 이력, 실제 JPA 저장/조회 및 API 문자열을 검증한다. 커밋 뒤 쓰기 재개 전 복구는 두 표가 여전히 빈 경우에만 별도 승인된 후속 versioned Flyway로 역변경하고 구 앱으로 복귀한다. 쓰기 재개 뒤에는 이 빈 표 복구를 쓰지 않으며 별도 roll-forward 또는 승인된 백업 복원이 필요하다. 과거 Flyway·적용 이력을 수정/삭제하지 않는다.

로그는 메타 충돌·동시 등록, 두 방향 writer, NULL·64비트 값 보존, 배치/대사, drift 거부와 Redirect 전 철회를 격리 PostgreSQL에서 검증한다. 시험 통과가 공유 DB 적용·대용량 성능·외부 소비자 종료의 증거는 아니다.

실행 절차와 적용 전 확인 항목은 [숫자 적용 패킷](../../04-operations/numeric-column-transition-proposal.md), [로그 적용 검토안](../../04-operations/log-duration-transition-proposal.md)에 둔다. 실행 결과는 구현 PR과 실제 적용 시의 공유 OCI 적용 로그에 남긴다.
