# ADR-0019: 운영 앞단 프록시로 클라이언트 IP 신뢰 경계를 세운다

- 상태: Accepted
- 결정일: 2026-09-14
- 근거: 2026-09-14 프로젝트 평가 뒤 개선 계획 단계 1(사용자 지시 "개선계획 계속 진행"), [GAP-SEC-004](../../../.agent/memory/known-gaps.md)

## 배경

사용자 IP는 로그인 IP 제한 정책, 로그인 IP 기록, 감사 IP, 요청 제한(RateLimitFilter)의 입력이다. 백엔드는 신뢰 대역(`TRUSTED_PROXIES`, 운영 `172.28.0.0/24`)에서 온 요청에 한해 `X-Forwarded-For`를 읽는다.

운영 compose는 Next(3000)와 API(8080)를 앞단 프록시 없이 공개했다. 이 형상에서 두 경로가 서로 다르게 틀렸다.

- 로그인·재발급·로그아웃 BFF와 서버 컴포넌트·서버 액션은 백엔드를 부를 때 사용자 IP를 싣지 않았다. 백엔드는 Next 컨테이너 주소를 사용자 IP로 판정했고, 로그인 IP 제한·로그인 기록·요청 제한이 전사 한 주소로 모였다.
- 브라우저의 API 요청은 Next rewrite를 거친다. Next는 `X-Forwarded-For`가 없을 때만 소켓 주소로 채우므로 클라이언트가 보낸 값이 그대로 남아 백엔드에 전달됐다.

같은 헤더를 BFF에서 그대로 넘기는 것만으로는 해결되지 않는다. Next가 직접 공개된 한 그 값은 위조할 수 있고, 백엔드가 Next를 신뢰하므로 IP 제한을 통과하게 된다.

## 결정

1. 운영 오버레이(`docker-compose.prod.yml`)에 비루트 nginx `edge`를 둔다. 브라우저의 진입점은 edge 하나이고, edge는 뒤로 넘기는 `X-Forwarded-For`를 **자신이 본 접속 주소로 덮어쓴다**. 원래 Host는 그대로 넘긴다(Next의 Origin 검사가 Host를 기준으로 판정한다). 이미지는 digest로 고정한다.
2. 운영 오버레이는 Next의 호스트 공개 포트를 비운다(`ports: !reset []`). 개발·E2E가 쓰는 base compose는 바꾸지 않는다.
3. API 8080의 직접 공개는 유지한다. 운영 형상에서 브라우저 직접 도달이 확인된 경로이며, 직접 온 요청은 신뢰 대역 밖이라 헤더를 무시하고 접속 주소를 쓴다.
4. edge 앞에 LB·TLS 종단이 따로 있으면 `EDGE_TRUSTED_UPSTREAM`에 그 대역을 준다. edge는 그 대역에서 온 요청만 상위가 붙인 `X-Forwarded-For`를 따라가 실제 주소를 복원한다. 기본값은 루프백이라 아무 상위도 신뢰하지 않는다.
5. Next는 `TRUSTED_EDGE_PROXY=true`일 때만 사용자 IP를 백엔드로 넘긴다. 이 값은 운영 오버레이에서만 켠다. 전달 대상은 인증 BFF 3개와 서버 측 공용 API 인터셉터이며, 모두 공용 헬퍼를 거친다. 헬퍼는 단일 주소가 아닌 값(쉼표 목록 등)을 넘기지 않는다.
6. 요청 제한 한도는 JVM 시스템 프로퍼티가 아니라 설정 속성·환경변수(`RATE_LIMIT_REQUESTS_PER_MINUTE`, `RATE_LIMIT_LOGIN_REQUESTS_PER_MINUTE`)로 받고 로그인 전용 버킷을 분리한다. 기본값은 종전 동작을 그대로 옮긴다(전체 10,000, 로그인 2,000). 한도를 낮추는 것은 이 경계가 배포돼 IP가 사용자별로 들어오는 것을 확인하고 거절 로그를 관측한 뒤다.
7. `scripts/edge-trust-boundary-contract.test.mjs`가 위 조건을 함께 검사한다. 덮어쓰기 대신 이어 붙이기, Host 누락, digest 해제, 템플릿 치환 범위 해제, Next 재공개, 운영 스위치 누락, 개발 스택에서의 스위치 켜기, 인터셉터·BFF의 헬퍼 누락, 헬퍼 없는 새 백엔드 직접 호출이 각각 실패한다.

## 영향과 한계

- 운영 접속 주소가 Next 3000에서 edge(`EDGE_HTTP_PORT`, 기본 80)로 바뀐다. 기존 배포의 접속 경로와 방화벽 규칙을 함께 바꿔야 한다.
- Docker 호스트의 userland-proxy가 켜져 있으면 외부 접속의 원 주소가 브리지 게이트웨이로 바뀐다. 그 주소는 신뢰 대역 안이라 사용자별 판정이 다시 한 주소로 모인다(위조는 되지 않는다). 운영 호스트는 `userland-proxy: false`로 둔다.
- TLS 종단은 이 결정에 포함하지 않는다. 운영 쿠키가 Secure이므로 브라우저 앞에는 HTTPS가 있어야 한다.
- 실측 범위: 격리 Docker 네트워크에서 edge가 위조한 `X-Forwarded-For`를 접속 주소로 덮어쓰고 원래 Host를 유지하는 것, 신뢰 상위에서 온 헤더만 복원하는 것을 확인했다. 운영 호스트의 전체 스택(edge→Next→API)에서 로그인 기록 IP와 IP 제한 허용·거부를 실측하는 것은 배포 시점의 확인 항목이다.
