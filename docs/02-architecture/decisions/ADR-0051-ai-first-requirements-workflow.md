# ADR-0051 — 산출물 기반 AI 요구사항·개발 계획 생성

- 상태: Accepted
- 결정일: 2026-11-06
- 승인: 사용자는 사람이 요구사항·회의록·관련 산출물을 올리고 AI가 요구사항을 생성하며 쟁점 답변 뒤 에픽 등을 이어서 만드는 흐름을 요청했다. 실행 방식은 “현재 PC의 에이전트 CLI 연결”, 입력 형식은 “HWP/HWPX, PDF, Word, Excel, 텍스트·Markdown ,html, 이미지 등”으로 확인했다.
- 대체 범위: [ADR-0050](ADR-0050-local-requirements-workspace.md) 결정 4의 입력·OCR·외부 AI 제외 경계와 결정 5의 수작업 상세화. 나머지 저장·세션·검증·기관 승인 경계는 유지한다.
- 후속 결정: 결정 1·6의 요구사항·에픽 생성과 확정 순서는 기본 화면에서 [ADR-0055](ADR-0055-requirements-item-store.md)가 대체한다. 이 흐름은 보완 경로로 남는다.

## 결정

1. 기본 흐름은 **파일 등록 → 로컬 본문 추출·OCR → AI 요구사항 초안·원문 근거 → 사람의 쟁점 답변 → 재분석 → 요구사항 검토·기준선 → AI 에픽·스토리·인수조건 → 사람의 검토·개발 패키지**다. 기존 직접 편집 화면은 보완 경로다. 생성과 기관 인수 판정, 코드 실행은 별개다.
2. HWP·Office·PDF·이미지·HTML 판독은 버전 고정한 로컬 파서를 별도 자식 프로세스에서 수행한다. TXT·Markdown은 크기가 제한된 본문을 엄격하게 디코딩한다. 파일·본문·시간·출력·V8 힙 한도를 두고 원본 해시와 조항 위치를 보관한다. 이미지·스캔 PDF는 로컬 OCR을 사용한다. 첫 실행에는 해시 검증되는 공개 OCR 모델 다운로드가 필요할 수 있다. 문서 매크로·HTML 스크립트를 실행하지 않는다. 이 프로세스 분리는 OS 보안 샌드박스나 네이티브 메모리 전체의 한도라는 뜻이 아니다.
3. 현재 실행 어댑터의 구현 기본값은 이 PC에 설치·로그인한 Claude CLI와 명시 모델 `claude-opus-5-5`, `xhigh`다. 사용자가 확정한 것은 설치 CLI 연결 방식이며, 이 기본값은 다른 공급자를 금지하는 기관 정책이나 사용자가 별도 확정한 런타임 모델 정책이 아니다. 다른 CLI 어댑터는 아직 없다. CLI 연결은 오프라인 추론이 아니다. 실행 전 자료 목록·자료 범위·모델 서비스 전송을 화면에서 확인하고 동의한다. 본문만 또는 본문과 이미지·PDF를 선택하며 답변 후 재분석과 자동 상세화에도 같은 선택을 적용한다. 기존 CLI의 인증·요금·관리형 정책을 따른다. 실제 기관 자료의 반출 허용 여부는 입력자가 확인한다.
4. CLI 명령·모델·인자는 서버가 정한다. 브라우저가 실행 파일·명령을 지정할 수 없다. 프롬프트는 stdin으로 전달하며 도구·MCP·슬래시 명령·세션 저장을 끈다. 검증한 Claude Code 2.1.287의 도움말에서 `--restricted`는 사용자·프로젝트·로컬 설정을 무시하고, `--safe-mode`는 CLAUDE.md·훅·플러그인 등 사용자 구성을 비활성화한다고 명시한다. 관리형 정책은 계속 적용된다. 실제 시험용 훅과 비공개 카나리아 지시 파일을 둔 실행에서도 훅이 실행되지 않고 지시가 문맥에 들어오지 않았다. 버전 변경 후에는 이 동작을 재확인한다. 노력 수준 기록은 CLI에 요청한 값이며 공급자 내부 추론량을 측정한 값이 아니다. 전용 임시 디렉터리와 제한된 환경 변수, 시간·출력 한도, 해당 작업의 프로세스 취소를 사용한다. 실행기 자체는 원시 프롬프트·CLI stderr·미검증 결과를 로그에 남기지 않는다. 공급자의 보존 정책이나 CLI 내부 로그 전체를 통제한다고 주장하지 않는다.
5. 모델 출력은 비신뢰 JSON이다. 추가 필드·승인 조작·알 수 없는 식별자·가짜/지나치게 짧은 인용·조항 누락·순환 의존·기존 대상 위조를 검증한다. 인용은 정확한 부분 문자열이며 최소 12개의 문자·숫자(더 짧은 조항은 그 조항의 전체 문자·숫자 수)를 요구한다. 이것이 문맥상 함의를 증명하지는 않으므로 원문 검토도 필요하다. 조항 역방향 연결은 검증된 인용에서 도출한다. 해결 방향·측정 기준 누락과 기존 열린 질문은 결정 질문으로 차단한다. 기존 범위 생략은 이전 결정을 유지하며 범위 변경과 작업·인수조건·추적 제외는 변경 전후·사유를 표시하고 항목별 사람 확인을 요구한다. 제외 사유 없는 작업 ID 누락을 거부하며 기관 판정이 있는 인수조건의 제외도 별도로 확인한다. 형식·민감정보 검사를 통과한 구조 오류만 원본과 위반 위치로 한 번 보정하며 보정 결과도 같은 검증을 통과해야 한다. 미검증 초안은 보관하지 않는다. AI의 추론만으로 사람의 정책·범위·기준선·인수를 확정하지 않는다.
6. 작업은 비동기이며 입력 백로그·문맥·결정을 해시에 묶고 불변 입력/결과 기록을 보관한다. 변경 중 완료된 결과는 재분석 대상으로 표시해 적용하지 않는다. 재시작한 실행은 중단으로 표시하고 자동 재전송하지 않는다. 요구사항을 바꾸는 결정 답변은 원천 자료로 추가해 재분석·재확정한다. 에픽 단계에서 사람이 작업 계획만 보완한다고 명시한 답변은 결정 이력에 남기고 기준선을 유지해 상세화를 재실행한다. 요구사항 확인 후 에픽 생성을 기본으로 자동 시작하되 요구사항만 먼저 확정할 수도 있고 생성 계획의 반영은 별도 검토한다. 재생성에는 기존 계획의 ID·문구를 전달한다. 변경 전 작업은 입력 기록에서 확인할 수 있고 의미가 같은 인수 근거는 유지한다.
7. 원본과 추출 자료는 기존 Git 밖 작업공간에만 보관한다. 개인정보·비밀 검사는 본문과 파서가 반환한 속성에도 적용하지만 완전한 비식별화를 보장하지 않는다. 입력자가 이미지·주석·속성까지 비식별 여부를 확인해야 한다. 시각 자료 전송은 이미지의 메타데이터 제거 사본과 PDF 원본이며 Office 내부의 비문자 도표는 별도 이미지/PDF 등록이 필요하다.

## 결과와 검증 경계

입력·결정·초안·기준선·실행 계획을 같은 작업공간에서 이어갈 수 있다. 실제 모델은 정책 누락을 질문하거나 검증에 실패할 수 있으며, 실패 결과를 현재 요구사항에 적용하지 않는다. 실제 고객 정책을 합성 시험의 답변으로 대신하지 않는다. DB 연결·자동 코드 구현·배포·공식 감리 승인은 이 결정의 범위 밖이다. 지원 형식·한도·재실행 절차의 정본은 [실행 안내](../../03-guides/requirements-workspace-guide.md)다.
