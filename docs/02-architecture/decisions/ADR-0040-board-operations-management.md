# ADR-0040 — 게시판 운영 화면을 두고, 사용 안 함·예약·상단 고정을 서버가 집행한다

- 상태: Accepted
- 결정일: 2026-10-22
- 승인: 사용자가 2026-10-22 게시판 고도화 설계 검토 뒤 "니가 권장하는 최선의 방안으로 설계문서를 완성해줘"라고 결정을 위임했다. 아래 결정은 그 권고안이다. 2026-10-23 사용자는 A0~B3를 이어서 구현하도록 하고, 이 ADR의 스키마 변경(버전 컬럼, 변경 이력 표, 예약·고정·비밀글·추천 설정 컬럼, 상단 고정 컬럼, 신규 표준 용어 6건, `BOARD_PIN`, 메뉴 표시명 데이터 변경)을 저장소 Flyway로 일괄 승인했다. 공유 OCI 적용은 PR이 병합될 때마다 하고, 예약 집행 전 진단에서 미래 시작일·형식 오류 행이 나와도 보정하지 않는다. 그 밖의 코어 데이터 변경은 따로 승인받는다.
- 대체: [DEC-OPS-206](../../../.agent/memory/decisions.md)의 "시작일은 기록만 하며 노출을 늦추지 않는다" 부분(②. 종료일 집행 ①은 유지한다).
- 후속 결정: 결정 8의 "공개 준비는 일반 그룹에 보이는 활성 메뉴가 있어야 통과한다", 설계서 §5.3 마법사의 메뉴 단계와 결과 화면 순서, §5.6 메뉴 경로 인계의 범위는 [ADR-0043](ADR-0043-board-publish-flow-and-designated-boards.md)을 따른다.

## 배경

게시판 관리는 마스터 목록, 생성 마법사, 메뉴 관리, 권한 관리로 흩어져 있다. 그래서 운영자가 새 게시판을 만든 뒤 공개 준비를 끝내려면 화면을 여러 번 옮겨 다녀야 한다. 적대적 검토와 코드 조사로 다음이 확인됐다([설계서 §3](../board-management-expansion-design.md#3-확인한-현행-동작)).

- 게시판 "사용 안 함"은 조회만 닫고 등록·수정·삭제·해결 표시는 열어 둔다. 마법사는 게시판을 사용 상태로 만들므로, 메뉴가 비활성이어도 주소를 아는 사용자는 바로 읽고 쓴다.
- 게시글 권한은 게시판마다 나뉘지 않고 `ROLE_USER`에 기본 배정된다. 메뉴는 접근을 막지 않는다.
- 게시 시작일은 어디서도 집행되지 않는다. 종료일은 공개 FAQ와 첨부 판정에서 빠져 있다.
- 시드 게시판의 메뉴는 모두 허브 탭(`?tab=`)으로 연결돼, 메뉴 주소만으로는 연결 여부를 판정할 수 없다. 새 메뉴는 관리자 그룹에만 자동으로 보인다.
- 기존 `ntc_yn`의 표준 정의는 "공지 여부"이고, 상단 고정에는 별도 표준 용어 `UPEND_FIX_YN`이 있다.

## 결정

번호는 설계서의 D1~D12와 같다.

1. **사용 안 함 게시판**: 이용자에게 읽기·쓰기를 모두 닫는다(404). `BOARD_READ_ALL` 보유자는 읽고, 해당 동작 권한이 있으면 글을 준비하거나 정리한다. 쓰기 판정은 서비스의 진입 판정 한 곳에 모으고 만족도 수정·삭제도 같은 경계를 지난다. 사용 여부는 커뮤니티 가드보다 먼저 본다. 마법사는 게시판을 사용 안 함으로 만든다. 공개 준비와 사용 중지는 따로 구분하지 않는다.
2. **운영 화면**: 고른 게시판의 운영은 `/admin/community/boards/master/[id]`의 `?tab=posts|settings|access`에서 한다. `[id]`와 `tab`은 URL 상태 승인 원장에 이미 있는 이름이다. 운영 화면 URL에 `?bbsId`를 싣지 않는다. 활성 메뉴 판정이 이용자 게시판 메뉴를 고르기 때문이다.
3. **예약 게시**: 시작일이 오늘(Asia/Seoul)보다 뒤인 글은 작성자와 `BOARD_READ_ALL` 외에게 모든 경로(목록·검색·통계·업무 홈 카드·상세·댓글·추천·만족도·공개 FAQ·첨부)에서 보이지 않는다. 기준일은 요청마다 한 번, 주입 가능한 시계로 계산한다. 게시 상태는 서버가 응답에 싣는다. 게시판 설정 "예약 게시"는 새 미래 시작일을 받을지만 정하고, 기존 글의 가시성을 바꾸지 않는다. 작성자는 공개 전에만 시작일을 바꾼다. 집행 전에 환경마다 기존 미래 시작일 글을 진단한다.
4. **정렬**: 일반 정렬 키는 작성일자와 게시 시작일 중 늦은 값(게시 기준일)이다. 새 컬럼 없이 질의에서 계산한다.
5. **상단 고정**: 게시글에 `upend_fix_yn`·`upend_fix_end_ymd`, 게시판에 `upend_fix_psblty_yn`·`upend_fix_uplmt_nocs`·`upend_fix_bsc_day_cnt`를 둔다. `ntc_yn`은 재사용하지 않는다. 새 기능 권한 `BOARD_PIN`은 기본 배정 없이 게시판·커뮤니티 운영 묶음에 넣는다. 공지·FAQ 지정 게시판에서는 두 편집 권한도 요구한다.
6. **설정 저장**: 새 설정은 `tb_bbs_master`에만 둔다. 옵션 표는 넓히지 않는다. 기본값은 지금 동작을 유지한다(예약 N, 고정 N, 비밀글 정책 `NONE`, 추천 Y). 신규 표준 용어는 6건이다: `RSVT_PSTG_PSBLTY_YN`, `UPEND_FIX_PSBLTY_YN`, `UPEND_FIX_UPLMT_NOCS`, `UPEND_FIX_BSC_DAY_CNT`, `PRVT_PST_PLCY_CD`, `UPEND_FIX_END_YMD`. 단어는 모두 대표어로 이미 있으므로 용어만 컬럼을 추가하는 같은 Flyway에서 등록한다. 나머지는 기존 용어(`UPEND_FIX_YN`, `RCMDTN_USE_YN`, `BBS_UPEND_CN`, `BBS_LWPT_CN`, `FORM_CN`)를 쓴다.
7. **비밀글 정책**: `NONE`(현행)·`OPTIONAL`(작성 화면 선택)·`REQUIRED`(서버 강제) 세 값이다. Q&A 게시판은 `NONE`을 유지한다(도움말 1:1 문의는 비밀, 지식 허브 질의응답은 공개).
8. **메뉴·접근**: 운영 화면은 메뉴 연결을 게시판 주소와 허브 탭 근거로 판정한다. 상태는 연결 없음·비활성·관리자 그룹만·일반 그룹 표시·확인 불가 가운데 하나다. 메뉴나 그룹을 읽을 권한(`MENU_READ`·`AUTHRT_READ`)이 없으면 확인 권한 없음으로 보이고, 공개 준비는 통과가 아니라 확인 불가로 끝난다. 공개 준비는 일반 그룹에 보이는 활성 메뉴가 있어야 통과한다. 메뉴 변경은 기존 메뉴 구조 저장으로 하고, 대상 메뉴 인계는 target-handoff 새 인계 종류로 한다.
9. **운영 이력**: 게시판이 소유하는 추가 전용 변경 이력 표를 둔다(V2_110 형식). 설정, 사용 여부(단건 비활성화를 포함한 모든 경로), 고정, 운영 화면의 게시 기간 변경(단건·일괄)을 기록한다. 작성 화면을 통한 일반 수정의 이력은 후속 설계 대상이다. 영구 삭제는 민감 작업 원장에도 남긴다.
10. **동시 수정**: 게시판 마스터에 버전 컬럼을 둔다(V2_133 형식). 게시글 수정 요청도 버전을 싣는다. 일괄 처리는 서버 재판정과 전체 미적용으로 원자성을 지킨다.
11. **사용자용 게시판 선택지**: 서버가 이용 가능한 게시판만 주는 읽기 API를 두고, 일반 사용자 경로의 시드 폴백을 걷는다.
12. **게시 기간 입력**: 8자리 형식, 달력·순서 검사(`Ymd.OPTIONAL_PATTERN`, `@YmdRange`)를 서버가 하고 입력 계약 원장에 등재한다. 일반 수정의 "null = 변경 없음"은 유지하고, 종료일 해제는 운영 일괄 처리의 명시적 동작으로 둔다.

## 영향과 경계

- 구현 순서와 배치별 검증·원장 갱신·승인 항목은 [설계서 §7](../board-management-expansion-design.md#7-구현-배치와-검증)이 정본이다. A0(결함 수정)은 이 ADR의 결정이 필요 없다.
- 쓰기 의미(결정 1)의 정본은 이 ADR이다. A2는 부정 시험을 같은 변경에 두고 red 증명은 PR에 남긴다. 스키마 일괄 승인은 [DEC-OPS-379](../../../.agent/memory/decisions.md)로 기록했고, 공유 OCI 적용은 적용 로그에 남긴다. 예약 집행(결정 3)을 구현할 때 정직성 계약의 "시작일은 기록만 한다" 단언을 의도대로 바꾸고 red를 증명한다.
- 게시판별 접근 권한(그룹별 게시판 ACL)과 게시판별 운영자 위임은 이 결정의 범위 밖이다. 게시판별 제한 수단은 커뮤니티 귀속 하나로 남는다.
- 안내문·양식·분류·초안·이력·이동·답글·신고·개인정보 점검·검토·필독은 후속 설계 대상이다. 선행 조건은 [설계서 §8](../board-management-expansion-design.md#8-후속-설계-대상)에 둔다.
