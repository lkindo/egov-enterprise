# ADR-0025 — 재사용 기반의 권한·업무 계약과 내구성 완결

- 상태: Accepted
- 결정일: 2026-09-28
- 승인: 사용자가 개선 결정안 D01~D15의 A를 모두 선택하고 구현·검증·적대적 재검토·수정, 커밋·푸시·required CI 통과 후 main 병합을 요청했다.
- 기준 소스: `15e28caabeb772236213f187ce13fae586a20dd6`
- 대체 범위: [이전 정책 제안](../../04-operations/evidence-first-policy-decisions-2026-09-27.md)의 선택 대기 항목 중 아래 결정과 겹치는 부분. 기존 Accepted ADR의 소유권·명시 권한·제품 경계는 유지한다.

## 배경과 범위

현재 제공 기능의 결함, 권한 공백, 데이터 정합성 및 장애 후 유실을 닫는다. 점수·검사 개수는 완료 기준이 아니다. 구현된 사용자 과업, 거부 반례, 실제 PostgreSQL과 브라우저, 최종 커밋에 결속된 검증 결과로 판정한다.

원래 선택지는 로컬 개선 결정안의 D01~D15였다. 다음 표와 상세 경계가 승인된 A의 추적 가능한 정본이다. 승인된 정책과 구현·검증 완료 상태는 구분한다.

## 보안과 내구성의 구체 경계

- D02의 GRANT+ASSIGN 보유자는 신뢰 루트다. 독립 복구 역할 분리를 구현했다고 주장하지 않는다. 역할 이름 ADMIN을 우회 근거로 사용하지 않는다. 자기 비밀번호 변경의 현재 비밀번호 증명과 MFA 복구는 별개다.
- D11 복구 경계의 집행 보완으로 `MFA_RECOVER` 자체의 추가·회수와 그 권한이 있는 그룹의 배정·회수·삭제도 GRANT+ASSIGN을 함께 요구한다. 개인·부서 일괄 배정, 가입 기본 그룹, 사용자 삭제를 통한 우회에도 같은 직렬화와 현재 DB 권한 검사를 적용한다. 보호계정 분류는 승인한 `USER_PASSWORD`·`AUTHRT_GRANT`·`AUTHRT_ASSIGN` 3개를 유지하며, 복구 권한 변경의 민감도와 계정 분류를 혼동하지 않는다. 이는 승인한 복구 경계의 구현 해석이며 별도 사용자 승인 또는 독립된 2인 승인 체계를 뜻하지 않는다.
- D11에서 비밀번호 초기화는 MFA를 끄지 않는다. 복구 담당 역할·본인확인·키 보관·비상 접근 준비를 명시해야 운영 강제를 활성화할 수 있다. 등록용 도전은 정상 업무 세션이 아니며, 기존 OTP 플래그만 켜서 계정을 잠그지 않는다. TOTP를 피싱 저항성 인증으로 표현하지 않는다.
- D12는 PostgreSQL 기반 내구 전달을 우선한다. core가 business-app 타입을 import하지 않으며 선택 프로필의 알림 도메인 부재를 처리한다. 메일/SMS 외부 전송은 공급자 계약 확인 전 최종 배달·정확히 한 번을 보장하지 않는다.
- D13의 전송 전 기록은 사용자가 내용을 모두 읽었다는 증거가 아니다. 감사 payload에 비밀번호·토큰·응답 본문을 복제하지 않고 현행 보존기간(24개월)을 바꾸지 않는다. afterCompletion에서 뒤늦게 실패시키는 방식으로 민감 응답 차단을 구현하지 않는다.
- D14는 과거 고아 후보 자동 삭제와 다르다. 경로가 재사용되거나 다른 파일로 교체된 경우 새 파일을 삭제하지 않아야 한다. 명시적 삭제의 안전한 재시도만 활성화한다.

## 실행·승인 및 외부 입력

L2 작업으로 승인 정책→구현→표적 검증→적대적 검토/수정→통합 검증→커밋/푸시→required CI→main 병합 순으로 진행한다. Entity·DDL 변경은 live 물리 스키마·메타 표준 확인 후 migration과 격리 PostgreSQL 검증까지 수행한다. 기존 사용자 변경은 보존한다. 같은 기계의 무거운 검증은 직렬 실행한다.

다음은 이번 코드 작업의 승인에 포함되지 않는다: 운영 DB 적용, 기존 데이터 일괄 정리, 실계정 권한 변경, MFA 강제 적용, 자격 회전, 릴리스 발행, 운영 배포. 외부 입력이 필요한 부분만 명시하고 독립적인 구현·격리 검증은 계속한다.

| 입력 | 운영 전 필요한 확인 |
|---|---|
| E01 운영 범위 | 단일/다중 인스턴스, 사용자·동시접속·첨부 규모, 지원 기기/브라우저/망. 운영 SLA를 추측하지 않는다. |
| E02 소비자·역할 | 외부 API 소비자와 전환일, 권한관리·MFA 복구·공지 편집·감사 역할. 미확인을 소비자 없음으로 취급하지 않는다. |
| E03 배포 권리·자격 | 배포 대상·자산 권리 담당·원본 자격 확인/회전. 비밀은 문서·채팅에 기록하지 않는다. |
| E04 복구·경보 | RPO/RTO·백업/키 보관·경보 담당/채널·실제 복원과 경보 수신. |
| E05 외부 발송 | SMTP/SMS 공급자·승인된 테스트 수신 범위·한도·결과 불명 시 재발송 정책. |
| E06 사람 평가·데이터 정답 | 수동 접근성 평가자·지원 환경, 과거 데이터의 권위 원천·정정 담당. 추정 정정 금지. |

기존 보류인 쪽지 수거/회수, 사업코드·행사연도 개명, 미확정 공통코드 제약/기관 수신 필드, 탈퇴자 가명화·보존기간, 운영 로그 수집, 미승인 메뉴 IA/URL 상태, 다중 인스턴스·기관별 기능, 비PostgreSQL 벤더 이관 자격, 외부 보안 probe·네트워크 신뢰 경계는 이번 A 선택만으로 승인되지 않는다.

## 헌법 대조

백엔드의 계층 분리·명시 인가·소유권·트랜잭션·계약 동기화, 프론트엔드의 과업·상태·개인정보·실제 성능/접근성 증거, DB의 live 표준·명명·생성 PK·감사 컬럼·Expand/Contract를 준수한다. 기존 예외 목록 확대나 테스트 약화로 통과시키지 않는다. 본 결정은 공통 규칙이나 세 헌법의 개정이 아니다.

## D11 신규 DB 표준 등록 승인

2026-09-28 실제 메타 조회에서 아래 표준이 없음을 확인한 후 사용자가 “추천안 전체 승인: 신규 표준 포함해 구현·격리 검증 진행”으로 승인했다. 단어 1개·도메인 1개·용어 10개를 개발용 migration과 격리 검증에 포함한다. 라이브 메타 등록·운영 DB 적용은 포함하지 않는다.

단어 `HASH`는 암호학적 **해시**이며 해시태그와 다르다. 신규 도메인 `해시값V64`는 SHA-256 lowercase hex를 위한 `VARCHAR(64)`다. 나머지 표준 도메인은 기존 메타를 재사용한다.

| 한글 용어 | 물리 약어 | 표준 도메인 | 타입·길이 |
|---|---|---|---|
| OTP인증일련번호 | OTP_CERT_SN | 일련번호N19 | BIGINT(19) |
| 인증요청일련번호 | CERT_DMND_SN | 일련번호N19 | BIGINT(19) |
| 복구코드일련번호 | RSTR_CD_SN | 일련번호N19 | BIGINT(19) |
| 사용자내부식별자 | USER_INSD_IDNTFR | 명V20 | VARCHAR(20) |
| OTP비밀암호화내용 | OTP_SECRET_ENCPT_CN | 내용V4000 | VARCHAR(4000) |
| 인증상태코드 | CERT_STTS_CD | 코드C10 | VARCHAR(10) |

| OTP최종성공일련번호 | OTP_LAST_SCS_SN | 일련번호N19 | BIGINT(19) |

자격·도전·복구코드는 별도 신규 테이블로 확장한다. 원문용 `otp_secret VARCHAR(32)`를 암호문 크기로 직접 변경하거나 기존 값을 추측 이관하지 않는다. 내부 식별자는 로그인 ID와 구분하고, 암호화 비밀 envelope·해시·인증 버전은 각각 다른 의미로 저장한다. 새 표준 승인 자체를 MFA 구현·검증 완료로 간주하지 않는다.
