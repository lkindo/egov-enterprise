# ADR-0042 — 콘텐츠 페이지 운영 보완: 초안 판정, 내려받기 파일, 게시 중지 상태, 삭제·파기, 안내 페이지 목록

- 상태: Accepted
- 결정일: 2026-10-26
- 승인: 2026-10-25 사용자가 CMS 메뉴·프로세스·UX 분석 보고서의 1~3차 개선을 순서대로 진행하라고 지시했다. 결정이 필요한 항목 가운데 "미완성 칸이 하나만 있어도 초안 저장이 막히는 규칙을 푼다"는 사용자가 직접 골랐다. 그 밖의 결정은 2026-08-23 위임에 따라 권고안으로 정했다. 2026-10-26 사용자는 게시본 삭제 금지 트리거에 파기 전용 예외를 두는 DDL(V2_143)과 병합 후 공유 OCI 적용을 승인했다. 콘텐츠 운영 메뉴 재배치(메뉴 데이터 변경)는 승인하지 않아 이 결정에 넣지 않는다.
- 대체: [ADR-0039](ADR-0039-cms-content-pages-first-scope.md) 결정 5의 "통과한 정규화 문서만 저장한다" 가운데 초안 저장 수준(→ 결정 1), 결정 7의 "리비전의 수정·삭제는 DB 트리거로 막는다" 가운데 삭제(→ 결정 5), 유보 목록의 "영구 삭제"·"미사용 업로드 정리"(→ 결정 4·5).

## 배경

1차 기능을 운영 관점에서 분석했다. 핵심 결함은 아니지만 운영자가 실수하거나 막히는 지점이 많았다.

- 초안에 이미지 하나를 아직 고르지 않았거나 바로가기 이름 하나가 비어 있어도 초안 전체를 저장할 수 없었다.
- 안내 페이지에 신청 서식(PDF·한글) 같은 내려받기 파일을 둘 방법이 없었다.
- 게시를 중지한 페이지가 "초안"과 같은 상태로 보여, 메뉴가 걸린 채 내려간 페이지를 가려낼 수 없었다.
- 잘못 만든 초안을 지울 수 없었고, 개인정보를 잘못 게시했을 때 게시본과 이미지를 지울 길이 없었다. 게시를 중지하면 일반 사용자에게서는 사라지지만, 관리 조회 권한자에게는 남고 DB 에서도 트리거 때문에 지울 수 없었다.
- 메뉴에 걸지 않은 게시 페이지는 주소를 아는 사람 말고는 찾을 수 없었다.
- 작성 권한만 있는 담당자는 게시를 맡길 방법이 없었다.

## 결정

1. **초안 판정과 게시 판정을 나눈다.** 서버 검증기 하나가 두 수준을 판정한다(`CmsDocumentValidator.Mode`). 초안 저장(DRAFT)은 아직 채우지 않은 칸을 받는다: 고르지 않은 이미지(`atchFileSn` 0), 설명 없는 이미지, 이름·주소가 빈 바로가기, 파일이 없는 내려받기 칸. 게시(PUBLISH)는 모든 칸이 완성돼야 한다. 채운 값의 형식(링크 규칙·길이·노드 구조)은 두 수준이 같다 — 초안이라도 허용하지 않는 주소는 저장하지 않는다. 화면 판정기(`document.ts`)는 같은 두 수준을 따르고, 공용 fixture 의 사례가 수준(`mode`)을 밝힌다. 게시할 수 있는 문서는 초안 판정으로도 같은 모양으로 저장된다(두 시험이 불변식으로 본다).
2. **내려받기 파일 칸을 둔다.** 칸 종류 `files` — 항목마다 첨부 하나와 표시 이름, 게시 시 1~10개. 파일은 기존 업로드 API 로 올리고 이미지와 같은 귀속 규칙을 따른다(원 업로더, 다른 페이지에 속하지 않음, 파일 하나뿐인 첨부). 확장자는 pdf·hwp·doc·docx·xls·xlsx·ppt·pptx·txt 이고 압축 파일은 받지 않는다. 이미지는 png·jpg·jpeg·gif 로 좁힌다 — 일반 업로드 API 가 webp 를 받지 않는데 화면이 webp 를 안내했다. 한 첨부를 이미지와 내려받기 파일로 함께 쓰지 않는다. 열람은 결정 8(ADR-0039)과 같은 참조원 판정을 따른다.
3. **게시 중지를 상태로 가른다.** 상태는 DRAFT(한 번도 게시하지 않음)·PUBLISHED·UNPUBLISHED(게시한 적이 있지만 지금은 내림)·ARCHIVED 다. 목록 조건은 ACTIVE(보관 제외 전체)·PENDING(게시 대기: 미게시 초안과 게시본과 다른 저장 초안이 있는 게시 중 페이지)·DRAFT·PUBLISHED·UNPUBLISHED·ARCHIVED 다. "게시본과 다름"은 제목·요약·문서(jsonb 값 비교)로 판정한다. 검색어의 `%`·`_` 는 글자 그대로 찾는다.
4. **한 번도 게시하지 않은 페이지는 지울 수 있다.** 사용자에게 보인 적이 없으므로 작성 권한(`CMS_UPDATE`)으로 지우고, 주소와 귀속 첨부를 돌려준다. 초안 저장은 초안에도 어느 게시본에도 쓰이지 않는 첨부의 귀속을 푼다. 귀속을 푼 첨부는 다른 업무 참조가 하나도 남지 않았을 때만 파일까지 지운다(`FileService.discardUnreferencedAttachment`). 참조원 조회에 실패하면 그 저장·삭제·파기 전체가 되돌아가고 아무것도 지우지 않는다. 다른 참조 때문에 남긴 파일은 화면에 따로 알리지 않는다.
5. **파기 경로를 둔다(사고 대응).** 새 권한 `CMS_PURGE`(기본 그룹·권한 묶음 없음 — 필요할 때 기능별 권한 표에서 담당자에게 준다)로 두 가지를 한다. ① 게시를 중지한 페이지의 초안·모든 게시본·귀속 첨부를 지운다. 주소를 다시 입력받는다. ② 지금 보이지 않는 지난 게시본 하나를 지운다. 그 게시본만 쓰던 첨부는 초안도 쓰지 않으면 귀속을 풀고 파일까지 지운다. 게시본 번호는 저장하지 않고 세므로 파기한 게시본보다 뒤의 번호가 하나씩 당겨진다. 둘 다 처리 근거 번호(민원·사고 접수 번호, `[A-Za-z0-9][A-Za-z0-9._-]{0,199}`)를 받아 민감 작업 감사에 남긴다 — 사유 본문은 받지 않는다(감사 원장에 자유 서술을 싣지 않는다, `SensitiveAuditPort#recordReferencedMutation`). DB 트리거는 같은 트랜잭션에서 파기 표시(`set_config('nuri.cms_purge','on',true)`)를 켠 동안에만 게시본·게시본 첨부 집합의 **삭제**를 받는다. **수정**은 표시가 있어도 계속 거부한다(V2_143).
6. **게시 페이지를 찾을 길을 둔다.** 로그인 사용자용 안내 페이지 목록(`/pages`, 게시본 제목·요약·게시일, 검색어)과 그 목록으로 가는 바닥글 링크(셸 링크 기여)를 둔다. 열람 범위는 게시본과 같다(로그인 사용자 전체). 통합 검색 편입과 메뉴 데이터 변경은 하지 않는다.
7. **작성과 게시를 나눠 맡길 수 있게 한다.** 권한 묶음 "콘텐츠 페이지 작성"(`CMS_ADMIN_READ`·`CMS_UPDATE`·`FILE_UPLOAD`)을 더한다. 게시 요청 상태·알림은 두지 않는다 — 작성자는 게시 대기 목록(결정 3)에 남고, 화면이 게시는 게시 권한자가 한다고 알린다.
8. **이미지 열람 감사는 그대로 두고 화면 캐시만 둔다.** 이미지를 내려받을 때마다 개인정보 접속기록이 남는 것은 일반 파일 API 의 기존 정책이다(ADR-0039 결정 8 — CMS 전용 이미지 경로를 두지 않는다). 화면은 같은 첨부를 다시 받지 않게 로그인 동안 캐시한다.

## 영향과 검증

- 새 마이그레이션 V2_143 은 함수 본문만 바꾼다(새 표·컬럼·표준 용어 없음). 예전 앱은 표시를 켜지 않으므로 동작이 같다. 되돌리기는 V2_137 의 함수 본문을 다시 적용한다.
- 업무 홈 지정 상태의 제목은 게시본 제목이다. 게시 중지가 홈 지정을 함께 풀면 홈 변경도 민감 작업 감사에 남긴다.
- 검증: 서버·화면 판정기의 공용 fixture(초안·게시 사례), 서비스 단위 시험, PostgreSQL 수명주기 통합 시험(목록 조건의 jsonb 비교, 미완성 초안의 게시 차단, 미사용 첨부 정리, 삭제·파기, 트리거 예외 — 예외를 끄면 붉어지는 것을 확인했다).
- 남은 유보: 권한 그룹별 열람, 업무 홈 전체 대체, 문서 안 공지·도움말 피드, 예약·승인 게시(상태가 있는 게시 요청), 익명 공개, 통합 검색 편입, 콘텐츠 운영 메뉴 재배치. 콘텐츠 페이지 조회 수 통계는 두지 않는다.
- 운영 절차는 [콘텐츠 운영 안내](../../03-guides/content-operations-guide.md)가 정본이다. 이 결정은 기관의 콘텐츠 운영 승인이나 개인정보 게시 검토를 대신하지 않는다.
