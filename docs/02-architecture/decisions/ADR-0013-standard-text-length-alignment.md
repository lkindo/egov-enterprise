# ADR-0013: 표준 길이 24개 정합과 SMS 수신번호 정규화

**Status:** Accepted — 대상·이행 범위. 환경별 적용 완료 여부는 운영 실측으로 확인한다.

**Date:** 2026-09-09

**Origin:** 사용자 요청 “설계확정이 필요한 6개를 제외한 나머지 건은 DB, 백엔드, 프론트엔드 전반적으로 수정진행”.

## Context

현재 소스와 OCI PostgreSQL 17.9(Flyway 2.88)의 `information_schema`, 표준 메타 3종, 데이터 길이·키 관계를 대조했다. 정확한 용어·VARCHAR 도메인이 매칭되는 180컬럼 중 30개가 길이 불일치였다. 19개는 일반 확장이고, 권한명·담당자명·주소 2개의 축소는 초과 데이터 0건이다. SMS 수신번호 115건은 모두 하이픈 포함 13자로, 하이픈 제거 후 11자리이며 `(sms_trsm_sn, 수신번호)` 중복은 0건이었다. 이는 조회 시점의 사실이며 이행 시 다시 검증한다.

## Decision

1. 일반 문자열 19개, 초과 데이터 없는 축소 4개, SMS 수신번호 1개의 DB·Entity·요청 DTO·OpenAPI·Zod·입력 UI 계약을 함께 맞춘다. 프로그램파일명 3개, 기관 변경시각 2개, 주민등록번호 암호문 1개는 변경하지 않는다. 표준 메타를 물리 폭에 맞춰 수정하지 않는다.
2. VARCHAR 확장 19개는 기존 V2_86과 같은 제한된 타입 변경 경로를 사용한다. 모든 대상 잠금을 `NOWAIT`로 선점하고, 표준과 현재 타입을 재검사하며 `statement_timeout`으로 실행 시간을 제한한다. 대상별 이유와 PostgreSQL 검증을 ZDM waiver에 결속한다. 이 구현은 새 컬럼을 추가하는 4단계 방식이 아니며, DB 헌법 제7조의 마커 기반 예외를 사용한다. 운영의 무중단 롤링 이행을 검증했다고 표현하지 않는다.
3. 축소는 제한·정규화 코드를 V2_91 상태에 배포하고 구버전 발송 작업을 소진한 뒤 진행한다. 별도 V2_92에서 기존 폭을 유지하며 검증된 입력 CHECK와 SMS 정규화를 적용하고, V2_93에서 CHECK 존재와 초과 0을 다시 확인하고 물리 폭을 축소한다. 각 Flyway 파일은 원자적이며, 여러 파일의 적용 전체를 단일 transaction이라고 주장하지 않는다.
4. SMS 수신번호는 선행 0을 보존하는 숫자 문자열(1~11자리)로 저장한다. 기존 하이픈 입력은 제거 후 검증하며 국제번호·문자·하이픈만 있는 입력은 거부한다. 기존 서비스가 허용하던 짧은 숫자 번호를 새로 제한하는 최소 자리수 정책은 도입하지 않는다. 사용자 연락처와 직접 입력 모두 정규화한 다음 중복을 제거한다. 수신번호 검색은 저장값과 검색어의 하이픈을 함께 제거해 전환 전후 표현과 부분 검색을 지원한다.
5. API는 숫자형 표현을 정본으로 노출하되 이전 클라이언트의 하이픈 JSON 입력은 Bean Validation 전에 정규화한다. 발송 결과 기록은 신키를 우선 조회하고 전환 전 하이픈 키를 보조 조회한다. 데이터 이행은 외부 발송을 유발하지 않으며 기존 발송 상태·메시지·감사값·전송 FK를 보존한다.
6. 메일·쪽지의 레거시 제목 DTO 별칭에는 누락된 길이 검증을 추가한다. 조직명은 동일 테이블의 두 Entity를 함께 수정한다. 원본 파일명 상한은 300으로 맞추되 저장 파일명은 기존 UUID 생성 방식을 유지한다. 권한명 입력의 기존 60자 제품 제한은 유지한다.

## Consequences and verification

- 표준 초과 값 또는 SMS 정규화 후 키 충돌이 존재하는 환경은 이행을 거부한다. 값을 절단하거나 충돌 행을 삭제·병합하지 않는다.
- 입력 허용 범위 축소와 SMS 저장 표현 변경은 구버전 애플리케이션의 쓰기와 호환되지 않을 수 있다. 백업 복구 증거·발송 작업 소진·단계별 애플리케이션 전환을 확인한 뒤 운영에 적용한다.
- 확장 후 새 길이 데이터가 쓰이면 이전 폭으로 축소하는 rollback은 안전하지 않다. 기본 복구는 forward-fix이며, 백업 복원은 쓰기 중단 후 DB·대응 앱 버전을 함께 되돌리는 별도 절차다.
- [PostgreSQL 검증](../../../api-server/src/test/java/nuri/api/schema/StandardLengthMigrationIntegrationTest.java)은 값·heap 보존, 잠금 경합 실패, 메타 drift 거절, 초과 데이터·SMS 중복 거절, 신형 입력과 보류 6개의 길이 보존을 확인한다.
- 전체 절차와 환경별 적용 증거는 [표준 길이 전환 런북](../../04-operations/standard-length-alignment-runbook.md)에 둔다. 헌법·게이트의 일반 정책과 레거시 예외 동결 목록은 변경하지 않는다.

검증 게이트 변경: 공용 PostgreSQL migration 검증 1개 추가로 동결 census를 38 → 39로 올리고, 대상 24개 마커 예외와 새 게이트의 baseline fingerprint를 함께 갱신한다. 기존 동결 항목의 삭제·일괄 제외는 하지 않는다.
