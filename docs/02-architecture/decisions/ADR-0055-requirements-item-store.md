# ADR-0055 — 요구사항·산출물 항목 저장소와 점진 분석

- 상태: Accepted
- 결정일: 2026-11-13
- 승인: 사용자는 “문서들은 계속 추가될수 있고 요구사항도 베이스라인을 정리할때까지는 계속 추가되면서 계속 점진적으로 고도화 되어가는 형태”, “확정된 요구사항은 … 요구사항으로 산출물을 내놓을 수 있어야”(대한민국 공공표준), “분석설계산출물은 정보공학방법론의 산출물을 적용하고 … 내가 선택한 산출물만 적용하고 … 나중에 추가로 작성할수 있어야”, “산출물들은 순서대로 계속 붙이다가 컨텍스트 초과가 났는데 이런 문제 안생기게 … 기존에 구축되어 있는 화면이나 프로세스 무시하고 니가 최적의 안을 다시 설계해줘”라고 요청했다. 설계안에 “니 추천대로 진행해주고, 리뷰는 제미나이 카본 하이로 진행해줘”, 화면 시안을 본 뒤 “지금 시안으로 일단 작업 진행해줘”라고 승인했다.
- 대체 범위: [ADR-0052](ADR-0052-ai-document-to-development-plan.md) 결정 1의 기본 화면 흐름(판독 뒤 문서 통합 → 요구사항 → 검토 → 계획 → 한 번의 최종 확인)과 [ADR-0051](ADR-0051-ai-first-requirements-workflow.md) 결정 1·6의 요구사항·에픽 생성과 확정 순서. 원본 판독(ADR-0052 결정 2~4), CLI 실행 경계(ADR-0051 결정 3·4), 저장·세션·기관 인수 경계([ADR-0050](ADR-0050-local-requirements-workspace.md)), 민감정보 안내([ADR-0053](ADR-0053-private-analysis-sensitivity-advisories.md))는 유지한다. 종전 화면은 검수·감리와 보완 경로로 남는다.
- 후속 결정: 결정 D-4의 프로그램이 올리는 값 차이와 결정 D-5의 확정 차단 대상 가운데 그 부분은 [ADR-0056](ADR-0056-requirements-wording-notes.md)이 대체한다. 결정 D-5의 쟁점 해소 가운데 질문 하나에 답 하나라는 단위는 [ADR-0058](ADR-0058-requirements-question-groups.md)이 대체한다(같은 것을 묻는 질문은 한 번에 답한다).

## 배경

종전 흐름은 요구사항 묶음을 순서대로 분석하면서 앞서 만든 요구사항 전체와 인용을 다음 요청에 다시 실었다. 문서가 늘수록 요청이 커져 크기 한도에 닿았고, 한도 안에 넣으려는 분할 규칙이 계속 늘었다. 문서 한 건을 더하면 전체 흐름을 다시 지나야 했고 확인은 마지막 한 번에 몰렸다.

## 결정

| D-n | 결정 | 관련 H | 영향 계약 파일 | 부정 시험 |
|---|---|---|---|---|
| D-1 | 요구사항과 산출물 항목을 서로 독립된 기록으로 저장하고 문서는 기록에서 조립한다. 저장은 `requirements-ui.json`의 `studio` 키이며 같은 잠금·저널·검사된 커밋을 쓴다. 정규화하면 달라지는 값은 저장을 거부한다. | H2 | `studio-model.mjs`, `engine.mjs` | 비정규 상태 10종 거부 |
| D-2 | 분석은 조각(조항) 단위로 한 번씩만 한다. 조각마다 요구사항 여부와 관련 산출물 종류를 표시해 두며, 꺼 둔 산출물의 표시도 남긴다. 문서를 더하면 그 문서의 조각만 보내고, 산출물을 나중에 켜면 표시된 조각만 보낸다. 조각 본문이 바뀌면 그 조각만 다시 분석하고 그 조각을 인용한 근거에 변경 표시를 한다. | - | `studio-model.mjs`, `studio.mjs` | 두 번째 문서에서 첫 문서 미전송 |
| D-3 | 모델 요청 하나는 조각 묶음 하나(24개·28KiB 이하) 또는 항목 몇 건과 그 비교 대상만 싣고, JSON 48KiB를 넘으면 줄이지 않고 거부해 그 사실을 센다. 비교 대상은 로컬 어휘 색인이 찾은 같은 종류의 기존 항목 6건 이하이고, 스토리를 쓸 때 보내는 기존 에픽도 비슷한 12개 이하다. 긴 기록은 앞부분만 실어 비교하되, 그렇게 내린 판정은 바로 적용하지 않고 변경 제안으로 올린다. 저장된 항목 전체를 보는 점검(추적 누락, CRUD 불일치 등)은 프로그램 규칙으로 한다. | H5 | `studio-tasks.mjs`, `studio-index.mjs` | 저장 4배 증가에도 요청 상한 유지, 초과 입력은 오류 |
| D-4 | 후보는 새 항목·같은 항목·충돌 가운데 하나로 처리한다. 모델은 같은지와 무엇이 충돌하는지만 답하고, 더해지는 내용은 그 후보에서 추출한 내용뿐이다. 초안에는 빈 글 칸을 채우고 목록·표에 행을 더할 뿐 지우거나 바꾸지 않는다. 확정된 기록은 출처까지 포함해 바꾸지 않고 변경 제안으로 올리며(사람도 확정 기록의 필수 칸을 비운 채 저장할 수 없다), 짧은 값이나 표의 같은 행이 문서마다 다르면 프로그램이 쟁점으로 올리고, 칸이 가득 차 더하지 못한 내용도 쟁점에 담아 남긴다. 같은 이름의 산출물 항목도 더할 내용이나 다른 값이 있으면 모델 비교를 거친다. 비교한 뒤 사람이 그 기록을 고쳤으면 판정을 버리고 다시 비교한다. 충돌은 양쪽 문장을 남긴 쟁점으로 올린다. 답이 없거나 범위를 벗어난 판정은 새 초안으로 둔다. | H3 | `studio-model.mjs`, `studio.mjs` | 확정 기록 불변(출처 포함), 기록에 없는 문장은 교체 대상 아님, 고친 기록에 대한 판정 미적용 |
| D-5 | 확정·제외·기준선·변경 제안 반영·쟁점 해소는 사람만 한다. 필수 칸·출처가 비었거나 열린 쟁점·질문이 있으면 확정할 수 없다. 기준선은 그때의 확정 기록을 불변 보관 파일로 남기고, 그 뒤의 변경을 표시한다. | H3 | `studio.mjs` | 쟁점이 있는 항목의 확정 거부 |
| D-6 | 요구사항 기록은 공공 제안요청서의 요구사항 양식(분류, 고유번호, 명칭, 정의, 세부 내용, 산출 정보, 관련 요구사항, 출처)을 따른다. 고유번호는 확정할 때 분류별 일련번호로 한 번 발급하며 다시 쓰거나 바꾸지 않고, 번호를 받은 뒤에는 어떤 경로로도 분류를 바꾸지 않는다(번호와 분류가 어긋난 상태는 저장을 거부한다). | 식별자 | `studio-catalog.mjs`, `studio-model.mjs` | 제외한 번호 재사용 없음, 분류 변경 거부 |
| D-7 | 분석·설계 산출물은 정보공학 산출물 13종 가운데 켠 것만 작성한다. 종류·칸·필수 여부·추출 지시는 한 카탈로그의 자료이며 화면·요청·검증·문서가 모두 그것을 읽는다. 속성정의서·논리 ERD·CRUD 매트릭스·요구사항추적표는 다른 기록에서 만든다. 끈 산출물의 항목과 표시는 보관한다. | - | `studio-catalog.mjs`, `studio-render.mjs` | 꺼 둔 산출물은 요청·문서·점검에서 제외 |
| D-8 | 스토리는 확정된 기능·인터페이스·데이터 요구사항에서만 만든다. 성능·보안·품질·제약 등은 모든 스토리에 붙는 품질 기준이다. 요구사항의 내용이 바뀌면 그 요구사항의 스토리만 다시 쓸 대상이 되고, 응답이 빠뜨린 요구사항의 기존 스토리는 지우지 않는다. 제외하거나 확정을 취소한 요구사항의 스토리는 사람이 계획 반영을 실행할 때 지운다. 개발 인계 문서는 스토리 하나에 필요한 요구사항·인수조건·관련 산출물을 담는다. | - | `studio-model.mjs`, `studio-render.mjs` | 초안·품질 요구사항은 스토리 대상 아님 |
| D-9 | 실행마다 자료 전송과 민감정보 분석 방식에 동의를 받는다. 끝난 요청은 곧바로 저장하므로 중지·실패 뒤 다시 실행하면 남은 부분만 진행하고, 실행기를 다시 시작해도 스스로 이어 가지 않는다. 쓸 수 없는 응답은 저장하지 않고 수를 세며, 같은 조각이 두 번 답을 받지 못하면 실패로 닫아 문서별로 보인다. 요구사항이라고 답했는데 쓸 수 있는 후보가 없는 조각도 답을 받지 못한 것으로 본다. 한도를 넘는 값은 사람이 입력하면 저장을 거부하고, 모델이 내면 일부만 담았다는 질문을 붙여 확정을 막는다. 쓸 수 없는 응답이 세 번 이어지면 실행을 멈춘다. 단계별 지시문과 버전을 화면에 보인다. | H5 | `studio.mjs`, `studio-tasks.mjs` | 동의 누락 거부, 재시작 뒤 중단 표시 |
| D-10 | 문서는 Markdown과 CSV로 내려받는다. CSV 칸이 수식으로 시작하면 무력화한다. | - | `studio-render.mjs` | 수식 시작 칸 |

모델 출력은 비신뢰 자료다. 카탈로그에 없는 칸·종류·값은 버리고, 근거는 그 요청에 실어 보낸 조각 번호로만 받는다. 근거 조각이 없는 후보는 만들지 않는다.

## 결과와 검증 경계

- 중복 판정의 입구는 어휘 유사도다. 표현이 전혀 다른 같은 요구는 비교 대상으로 뽑히지 않아 별개의 초안으로 남으며, 사람이 제외하거나 고친다. 잘못 합치는 쪽보다 따로 남는 쪽을 택했다.
- 근거는 조각(1,800자 이하) 단위로 연결한다. 조각 안의 인용 위치를 따로 대조하지 않는다. 추적은 같은 조각을 인용한 기록과 사람이 직접 건 연결에서 나온다.
- 이 흐름의 스토리는 `backlog.json`, 종전 `TASK-PACKAGE.md`, 검수표로 넘어가지 않는다. 검수·감리는 종전 화면과 CLI의 경계 그대로다. 두 흐름의 연결은 정해지지 않았다.
- 요구사항 분류 11종과 산출물의 칸은 공개된 제안요청서 사례와 일반적인 정보공학 산출물 구성을 따른 기본값이다. 고시·기관 표준 원문과 대조한 것이 아니며, 다르면 카탈로그를 고친다.
- 시험은 합성 자료와 규칙 기반 가짜 응답으로 저장·요청 크기·판정 규칙·화면 흐름을 검증한다. 실제 모델이 내는 분류·추출의 품질은 증명하지 않는다.
- 항목 4,000건 등 작업공간 하나의 상한과 `requirements-ui.json` 8MiB 한도 안에서 동작하며, 넘으면 저장을 거부한다. HWP·Word·Excel 출력은 없다.

사용법은 [실행 안내](../../03-guides/requirements-workspace-guide.md)에 둔다.
