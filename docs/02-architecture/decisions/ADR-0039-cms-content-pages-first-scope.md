# ADR-0039 — 콘텐츠 페이지(CMS) 1차 범위: 로그인 사용자 열람, 업무 홈 상단 조각, 서버가 검증하는 JSON 문서

- 상태: Accepted
- 결정일: 2026-10-22
- 승인: 사용자가 2026-10-22 Codex CMS 설계 v2의 적대적 점검에서 제시한 권장안 다섯 건(홈 조각·1차 그룹 열람 제외·버전 컬럼 관례·jsonb·링크 범위)을 채택하고 구현을 지시했다. 세부 결정은 2026-08-23 위임에 따라 권장안으로 정했다.
- 관련: [DEC-OPS-378](../../../.agent/memory/decisions.md)(낙관적 잠금 컬럼 관례), [ADR-0017](ADR-0017-task-oriented-menu-navigation.md)(메뉴 영역), [ADR-0028](ADR-0028-presets-are-named-domain-lists.md)(기능 선언).

## 배경

운영자가 안내 페이지와 로그인 뒤 첫 화면의 소개 영역을 코드 배포 없이 작성·게시하려는 요구가 있다. 외부 설계 시안(Codex v2, 저장소 밖)은 업무 홈을 CMS 페이지로 대체하고 권한 그룹별 열람·문서 안 공지 피드·상세 파일 UUID 참조까지 1차에 넣었다. 점검 결과 홈 대체는 `/`의 통합 대시보드로 가는 길을 없애고, 그룹 열람은 권한 카탈로그 밖의 새 인가 축이며, 공지 피드는 금지된 app→app 결합이었다. 이 결정은 같은 사용 목적을 기존 구조 안에서 이루는 1차 범위를 정한다.

## 결정

1. **선택 기능 `cms`.** business-app의 선택 업무 기능으로 둔다. 기능 선언(`config/modules`)이 소유 패키지·표·권한·화면·슬롯 기여를 가진다. 빠진 구성에서는 화면·API·권한·첨부 참조원·홈 조각이 함께 사라진다. CMS 전용의 기동 거절 검사는 두지 않는다 — 생성기는 새 소스와 새 DB 번들을 만들 뿐, 설치된 DB에서 기능을 빼는 흐름이 없다.
2. **업무 홈은 대체하지 않는다.** `/`는 통합 대시보드로 남는다. 운영자가 지정한 게시 페이지는 업무 홈 맨 위의 조각(home-sections 슬롯 기여)으로 보인다. 지정이 없거나 페이지가 게시 중지·보관되면 조각만 사라진다. 홈 지정은 사이트 설정 한 행이 가리키며, 별도 권한으로 바꾼다.
3. **1차 열람 범위는 로그인 사용자 전체다.** 게시본은 인증된 사용자 누구나 읽는다. 권한 그룹별 열람은 새 인가 축이므로 요구가 확정되면 별도 ADR로 연다. 화면은 게시 전에 "로그인한 모든 사용자가 읽을 수 있다"고 알린다.
4. **문서 정본은 JSON 하나다.** 초안과 게시 리비전은 `schemaVersion`과 영역(section) 목록을 가진 문서를 jsonb로 저장한다. 영역은 1단·2단(50:50, 40:60)·3단 중 하나이고 단마다 내용 하나(서식 본문·이미지·바로가기 목록)를 둔다. 배경·간격은 의미 토큰 이름으로만 저장한다(색 이름 금지). 중첩 영역·자유 HTML·CSS·스크립트는 받지 않는다. 문서 안 공지 피드는 두지 않는다 — 업무 홈에는 게시판 조각이 이미 공지를 보인다.
5. **검증은 서버 한 곳, 렌더링은 HTML 문자열 없이.** 허용 노드·속성·크기·링크·파일 참조는 서버 검증기 하나가 판정하고, 통과한 정규화 문서만 저장한다. 화면은 문서를 React 요소로 그리며 HTML 문자열 삽입을 쓰지 않는다. DB에는 문서를 해석하는 트리거를 두지 않는다. 서버 검증기와 화면 렌더러는 같은 판정 fixture로 대조한다.
6. **링크는 `https`·사이트 내부 경로(`/`로 시작)·`mailto`·`tel`만 허용한다.** 자격증명이 든 주소·`javascript:`·`data:`·프로토콜 상대 주소는 거부한다. 내부망 `http`는 기관 요구가 확인될 때 배포 설정의 허용 호스트로 연다.
7. **게시 모델.** 페이지당 초안 하나와 불변 게시 리비전 이력을 둔다. 게시는 저장된 초안과 기대 버전에 결속한다 — 같은 요청을 다시 보내면 버전이 달라 409가 되므로 중복 리비전이 생기지 않는다. 별도 멱등 키는 두지 않는다. 리비전의 수정·삭제는 DB 트리거로 막는다. 이력 복원은 과거 본을 편집기에 불러와 새 초안으로 저장하는 동작이다. 게시 중지는 현재 게시 포인터를 비우고, 홈 지정이 그 페이지면 같은 트랜잭션에서 해제한다. 재게시는 홈 지정을 되살리지 않는다. 주소(slug)는 최초 게시 뒤 바꿀 수 없다.
8. **첨부는 기존 파일 구조를 그대로 쓴다.** 이미지는 기존 업로드 API로 올린 첨부(`atch_file_sn`)를 문서가 가리키고, 초안 저장 때 서버가 업로더 본인 확인 뒤 그 첨부를 페이지 소유로 등록한다. 한 첨부는 한 페이지에만 속한다. 열람은 기존 첨부 참조원 구조에 CMS 참조원을 등록해 판정한다: 현재 게시 리비전이 가리키면 로그인 사용자, 그 밖에는 CMS 조회 권한자만 연다. 페이지가 쓰는 파일은 일반 파일 API로 지울 수 없다(외래 키). 열람 판정이 묶음 단위이므로, 업로더가 일반 파일 API로 같은 묶음에 파일을 덧붙이면 그 묶음은 로그인 사용자 공유를 잃는다 — 이미지 검사를 거치지 않은 파일을 모두에게 열지 않는다.
9. **메뉴 연결은 기존 메뉴 관리가 맡는다.** 게시한 페이지에서 기존 대상 인계로 메뉴 관리의 생성 위치 선택을 연다. 메뉴 저장 시 서버가 페이지 게시 여부를 검사하지 않는다(core가 CMS를 알지 않는다). 게시 중지된 페이지로 가는 메뉴는 "없거나 게시되지 않은 페이지"를 보인다 — 없는 주소와 같은 화면이라 미게시 페이지의 존재를 드러내지 않는다. 메뉴 표시(NAVIGATION)는 열람 권한이 아니다.
10. **권한.** 관리 화면 조회(`CMS_ADMIN_READ`), 페이지 만들기·초안 수정(`CMS_UPDATE`), 게시·게시 중지·보관(`CMS_PUBLISH`), 홈 지정(`CMS_HOME_UPDATE`)을 둔다. 기본 배정은 관리자·시스템 그룹이며, 권한 묶음 "콘텐츠 페이지 관리"가 이미지 올리기(`FILE_UPLOAD`)와 함께 맡긴다. 게시본 열람 API는 인증만 요구한다. 게시·게시 중지·홈 변경은 민감 작업 감사에 남긴다.

## 영향과 경계

- 새 표는 콘텐츠·게시 리비전·리비전 첨부·페이지 소유 첨부·사이트 설정이다. jsonb 컬럼과 구조 문서 도메인은 이 기능이 처음 도입한다. 이관 도구는 jsonb를 해석하지 못해 적재를 거부한다 — 검증기를 우회한 문서 적재를 막는 동작이므로 1차에서 그대로 둔다.
- 낙관적 잠금 컬럼은 [DEC-OPS-378](../../../.agent/memory/decisions.md)의 `version integer` 관례를 따른다.
- 유보: 권한 그룹별 열람, 업무 홈 전체 대체, 문서 안 공지·도움말 피드, 예약·승인 게시, 열 안 여러 내용, 표 제목·설명, 익명 공개, 영구 삭제, 미사용 업로드 정리.
- 이 결정은 기관의 콘텐츠 운영 승인이나 개인정보 게시 검토를 대신하지 않는다. 운영자는 게시 전에 공개 범위(로그인 사용자 전체)를 확인한다.
