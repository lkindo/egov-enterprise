# ADR-0048 — 업로더 근거의 범위와 개인 귀속 첨부의 개별 삭제

- 상태: Accepted
- 결정일: 2026-10-31
- 승인: 보안 지시서 검증의 결정 항목을 사용자가 "권장한 대로 결정"으로 확정했다.
- 관계: [ADR-0045](ADR-0045-bookmark-cleanup-input-policy-and-memo-read-consistency.md) 결정 5의 "지시 후 모든 첨부 변경 금지를 새로 도입하지 않는다"를 이 결정의 범위에서 대체한다. 토큰이 내용 동등성만 보장한다는 나머지 내용은 그대로다. [ADR-0040](ADR-0040-board-operations-management.md) 결정 1의 사용 안 함 게시판 잠금이 업로더에게도 걸리게 한다.

## 맥락

첨부 정책은 업로더 본인을 참조 조회보다 먼저 허용했다. 이 근거의 목적은 글을 저장하기 전의 미첨부 창이지만, 업무 행에 붙은 뒤에도 그대로 살아 있어 두 가지 문제가 생겼다.

- 사용 안 함 게시판은 작성자의 소유 근거까지 닫는데, 작성자가 업로더이면 잠금을 지나 첨부를 열고 지울 수 있었다.
- 개인 귀속 첨부는 여러 당사자가 같은 묶음을 본다. 쪽지 수신자 한 명이 개별 삭제를 부르면 발신자와 다른 수신자의 파일도 사라지고, 메모 작성자는 지시가 달린 뒤에도 첨부를 뺄 수 있었다. 지시가 달린 메모의 본문 수정과 삭제는 이미 막혀 있어 첨부만 빈틈이었다.

화면에서 개별 삭제 API 를 부르는 곳은 게시글 작성 화면 하나뿐이다.

## 결정

1. 업로더 근거는 어느 업무 행도 가리키지 않는 첨부에만 쓴다. 참조를 판정하지 못하면 참조가 있는 것으로 본다. 업무 행에 붙은 뒤에는 열람과 삭제 모두 그 참조의 판정을 따른다.
2. 개인 귀속 참조가 있는 첨부는 개별 삭제 API 로 지우지 않는다. 당사자와 관리자 모두 같다. 묶음을 바꾸는 일은 각 업무의 수정 경로가 맡는다.
3. 열람은 그대로다. 메모·쪽지 당사자는 첨부를 계속 연다.
4. 삭제한 쪽지의 관계는 첨부 근거가 되지 않는다. 본문을 404 로 닫은 사람이 번호로 첨부를 여는 경로를 남기지 않는다. 쪽지 표의 등록자 축은 발신 사본을 지워도 남으므로 소유 판정에서 뺀다.

## 결과

- 지시가 달린 메모는 본문·삭제에 이어 첨부도 바꿀 수 없다. 지시 전 첨부 교체는 메모 수정이 맡는다.
- 지시 토큰의 묶음 비교는 그대로 둔다. 일반 경로로 묶음이 바뀌지 않아도, 다른 경로로 바뀌면 거부하는 방어선이다.
- 잘못 보낸 쪽지의 첨부를 지우는 경로는 없다. 쪽지를 지우면 자기 사본의 접근만 닫힌다.
- 기존 시험이 고정한 "업로더는 참조와 무관하게 연다"와 "개인 당사자는 지운다"는 이 결정으로 바뀐 동작이다.

## 대안

- 메모는 지시가 달렸을 때만 막는 안: 첨부 판정 SQL 이 메모의 지시 컬럼까지 읽어야 한다. 참조원 하나의 SQL 오류는 모든 첨부를 거부하므로 판정 SQL 을 늘리는 쪽이 위험하고, 지시 전 삭제를 쓰는 화면도 없다.
- 첨부 재사용 전역 금지: 업무 간 공존을 전제한 CMS 재사용을 깨고, 연결은 원 업로더만 할 수 있어 피해가 본인 파일에 그친다. 택하지 않는다(DEC-OPS-394).
