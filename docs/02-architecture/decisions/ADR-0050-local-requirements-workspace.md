# ADR-0050 — 요구사항 분석부터 검수까지의 로컬 작업공간

- 상태: Accepted
- 결정일: 2026-11-04
- 승인: 사용자가 요구사항 UI 시안을 검토한 뒤 “화면시안은 잘만들어진것 같아 작업을 진행하자”라고 구현을 승인했다. 구현 검토는 Gemini 아르곤 high, Claude Opus 5.5 xhigh 순서로 진행한다.
- 관련: DEC-OPS-382·399의 외부 작업공간과 4층 상태 분리, [ADR-0018](ADR-0018-governance-review-lifecycle-and-adoption.md)의 기술 검증·기관 승인 분리.
- 후속: 입력·OCR·AI 자동 해석과 상세화는 [ADR-0051](ADR-0051-ai-first-requirements-workflow.md)이 대체한다. 아래 내용은 최초 구현 경계를 기록한다.

## 배경

고객 자료를 수집하고 원문 조항·요구사항·에픽·스토리·인수조건·추적 연결을 상세화하는 CLI가 있다. 비개발자가 명령과 JSON을 직접 편집하지 않고 분석·검토·개발 인계·인수 근거·감리 지적을 이어서 다룰 화면이 필요하다. 승인된 시안의 합성 성공은 실제 저장이나 기관 인수를 증명하지 않는다.

## 결정

1. Node 22 독립 실행기와 로컬 정적 UI를 제공한다. 온라인 앱의 메뉴·인증·업무 DB를 바꾸지 않는다. 기존 CLI와 같은 스키마·검증·매칭·작업 패키지·CSV 함수를 사용하며 임의 shell 실행 API를 두지 않는다. 화면은 기존 시맨틱 토큰과 로컬 폰트를 재사용한다. 독립 도구에는 기존 로컬 작업공간처럼 정적 CSS를 사용하며 Next 앱에 대한 Tailwind·SSR 규칙을 변경하지 않는다.
2. 고객 자료는 모든 Git 작업 트리 밖의 실제 로컬 디렉터리에만 저장한다. `backlog.json`과 `context.snapshot.json`은 CLI 교환 정본이고 `requirements-ui.json`은 검토 당시 문맥·분석 기준선·인수 이력·감리 지적·다운로드 자료의 작은 참조를 보관한다. 단일 작성자 잠금·세 파일 해시 CAS·저널과 원자적 파일 교체를 사용한다. 큰 기준선·산출물·과거 인수 이력은 `records/`의 불변 파일로 보관하고 해시로 읽는다. 작업용 임시 사본도 작업공간 안의 `.scratch/`에 둔다. CLI도 같은 잠금을 예약하며 UI 실행 중의 CLI 쓰기는 거부한다. CLI 갱신 뒤 문맥 사본과 교환 파일의 차이는 숨기거나 자동 덮어쓰지 않고 UI에서 확인 후 갱신한다. 복구 파일과 현재 내용이 충돌하면 덮어쓰지 않는다. 백로그가 있는 전체 산출물 패키지도 Git 밖 새 디렉터리에만 만들며 기존 고객 디렉터리를 덮어쓰지 않는다. 브라우저 다운로드 위치는 사용자가 관리한다. 작업공간 폴더 전체를 기관 보관 정책에 따라 백업한다.
3. 실행기는 `127.0.0.1`에만 바인딩하고 정확한 Host·Origin·Sec-Fetch 및 요청 토큰을 검사한다. 매 실행의 비밀은 터미널 주소의 조각으로 전달하고 교환 후 주소에서 지운다. 재접속 쿠키에는 실행 비밀이나 API 토큰 대신 부트스트랩마다 발급한 무작위 조회 식별자만 넣고, 서버 메모리의 해시 인덱스로 세션을 찾는다([CodeQL 권고](https://codeql.github.com/codeql-query-help/javascript/js-clear-text-storage-of-sensitive-data/)). 조회 식별자도 재접속 권한을 주는 bearer 값이므로 쿠키 탈취 위험을 없앴다고 보지 않는다. Secure·HttpOnly·SameSite=Strict를 적용하고 종료 시 인덱스를 지운다. 정확한 `127.0.0.1` HTTP loopback에서 Chromium이 Secure 쿠키를 저장·재전송하는 동작과 실제 UI 재접속을 검증한다. 외부 도달성이나 TLS를 제공하는 실행기로 확장하지 않으며 온라인 인증 쿠키 정책도 유지한다. 고객 내용·실행 비밀·API 요청 토큰은 URL query·로그·브라우저 영속 저장에 넣지 않는다.
4. 기본 작업공간은 빈 백로그다. TXT·Markdown의 비식별 발췌를 직접 입력하거나 브라우저에서 읽어 조항으로 검토한다. 원본 파일의 해시는 참고 식별자이며 파일 진위 검증을 뜻하지 않는다. HWP·PDF·이미지 OCR 및 외부 AI 전송·자동 해석은 이 구현에 포함하지 않는다. 개인정보·비밀 패턴은 저장 전에 차단하며 패턴 검사가 비식별화를 보장한다고 주장하지 않는다.
5. 초안의 구조 유효성, 분석 기준선 준비, 개발 준비를 분리한다. 분석 기준선은 조항 처분·업무 범위·질문·측정 기준·현재 내용 검토를 묶고, 검토 당시 원장 digest는 출처 정보로 남긴다. 개별 요구사항 검토는 그 요구사항과 실제로 연결된 조항에만 결속한다. 에픽·스토리 상세화와 무관한 원장 변경은 업무 분석 기준선을 철회하지 않는다. 문맥이 바뀌면 차이를 확인하고 갱신하지만 해당 업무 요구사항이 같으면 전 요구사항을 재승인하지 않는다. 개발 패키지는 현재 업무 기준선, 확인한 문맥, 실행 가능한 작업·의존성, 결정 카드, Green/Red 인수조건과 추적 근거를 확인한 뒤 만든다. 매칭 점수는 사람이 판단할 후보이며 에픽·스토리를 자동 확정하거나 코드를 자동 구현하지 않는다.
6. 인수 판정은 실제 검증일·담당 역할·대상 빌드(`uatBuildRef`)·근거 참조를 기록하거나 검수 CSV를 검증해 가져온다. 인수 해시 v3는 인수조건·연결된 요구사항과 원문·작업 결정·AC 집합·관련 추적, 해당 요구사항의 후보 모듈과 추적 대상의 현재 정보에 결속한다(`contextBindings`). 전체 원장 digest만 달라졌다는 이유로 무관한 인수를 지우지 않는다. 관련 의미가 바뀌면 영향받은 현재 판정만 재검토 상태로 돌리고 이력은 보존한다. CLI 문맥 갱신도 같은 규칙을 쓴다. 변경 없는 CSV 행을 다른 빌드의 새 검수로 기록하지 않고, 실제 판정·근거·빌드가 바뀐 행에만 이력을 더한다. CSV의 누락 행을 삭제로 해석하지 않는다. 기록은 공식 결재·전자서명을 대신하지 않는다.
7. 생성 자료는 입력 버전·내용 해시를 가진 검토 자료다. 감리 지적의 조치 완료는 근거를 요구한다. 도구의 제출 준비 표시와 실제 기관 인수·운영 전환 승인은 별개다. 운영 DB·배포·권한 변경과 실제 자료의 외부 전송은 기존 승인 경계를 따른다.

## 검증과 한계

스토어는 실제 자식 프로세스 중단·재시작, 다중 작성자·오래된 revision·외부 수정·연결 경로·Git 내부 저장 거부를 검증한다. HTTP는 세션·교차 출처·Host 재바인딩·크기·경로 거부를 검증한다. 화면은 실제 HTTP·파일 저장 경로에서 입력·재접속·초안 보존·XSS 비실행·반응형과 대표 접근성 상태를 확인한다. 자동 접근성 검사는 모든 보조기술과 기관 업무 인수를 보장하지 않는다. Windows의 CLI 잠금 검증은 `O_NOFOLLOW`가 없어 링크 대상이 먼저 열릴 수 있으나 파일 형식·경로 동일성을 검사하기 전에는 내용을 읽지 않는다. 링크 열기 자체의 OS 부작용을 격리한다고 주장하지 않는다. 파일 권한은 OS 보안 정책에 의존하며 로컬 관리자나 같은 계정의 악성 프로그램을 방어하는 격리 경계는 아니다.

사용법과 현재 지원 범위는 [실행 안내](../../03-guides/requirements-workspace-guide.md)에 둔다.
