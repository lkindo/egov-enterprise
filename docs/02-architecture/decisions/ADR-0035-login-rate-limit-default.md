# ADR-0035 — 로그인 요청 제한의 템플릿 기본값을 낮춘다

- 상태: Accepted
- 결정일: 2026-10-19
- 승인: 사용자가 2026-10-19 품질 평가의 우선 개선 과제를 "모두 완료할 때까지" 진행하라고 지시했다(과제 4, 기본 요청 제한).
- 부분 대체: [ADR-0019](ADR-0019-client-ip-trust-boundary.md) 결정 6의 "기본값은 종전 동작을 그대로 옮긴다(로그인 2,000)"와 "한도를 낮추는 것은 거절 로그를 관측한 뒤다". 한도를 설정 속성·환경변수로 받고 로그인 버킷을 따로 두는 결정은 그대로다.

## 결정과 이유

로그인 버킷의 기본값을 IP당 분당 30으로 낮춘다. 전체 버킷(분당 10,000)은 그대로 둔다. E2E 프로파일은 같은 주소에서 많은 로그인을 만들므로 종전 값으로 덮어쓴다. 운영은 `RATE_LIMIT_LOGIN_REQUESTS_PER_MINUTE` 로 계속 조정한다.

종전 기본값 2,000은 계정을 돌아가며 비밀번호를 대입하는 공격을 사실상 막지 못했다. 계정별 잠금은 한 계정만 지킨다. 30은 사용자별 IP가 들어오는 운영 형상(ADR-0019 edge)에서 한 사람에게 충분하고, 대입 속도를 크게 줄인다. 템플릿을 받아 쓰는 기관이 처음부터 안전한 쪽에서 출발하도록, 관측 뒤 낮추던 순서를 바꾼다.

## 경계

edge 없이 Next 한 주소로 요청이 모이는 형상(기본 compose)에서는 30이 스택 전체의 로그인 상한이 된다. 여러 사용자가 한 NAT 주소를 쓰는 기관도 같다. 이런 형상은 환경변수로 한도를 올리고, 운영 배포에서 `[RATE-LIMIT]` 거절을 관측해 조정한다. 버킷은 인스턴스 메모리라 여러 인스턴스의 합산은 하지 않는다.
