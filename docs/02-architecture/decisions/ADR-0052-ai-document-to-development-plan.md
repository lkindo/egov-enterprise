# ADR-0052 — AI 원본 판독에서 개발 작업계획까지

- 상태: Accepted
- 결정일: 2026-11-06
- 승인: 사용자는 “전과정을 ai가 진행했으면 좋겠어”, 범위는 “원본 판독 → 요구사항 → 에픽·스토리·개발 작업계획까지”로 확인했다. 이어 “각단계에서 어떤 프롬프트가 여러상황에 맞춰 최고의 효율을 낼 수 있을지 만들어주고 제대로 적용해줘”, “문서는 어떤 형태도 올수 있음을 숙지하고 작업을 진행했으면해”라고 요청했다.
- 대체 범위: [ADR-0051](ADR-0051-ai-first-requirements-workflow.md) 결정 1·2·6·7의 기본 판독 방식, 중간 확정 순서, 시각 자료 경로. 기존 로컬 추출·분리 분석은 보완 경로로 유지한다. 저장·인가·기관 인수의 경계는 유지한다.
- 후속 결정: 결정 1의 기본 화면 흐름은 [ADR-0055](ADR-0055-requirements-item-store.md)가 대체한다. 원본 판독(결정 2~4)은 그대로 쓴다.

## 결정

1. 기본 UI는 **AI 원본 판독 → 문서 통합 → 요구사항 → 요구사항 품질 검토 → 에픽·스토리·인수조건 → 계획 품질 검토 → 개발 작업계획 초안 → 사람의 최종 확인**을 이어서 수행한다. 실제 정책 결정이나 판독 불확실성은 질문으로 중단한다. 초안 계산을 위해 사람의 검토·기준선·인수 기록을 만들지 않는다. 최종 확인 때 요구사항과 계획을 함께 검증해 기준선·작업 패키지를 원자적으로 저장한다. 범위 변경·기존 계획 제외에는 종전 항목별 확인을 유지한다.
2. 입력을 정해진 서식으로 제한하지 않는다. AI가 문서 역할과 혼합 구성을 판단하고 단계·자료 유형·시각/표 구조·기존 결정에 맞는 프롬프트를 사용한다. 파서는 디코딩·렌더링을 담당하고 업무 해석은 AI가 수행한다. PDF·이미지는 로컬 OCR 성공 여부와 무관하게 페이지 이미지로 AI가 판독한다. 지원되지 않는 바이너리·보호·손상 파일을 읽었다고 표시하지 않는다. 안전하게 수용한 실패 원본은 보존하고 변환·재등록 경로를 알린다.
3. 네이티브 원문, AI 이미지 전사, 글자 없는 도형의 AI 시각 해석을 구별한다. 원본 해시·페이지/시트/구간·판독 불확실성·변환 누락을 보관한다. 판독 누락은 모델이 문제없다고 답해도 애플리케이션이 확인 질문으로 남긴다. 시각 전사에 대한 문자열 검증은 원본 이미지와 독립적인 의미 검증을 보장하지 않는다.
4. 원본·지시 버전·모델·분류·유형·현재 근거 본문이 같을 때 판독을 재사용한다. 사람이 보정·처분·근거 연결한 기존 조항과 사유는 AI 재판독으로 교체하지 않는다. 구형 자료의 변경 이력을 검증할 수 없으면 기존 조항을 보존하고 새 AI 근거를 별도로 추가한다. 연결 없는 이전 판독을 갱신할 때도 변경 전 사본을 보존한다. 처리 중 사람의 변경과 동의 범위 밖 자료 추가를 감지하면 전송·반영을 중단한다.
5. 완료 단계와 분석 묶음은 입력·지시 버전·상위 결과의 해시로 묶어 검증한 뒤, 명시적으로 새 실행에 동의할 때 재사용한다. 실행기 재시작은 자동 전송을 시작하지 않는다. 무효하거나 손상된 기록은 반영할 수 없다. 중간 초안은 확정 요구사항을 수정하지 않는다.
6. 단계별 프롬프트 버전·해시와 실제 사용 지시문을 UI에서 확인할 수 있게 한다. 문서·모델 출력은 비신뢰 데이터이며 명령 실행·도구·MCP를 허용하지 않는다. 원본 전송 전 자료 목록·비식별 확인·서비스 전송·복수 호출 비용에 동의한다. CLI는 오프라인 AI가 아니다. 지원 형식과 유한한 처리 한도의 정본은 [실행 안내](../../03-guides/requirements-workspace-guide.md)다.

## 결과와 검증 경계

반복 판독과 중간 수동 확정을 줄이고 문서 해석부터 개발 인계 초안까지 연결한다. AI의 품질 검토는 별도 호출이며 독립 공급자의 외부 감리나 사람의 최종 승인이 아니다. 자동 코드 개발·배포·실제 시험·기관 검수·공식 감리 수행은 이번 범위에 포함하지 않는다. 고객 데이터는 Git 밖 파일 작업공간에 저장하며 업무 DB에 연결하지 않는다.
