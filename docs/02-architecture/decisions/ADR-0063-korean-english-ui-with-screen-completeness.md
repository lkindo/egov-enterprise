# ADR-0063 — 프런트 UI 를 한국어·영어로 제공하되 화면 단위 완결성으로 단계 도입한다

- 상태: Accepted
- 결정일: 2026-11-26
- 승인: 2026-11-25 사용자가 품질 평가 개선 과제의 결정 충돌(ADR-0002 한국어 단일 언어 ↔ 다국어 개선 과제) 질문에 "다국어만 진행"을 골랐다([DEC-OPS-432](../../archived/operational-decisions-history.md#dec-ops-432) ⑤).
- 대체: [ADR-0002](ADR-0002-korean-first-frontend.md) 의 "프런트 UI 의 지원 언어는 한국어 하나다·`html[lang]` 을 `ko` 로 고정한다·`next-intl` 과 프런트 카탈로그를 제거한다" 부분. ADR-0002 의 백엔드 ko/en MessageSource·`Accept-Language` 오류 응답 계약과 "부분 번역을 다국어 지원으로 오인시키지 않는다"는 결정 요인은 유지한다.
- 관련: [화면 번역 원장](../../../frontend/src/i18n/surfaces.ts), [카탈로그](../../../frontend/messages/), [완결성 계약](../../../frontend/src/__tests__/i18n-catalog-contract.test.ts), [렌더링 시험](../../../frontend/src/i18n/__tests__/i18n-rendering.test.tsx), [화면 용어 원장](../../../config/frontend-visible-terms.json)

## 맥락

ADR-0002 는 로그인 오류 2개·대시보드 문구 2개만 번역된 반쪽 `next-intl` 을 걷고 프런트를 한국어 단일 언어로 선언했다. 그때 다국어 재도입 조건으로 "지원 로케일과 번역 책임자가 정해지고, 가시적 로케일 선택기, `html[lang]` 동기화, 화면 단위 카탈로그 완결성, 누락 키/전환 E2E 가 한 묶음으로 구현될 것"을 남겼다.

2026-11-25 품질 평가의 개선 과제가 다국어(ko/en)를 다시 제안했고, 사용자가 ADR-0002 와의 충돌에서 다국어를 골랐다. 화면은 600개가 넘는 시험 파일이 한국어 문구로 단언하는 규모라, 한 번에 전 화면을 옮기면 검토할 수 없는 변경이 된다. 반대로 화면을 조금씩 옮기면 ADR-0002 가 막으려던 "한 화면 안의 언어 혼합"이 생긴다.

## 결정

1. **지원 로케일은 `ko`(기본·정본)와 `en` 이다.** 번역 책임자는 단독 운영 기간의 저장소 소유자다([DEC-OPS-013](../../archived/operational-decisions-history.md#dec-ops-013)) — 영문은 초벌(사람 또는 AI)을 소유자가 PR 리뷰에서 확인한다. 한국어 문구의 규범은 계속 화면 용어 원장이다.
2. **런타임은 `use-intl`(next-intl 의 런타임 코어)이고 i18n 라우팅을 쓰지 않는다.** 로케일은 쿠키(`NEXT_LOCALE`, 값은 `ko`·`en` 만)로 정하고 없거나 모르는 값이면 `ko` 다. URL·메뉴 경로·라우트는 바꾸지 않는다(ADR-0009·메뉴 DB 경로 유지). 루트 레이아웃이 `html[lang]` 과 카탈로그 공급자를 현재 로케일로 그린다. `next-intl` 본체는 라우팅·미들웨어·문구 추출 도구를 위한 네이티브 의존성(`@swc/core`·`@parcel/watcher`)을 함께 들이는데, 이 결정은 그 기능을 쓰지 않으므로 같은 API 의 코어만 쓴다.
3. **보이는 로케일 선택기**를 머리글과 로그인 화면에 둔다. 바꾸면 쿠키를 쓰고 서버 렌더를 다시 받는다.
4. **화면 단위 완결성.** 번역을 마친 화면만 [화면 번역 원장](../../../frontend/src/i18n/surfaces.ts)에 그 경로와 고정 문구 파일로 적는다. 원장에 적힌 화면은 영어 로케일에서 모든 고정 문구(검증 안내·오류·공용 부품 포함)를 카탈로그에서 그린다. 원장에 없는 화면은 영어 로케일에서도 틀 전체(머리글·사이드바·본문·바닥글)를 `lang="ko"` 영역과 한국어 카탈로그로 다시 감싸 그리고(WCAG 3.1.2 부분 언어 — 그 안의 공용 부품도 한국어라 언어가 섞이지 않는다), 영역 밖 맨 위에 "This page is available in Korean only." 를 한 줄 보인다.
5. **완결성 게이트.** ① `ko`·`en` 카탈로그의 키 집합이 같고 빈 문구가 없으며 영어 카탈로그에 한글 문장이 없다(언어 이름 제외). ② 원장에 적힌 파일의 주석·정규식 밖 문자열·JSX 글자에 한글이 남지 않는다. ③ 스키마가 적은 카탈로그 키(`catalogKey(...)`)가 모두 있다. ④ 개발·시험 렌더에서 누락 키는 예외다. ⑤ E2E 가 선택기 전환 → `html[lang]`·문구·검증 안내 변경 → 새로고침 유지, 원장 밖 화면의 `lang="ko"` 영역과 안내를 본다. 검증 메시지는 스키마에 문장 대신 `$t:네임스페이스.키` 를 적고 수동 폼 검증이 현재 로케일로 바꾼다 — 한국어 문장을 적은 기존 스키마는 그대로 동작한다.
6. **데이터는 번역하지 않는다.** 메뉴·게시판·코드 이름처럼 DB 에서 오는 값은 영어 로케일에서도 원문 그대로다 — 데이터 번역은 별도 제품 결정이다.
7. **API 오류 문구는 같은 로케일을 따른다.** 브라우저의 API 요청에 `Accept-Language` 를 현재 로케일로 실어 ADR-0002 가 유지한 ko/en MessageSource 를 쓴다. 서버 렌더의 요청은 1단계에서 기본(한국어)이다.
8. **1단계 범위는 로그인 화면이다** — 로케일 선택기(머리글·로그인), 로그인 카드·검증 안내·로그인 오류·추가 인증(MFA)·세션 종료 안내, 그 화면이 쓰는 공용 폼 부품(필수 표시·오류 요약)과 틀의 고정 문구(본문 바로가기·불러오는 중), 미번역 화면 안내. 머리글·사이드바·업무 화면·오류 화면은 이후 화면 단위 PR 로 원장에 더한다. 영어 로케일의 로그인 뒤 화면은 지금은 모두 "한국어로만 제공" 이다.

## 결과

- 장점: 사용자가 영어를 고를 수 있고, 어느 화면이 번역됐는지가 원장과 화면에 드러난다. 미번역 화면도 접근성 메타데이터가 사실과 같다.
- 비용: 화면을 번역할 때마다 카탈로그 두 벌과 원장을 함께 고친다. 화면 시험은 시험 설정이 한국어 카탈로그로 번역 함수를 대신하고, 영어를 보는 시험은 실제 런타임으로 감싼다.
- 재검토 조건: 지원 로케일을 늘리거나, 데이터 번역을 시작하거나, URL 로케일 접두사가 필요해지면 새 ADR 로 다룬다.
