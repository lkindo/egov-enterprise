# ADR-0063 — 프런트 UI 를 한국어·영어로 제공하되 화면 단위 완결성으로 단계 도입한다

- 상태: Accepted
- 결정일: 2026-11-26
- 승인: 2026-11-25 사용자가 품질 평가 개선 과제의 결정 충돌(ADR-0002 한국어 단일 언어 ↔ 다국어 개선 과제) 질문에 "다국어만 진행"을 골랐다([DEC-OPS-432](../../archived/operational-decisions-history.md#dec-ops-432) ⑤).
- 대체: [ADR-0002](ADR-0002-korean-first-frontend.md) 의 "프런트 UI 의 지원 언어는 한국어 하나다·`html[lang]` 을 `ko` 로 고정한다·`next-intl` 과 프런트 카탈로그를 제거한다" 부분. ADR-0002 의 백엔드 ko/en MessageSource·`Accept-Language` 오류 응답 계약과 "부분 번역을 다국어 지원으로 오인시키지 않는다"는 결정 요인은 유지한다.
- 관련: [화면 번역 원장](../../../frontend/src/i18n/surfaces.ts), [로케일 경계](../../../frontend/src/i18n/LocaleBoundary.tsx), [카탈로그](../../../frontend/messages/), [완결성 계약](../../../frontend/src/__tests__/i18n-catalog-contract.test.ts), [렌더링 시험](../../../frontend/src/i18n/__tests__/i18n-rendering.test.tsx), [영어 로그인 렌더 증거](../../../frontend/src/app/login/__tests__/login-english.test.tsx), [화면 용어 원장](../../../config/frontend-visible-terms.json)

## 맥락

ADR-0002 는 로그인 오류 2개·대시보드 문구 2개만 번역된 반쪽 `next-intl` 을 걷고 프런트를 한국어 단일 언어로 선언했다. 그때 다국어 재도입 조건으로 "지원 로케일과 번역 책임자가 정해지고, 가시적 로케일 선택기, `html[lang]` 동기화, 화면 단위 카탈로그 완결성, 누락 키/전환 E2E 가 한 묶음으로 구현될 것"을 남겼다.

2026-11-25 품질 평가의 개선 과제가 다국어(ko/en)를 다시 제안했고, 사용자가 ADR-0002 와의 충돌에서 다국어를 골랐다. 화면은 600개가 넘는 시험 파일이 한국어 문구로 단언하는 규모라, 한 번에 전 화면을 옮기면 검토할 수 없는 변경이 된다. 반대로 화면을 조금씩 옮기면 ADR-0002 가 막으려던 "한 화면 안의 언어 혼합"이 생긴다.

## 결정

1. **지원 로케일은 `ko`(기본·정본)와 `en` 이다.** 번역 책임자는 단독 운영 기간의 저장소 소유자다([DEC-OPS-013](../../archived/operational-decisions-history.md#dec-ops-013)) — 영문은 초벌(사람 또는 AI)을 소유자가 PR 리뷰에서 확인한다. 한국어 문구의 규범은 계속 화면 용어 원장이다.
2. **런타임은 `use-intl`(next-intl 의 런타임 코어)이고 i18n 라우팅을 쓰지 않는다.** 로케일은 쿠키(`NEXT_LOCALE`, 값은 `ko`·`en` 만)로 정하고 없거나 모르는 값이면 `ko` 다. URL·메뉴 경로·라우트는 바꾸지 않는다(ADR-0009·메뉴 DB 경로 유지). 루트 레이아웃의 **로케일 경계**가 화면(경로)마다 실제로 그리는 로케일을 정해 `html[lang]`·카탈로그 공급자·API 언어를 함께 맞춘다 — 사용자가 고른 로케일이 영어여도 번역을 마치지 않은 화면(경로를 모를 때 포함)은 한국어다. 서버는 proxy 가 문서 요청마다 덮어 싣는 요청 경로 헤더로 첫 렌더를 그 언어로 그리고, 화면을 옮기면 경계가 맞춘다. 카탈로그 값은 서버가 경계의 props(RSC 데이터)로 넘긴다 — 고른 로케일의 것과, 고른 로케일이 영어면 미번역 화면용 한국어 것까지 두 벌이다. 클라이언트 JS 번들에는 카탈로그 JSON 을 싣지 않는다(키 타입만 읽는다). `next-intl` 본체는 라우팅·미들웨어·문구 추출 도구를 위한 네이티브 의존성(`@swc/core`·`@parcel/watcher`)을 함께 들이는데, 이 결정은 그 기능을 쓰지 않으므로 같은 API 의 코어만 쓴다.
3. **보이는 로케일 선택기**를 머리글(좁은 화면은 사이드바 서랍)과 로그인 화면에 둔다. 바꾸면 쿠키를 쓰고 서버 렌더를 다시 받는다 — 트리 모양이 같아 작성 중인 입력과 보이는 검증 오류가 남는다. 선택기의 눌린 단추는 고른 로케일이다(번역을 마치지 않은 화면에서도 영어가 눌려 있고 한국어를 누르면 돌아간다).
4. **화면 단위 완결성.** 번역을 마친 화면만 [화면 번역 원장](../../../frontend/src/i18n/surfaces.ts)에 그 경로와 고정 문구 파일로 적는다. 원장에 적힌 화면은 영어 로케일에서 모든 고정 문구(검증 안내·오류·공용 부품 포함)를 카탈로그에서 그린다. 원장에 없는 화면은 영어 로케일에서도 한국어 카탈로그로 그리고 문서 언어(`html[lang]`)를 `ko` 로 둔다 — 본문 밖에 그려지는 대화상자·토스트(포털)와 비밀번호 변경 관문까지 같은 언어로 읽힌다. 번역을 마친 경로 위에 아직 번역하지 않은 화면이 통째로 대신 그려지면(임시 비밀번호 변경 관문) 그 화면이 스스로 한국어 전용을 선언해(`KoreanOnlyScreen`) 경로와 무관하게 같은 규칙을 따른다. 루트 레이아웃은 문서를 내보내기 전에 인증 조회를 기다리지 않도록 첫 문서의 `html[lang]` 을 경로로만 정한다 — 그런 화면은 본문에 `lang="ko"` 를 달고 하이드레이션 뒤 경계가 문서 언어를 맞춘다. 탭 제목은 경로의 메타데이터가 정한다(클라이언트가 덮어쓰면 Next 의 제목 갱신과 겨룬다) — 관문이 남는 `/login` 은 메타데이터가 임시 비밀번호 사용자에게 관문의 한국어 제목을 낸다(메타데이터는 본문과 따로 흘려 보낸다). 맨 위에 고른 언어로 쓴 안내("This page is available in Korean only.", `lang="en"` 인 보조 랜드마크)를 한 줄 둔다. 원장의 경로는 정확히 그 경로만이다 — 아래 경로는 따로 번역을 마치고 적을 때까지 한국어 화면이다.
5. **완결성 게이트.** ① `ko`·`en` 카탈로그의 키 집합이 같고 빈 문구가 없으며 영어 카탈로그에 한글 문장이 없다(언어 이름 제외). ② 원장에 적힌 파일의 주석·정규식 밖 문자열·JSX 글자에 한글이 남지 않고, 그 파일이 한글 문구를 가진 다른 모듈에서 가져오는 이름은 화면에 닿지 않는 것으로 확인한 허용 목록 안이다. ③ 번역 함수와 `catalogKey(...)` 의 키는 카탈로그로 타입이 좁혀져 오타를 타입 검사가 막는다. ④ 개발·시험 렌더(시험 설정의 한국어 대역 포함)에서 누락 키·빠진 ICU 인자·메시지 문법 오류는 같은 기준으로 예외다(인자 값의 종류는 검사하지 않는다 — 로그아웃 안내처럼 저장해 두는 인자는 타입과 읽기 검사로 지킨다). 번역 화면이 글자로 그리는 사이트 정체는 `contentLang` 표지를 단다(한글 판정은 완성형 음절과 자모). 한글 문구 모듈(TS·JS)을 재수출·네임스페이스 멤버로 거쳐 가져와도 허용 목록 검사가 따라간다. ⑤ 렌더 시험과 E2E 가 영어 로그인 화면 본문에 `lang="ko"` 표지 없는 한글(글자·접근 이름·placeholder)이 없음을, E2E 가 선택기 전환 → `html[lang]`·문구·이미 보이는 검증 오류의 재번역 → 새로고침 유지, 원장 밖 화면의 문서 언어·안내·입력 보존·한국어 복귀를 본다. 검증 메시지는 스키마에 문장 대신 `$t:네임스페이스.키` 를 적고 수동 폼 검증이 원인(이슈·키)을 저장해 그릴 때 그 순간의 로케일로 바꾼다 — 한국어 문장을 적은 기존 스키마·전역 오류 맵은 한국어로 그리는 화면에서만 그대로 쓰고, 영어로 그리는 화면에서는 항목 이름과 함께 일반 안내로 바꾼다.
6. **데이터와 고유 이름은 번역하지 않는다.** 메뉴·게시판·코드 이름처럼 DB 에서 오는 값은 영어 로케일에서도 원문 그대로다 — 데이터 번역은 별도 제품 결정이다. 사이트 정체(`site-identity` 의 기관·제품 이름·저작권 표기)와 한국어로만 제공하는 화면으로 가는 링크 이름도 번역하지 않고, 한글이 들었으면 그 요소에 `lang="ko"` 를 단다(문서 제목은 요소 언어를 달 수 없어 목적 부분만 번역하고 사이트 이름 접미사는 그대로다). 아직 번역하지 않은 오류·찾을 수 없음 화면도 루트에 `lang="ko"` 를 단다.
7. **API 오류 문구는 그 화면의 로케일을 따른다.** 브라우저의 API 요청(인증·추가 인증 BFF 포함 — BFF 는 `ko`·`en` 만 백엔드로 넘긴다)에 `Accept-Language` 를 지금 화면의 로케일로 실어 — 쿠키·주소가 아니라 그 탭이 그린 로케일을 기준으로 해 다른 탭의 선택, 다시 그리기를 기다리는 동안, 주소가 화면보다 먼저 바뀐 순간에도 화면과 어긋나지 않는다 — ADR-0002 가 유지한 ko/en MessageSource 를 쓴다. 번역을 마치지 않은 화면의 요청은 한국어다. 서버 문구가 없는 전송 실패(연결·시간 초과)의 전역 알림은 실패 종류를 받아 지금 화면의 로케일 문구로 그린다(이미 떠 있는 알림은 언어를 바꿔도 다시 쓰지 않는다 — 몇 초 뒤 사라지는 일시 알림이라 받아들인 경계다). 서버 렌더의 요청은 1단계에서 기본(한국어)이다.
8. **1단계 범위는 로그인 화면이다** — 로케일 선택기(머리글·서랍·로그인), 로그인 카드·검증 안내·로그인 오류·추가 인증(MFA)·세션 종료 안내(종전 형식으로 남은 안내도 옮겨 보인다), 문서 제목, 그 화면이 쓰는 공용 폼 부품(필수 표시·오류 요약)과 틀의 고정 문구(본문 바로가기·불러오는 중·바닥글), 미번역 화면 안내. 머리글·사이드바·업무 화면·오류 화면은 이후 화면 단위 PR 로 원장에 더한다. 영어 로케일의 로그인 뒤 화면은 지금은 모두 "한국어로만 제공" 이다.

## 결과

- 장점: 사용자가 영어를 고를 수 있고, 어느 화면이 번역됐는지가 원장과 화면에 드러난다. 미번역 화면도 접근성 메타데이터가 사실과 같다.
- 비용: 화면을 번역할 때마다 카탈로그 두 벌과 원장을 함께 고친다. 화면 시험은 시험 설정이 한국어 카탈로그로 번역 함수를 대신하고, 영어를 보는 시험은 실제 런타임으로 감싼다.
- 재검토 조건: 지원 로케일을 늘리거나, 데이터 번역을 시작하거나, URL 로케일 접두사가 필요해지면 새 ADR 로 다룬다.
