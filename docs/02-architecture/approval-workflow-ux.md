# 다단계 결재와 업무 UX

2026-09-16 사용자 요청에 따른 구현 범위와 설계 근거다. 대상은 문서를 올리는 기안자와 결재·합의를 처리하는 참여자다. 기존 구현은 결재자 한 명, 제목·본문 없는 업무 구분 중심 기안이었으며, 여러 단계의 순서·처리자별 결과를 저장하지 못했다.

## 자료와 적용

공식 자료를 2026-09-16 확인했다. 사용자 과업 시간·오류율의 개선은 아직 측정하지 않았으므로 아래 선택은 검증할 설계 가설이다.

## 업무 규칙

- 결재선은 순서가 있는 최대 10단계이며, 단계당 1~10명·전체 50명까지 지정한다. 이 상한은 유계 입력·조회 비용을 위한 제품 제한이며 KRDS의 표시 권장 수를 업무 제한으로 해석한 것이 아니다.
- 단계는 결재 또는 합의다. 두 유형 모두 지정된 전원의 승인이 필요하다. 앞 단계 완료 전에는 다음 단계가 처리할 수 없다. 한 사람이 같은 문서 결재선에 중복되거나 자기 문서를 결재할 수 없다.
- 대기 목록과 대시보드 건수는 현재 차수의 활성 단계에서 본인이 아직 처리하지 않은 문서만 센다. 개인의 승인 완료와 전체 문서의 완료를 구분한다.
- 한 사람이 반려하면 그 차수는 종료되고 미완료 결재는 중단된다. 반려 사유는 필수이고 승인 의견은 선택이다.
- 기안자는 진행 중 문서를 회수할 수 있다. 완료된 결정과 문서는 삭제하지 않는다. 반려·회수된 문서는 내용을 수정하고 결재선을 다시 확인하여 새 차수로 재상신한다.
- 이전 차수의 내용·결재선·결과는 보존한다. 기안자는 모든 차수를, 결재자는 자신이 참여한 차수만 열람한다. 과거 참여자에게 재상신 후 새 내용을 자동 공개하지 않는다.
- 서버가 처리 가능 여부를 결정한다. 문서 잠금과 버전을 함께 사용하여 동시 승인·회수·재상신의 충돌을 제어한다. 실패했을 때 의견·작성 입력을 보존하고 최신 상태를 다시 확인하도록 안내한다.

조건에 따른 자동 분기, 대결·위임, 정족수·최초 응답 규칙은 이 범위에 포함하지 않는다. 특히 최초 응답은 최초 **승인 또는 반려**이며 ‘누구든 한 명 승인’과 같은 규칙이 아니다.

## 저장 구조와 연관 기능

기존 `tb_ifml_atrz_info`의 문서 식별자와 단일 결재 입력을 유지한다. `V2_101__expand_approval_workflow.sql`은 제목·본문·현재 차수를 추가하고, `tb_ifml_atrz_hstry`에 차수별 내용을, `tb_ifml_atrz_dtl`에 참여자별 결정과 의견을 저장한다. 기존 문서는 차수 1의 단일 결재선으로 옮긴다. 새 컬럼명·길이는 로컬 PostgreSQL의 표준 메타와 물리 구조를 읽어 확인했다.

결재는 기존 `demo` 팩 소유를 유지한다. 두 테이블도 같은 팩에 속한다. 새 단계가 활성화되면 해당 참여자에게 앱 내 알림을 요청하고, 전체 승인·반려가 확정된 때만 최종 결과를 알린다. 알림은 트랜잭션 커밋 후 발행한다.

재사용 `core`·`collaboration` 프로필에는 결재 서비스·테이블이 없으므로 결재 업무 통합 테스트도 같은 범위에서 제거한다. 이 범위는 [프로필 원장](../../config/reusable-base-profiles.json)의 파일별 사유와 실제 제거 계획을 대조하는 계약으로 확인한다. 전체 `demo` 프로필에서는 테스트를 유지한다. 이전 DB를 새 구조로 옮기는 백필 테스트는 기존 역사적 마이그레이션 테스트 규칙을 따르며, 원본 저장소의 [스키마 검증 집합](../../config/governance/gates.json)에서는 두 테스트를 모두 실행한다.

격리 DB 생성 시 과거 권한 전환에 사용하는 검토 버전은 고정된 `V2_99`에서 읽는다. 상세 조회·재상신 API 추가로 현재 권한 카탈로그 버전이 달라져도 과거 전환의 검토 기준은 바뀌지 않는다. 기존 Contract의 변조 탐지·롤백 검사는 유지한다.

## 검증 기준

순차·병렬 전원 승인, 미래 단계의 처리 차단, 참여자별 열람, 회수·재상신 이력 보존, 동시 결정, 과거 단일 문서 백필을 서버 및 PostgreSQL 테스트로 확인한다. 화면은 단계 이동·순서 변경·처리 결과·입력 보존·회수·재상신을 컴포넌트와 브라우저 과업으로 확인한다. 자동 검사 통과를 실사용자 평가나 접근성 준수 인증으로 표현하지 않는다.

기존 BIGINT 전환 테스트는 키 변환을 검증하므로, 차수 백필과 실제 동시 결재는 각각 결재 전용 PostgreSQL 테스트로 추가했다. 실행 경로는 기존 `schemaValidationTest`를 사용한다.

2026-09-16 검증 결과:

- 결재 도메인·서비스·알림·대시보드 단위 테스트 86개 통과.
- 실제 PostgreSQL 결재 통합·기존 문서 백필 5개와 권한 전환 회귀 2개 통과.
- 기안·결재선·의견 보존·충돌 안내·이력 표시 컴포넌트 테스트, TypeScript 및 관련 lint 통과.
- 실제 계정으로 기안 → 순차 승인 → 합의 반려 → 수정·재상신 → 최종 승인 브라우저 과업 통과.
- 1366px 데스크톱과 390px 모바일 화면 확인. 가로 넘침 없음.

현재 차수는 본문에서 표시하고, 이전 차수 이력에는 그보다 오래된 차수만 표시한다. 과거 결재선에는 차수별 접근성 이름을 부여하며, 처리 시각은 공용 날짜 표기 함수를 사용한다.
