# 요구사항 작업공간 실행 안내

고객의 요구사항·회의록·관련 산출물을 등록하면 AI가 원문 근거를 가진 요구사항을 만들고, 사람이 쟁점을 결정한 뒤 에픽·스토리·인수조건으로 이어가는 로컬 UI다. 개발 작업 패키지와 검수·감리 자료까지 같은 작업공간에서 관리한다. 기존 [앞단 CLI 플레이북](design-to-deliverables-guide.md#7-요구사항-입구intake통합-전환cutover최종-종료closeout-연결)과 같은 검증기를 사용한다. 저장·인수 경계는 [ADR-0050](../02-architecture/decisions/ADR-0050-local-requirements-workspace.md), AI 흐름은 [ADR-0051](../02-architecture/decisions/ADR-0051-ai-first-requirements-workflow.md)이 정한다.

## 시작

Node 22 이상과 루트·frontend 의존성을 준비한다(`npm ci`, `pnpm -C frontend install --frozen-lockfile`). AI 실행에는 이 PC의 Claude CLI 설치·로그인과 `claude-opus-5-5` 사용 권한이 필요하다. 모델은 `xhigh`로 실행하며 CLI의 기존 인증·요금 조건이 적용된다. 고객 작업공간은 이 저장소뿐 아니라 다른 Git 작업 트리에도 속하면 안 된다.

```powershell
node tools/requirements-workspace/server.mjs --workspace D:\agency-workspaces\project-001
```

터미널에 표시된 `http://127.0.0.1:8792/#launch=...` 전체 주소를 브라우저에서 연다. 주소의 실행 비밀을 공유하거나 문서에 기록하지 않는다. 연결 후 조각은 제거되며 같은 브라우저의 새로고침은 세션 쿠키로 다시 연결한다. 서버를 재시작하면 새 터미널 주소로 연결한다. 포트가 사용 중이면 `--port 8793`을 지정한다. 종료는 Ctrl+C다.

브라우저 자동 검증은 Chromium 엔진(Chrome·Edge 계열)에서 수행한다. 다른 엔진에서 loopback의 Secure 쿠키가 차단돼 새로고침 뒤 연결이 복원되지 않으면, 터미널의 전체 실행 주소를 다시 열거나 Chromium 계열 브라우저를 사용한다. 쿠키 보안 속성을 끄는 방식으로 우회하지 않는다.

기본은 빈 프로젝트다. 실제 고객 자료 대신 예시를 자동 채우지 않는다. 프로젝트 이름·코드·기관·시작 구성을 먼저 입력한다.

## 화면을 따라 진행하기

1. **산출물 수집**: **산출물 파일 등록**에서 비식별 문서·이미지를 여러 개 선택하고 유형·분류를 정한다. 본문·이미지·문서 속성의 개인정보와 비밀을 제거했음을 확인한다. 원본은 Git 밖 작업공간에 보관하며 본문·조항 위치·SHA-256을 자동 등록한다. 필요하면 기존 자료 추가·편집 화면에서 보완한다.
2. **AI 요구사항 생성**: 등록 뒤 분석을 이어가도록 선택하거나 **AI 요구사항 생성**을 누른다. 본문만 또는 본문과 이미지·PDF를 선택하고 모델 서비스 전송에 동의한다. **CLI 연결은 오프라인 AI가 아니다.** 자료 분류가 기관 반출 허용을 대신하지 않는다. AI가 요구사항·정확한 원문 인용·조항별 처분·누락/충돌/결정 질문을 만든다. 형식·출처·식별자·관계를 검증하지 못한 결과는 반영하지 않는다.
3. **질문과 분석 기준선**: **답변하고 계속**에서 업무 범위·권한·측정 기준 등 중요한 질문에 답한다. 답변은 결정 근거로 남고 같은 자료 범위로 재분석한다. AI가 해결 방향이나 측정 기준을 누락하면 프로그램도 결정 질문으로 차단한다. 초안의 원문·포함/보류/제외·Fit-Gap을 검토한 뒤 **요구사항 확정하고 에픽 생성**으로 현재 내용을 확인한다. 업무 분석 기준선을 만들고 다음 AI 단계를 자동 실행한다. 확정 창의 자동 생성 선택을 해제하면 요구사항만 먼저 확정할 수 있다. 직접 내용을 바꾸면 해당 요구사항 검토와 분석 기준선을 다시 확정한 뒤 에픽 생성을 시작한다. 현재 요구사항이 같으면 무관한 원장 변화로 기준선을 철회하지 않는다.
4. **에픽·스토리**: AI가 포함 요구사항을 에픽 아래 스토리·구성·검증·기반 작업, 의존성, D-1~D-5 결정 카드, Green/Red 인수조건과 후보/계획/기존 추적으로 상세화한다. 재생성에는 기존 계획의 ID·문구를 전달하며 인수조건의 실제 검수 판정 필드는 보내지 않는다. 화면의 변경 전·후 목록을 비교하고 **에픽·스토리 반영**으로 확인한다. 기존 범위 변경과 작업·인수조건·추적 제외는 사유와 기존 판정을 보고 항목별로 확인해야 한다. 사유 없는 기존 작업 누락과 답변 없는 열린 질문을 거부한다. 변경 전 입력은 **생성 기록 다운로드**의 `inputBacklog`에 보관한다. 같은 의미의 유효한 검수 근거는 유지하며 영향받은 판정만 재검토한다. 에픽 단계 질문의 답변이 작업 계획만 보완한다면 해당 선택으로 기준선을 유지하고 상세화를 재실행한다. 업무 범위·권한·기준을 바꾸거나 영향이 불확실하면 요구사항 재분석·재확정을 선택한다. 생성된 계획은 개발 완료가 아니다.
5. **개발 인계**: 개발 준비의 보완 항목을 해결해 `TASK-PACKAGE.md`를 생성·다운로드한다. 에이전트나 개발자가 그 패키지를 받아 기존 SOP의 수직 슬라이스 개발을 수행한다. 화면의 패키지 생성이 코드를 구현하거나 테스트를 실행하지는 않는다. 프로젝트 구성 대조와 검토 CSV 왕복도 이 화면에서 한다.
6. **검수·감리**: 실제 시험 뒤 담당 역할·검증일·대상 빌드·근거 문서번호/해시로 인수 판정을 기록한다. 검수표 CSV를 내보내 검토하고 다시 가져올 수도 있다. 변경 없는 CSV 행은 새 빌드의 확인 기록으로 다시 만들지 않는다. 변경한 행에 이전 빌드가 기본값으로 남아 있으면 가져오기에서 지정한 새 빌드를 적용하며, 행에 이전과 다른 빌드를 직접 적으면 그 행의 값을 사용한다. 인수조건·요구사항·연결 원문·관련 작업 결정·대상 원장 정보가 바뀌면 영향받은 판정만 재검토 상태가 된다. 모듈의 화면·표 개수 같은 집계 변화는 인수를 지우지 않는다. 지적사항을 등록하고 근거를 붙여 조치 기록을 남긴다. 감리 보고서는 공식 승인·서명과 구분하는 초안이다.

## 파일 교환·복구

`backlog.json`과 `context.snapshot.json`은 기존 CLI와 같은 교환 파일이다. `requirements-ui.json`에는 기준선·원장 문맥·AI 작업/결정·파일 등록 이력·보관 파일의 해시 참조가 담긴다. 세 파일은 같은 저장 저널로 보호한다. 원본 파일은 분할 보관하며 큰 기준선·AI 입력/유효한 출력·산출물·오래된 검수 이력은 `records/`의 불변 파일로 보관하고 화면에서 내려받는다. 작업용 임시 사본도 `.scratch/`에만 만든다. 개별 교환/보관 파일의 8MiB 한도를 넘으면 원본을 보존하고 저장을 거부한다. 업무 DB에는 연결하지 않는다.

AI와 문서 판독은 비동기다. 새로고침해도 저장된 상태를 이어서 볼 수 있다. 진행 중 취소하면 해당 자식 프로세스만 종료하며 이미 등록 완료된 파일은 유지한다. 실행기를 재시작하면 실행 중 작업은 중단으로 표시하고 자동 재전송하지 않는다. 입력이 변경된 결과는 적용할 수 없으며 현재 자료로 다시 실행한다. 보관한 AI 결과가 손상되면 해당 제안의 반영을 막고 현재 프로젝트·원문을 보존한다. 원시 CLI 오류·미검증 결과는 로그나 고객 작업공간에 저장하지 않는다.

## 지원 자료와 판독 한계

| 형식 | 처리 |
|---|---|
| TXT·Markdown·HTML | UTF-8 또는 BOM 있는 UTF-16 본문. HTML은 스크립트·외부 리소스를 실행하지 않는다. |
| HWP/HWPX·DOCX·XLS/XLSX·PPTX | 로컬 파서로 본문·표·시트/페이지 위치를 추출한다. 구형 Word DOC는 사용자가 DOCX 사본으로 변환한 뒤 등록한다. |
| PDF | 본문 추출, 스캔은 로컬 OCR. 시각 자료 포함 선택 시 PDF 원본도 모델에 전달한다. |
| PNG·JPEG·WebP·TIFF | 로컬 OCR. 시각 자료 포함 선택 시 메타데이터를 제거한 축소 JPEG를 전달한다. 다중 페이지 이미지의 시각 전송은 지원하지 않는다. |

파일당 20MiB, 추출 본문 512KiB, 요청 JSON 768KiB, AI 시각 자료 합계 20MiB/100개 한도다. 문서 판독은 3분, AI 호출은 15분 제한이며 초과하면 실패 상태로 남긴다. 구조가 잘못된 초안은 원본과 위반 위치를 바탕으로 한 번만 자동 보정하며 추가 호출의 시간·요금이 발생할 수 있다. 민감정보·잘못된 형식은 보정 대상으로 재전송하지 않는다. 보정도 검증에 실패하면 반영하지 않는다. 암호·보호·손상 문서는 보호 해제한 비식별 사본을 사용한다. 읽을 수 있는 본문이 없으면 성공으로 등록하지 않는다. 모델 서비스의 페이지·이미지 제한으로도 거부될 수 있다.

OCR은 첫 실행 시 버전 고정 파서에 SHA-256이 등록된 공개 PP-OCRv5 모델을 내려받아 로컬에서 수행한다. 모델 다운로드에 문서 내용을 보내지 않는다. 기본 캐시는 `%USERPROFILE%\.cache\kordoc\models\ppocr`(다른 OS는 `~/.cache/kordoc/models/ppocr`)이며 작업별 `.scratch`와 별개다. 오프라인 환경에서는 모델 캐시를 미리 준비하고 `KORDOC_OFFLINE=1`로 실행한다. OCR·복잡한 표·수식·도형·레이아웃은 오독하거나 누락할 수 있으므로 원본과 대조한다. Office 내 비문자 도표는 별도 이미지/PDF로 등록한다. BMP는 PNG/JPEG 사본으로 변환한 뒤 등록한다. 시각 자료의 합계 한도·지원 조건을 넘으면 자료를 임의로 빼서 전송하지 않고 실패로 알리며, 파일을 나누거나 추출 본문만으로 실행할 수 있다. 개인정보 패턴은 완전한 비식별 검사가 아니며 이미지·주석·속성도 입력자가 확인한다.

UI가 열려 있는 동안 CLI와 다른 UI는 같은 작업공간에 쓸 수 없다. CLI로 작업할 때는 UI 실행기를 먼저 종료한다. CLI가 문맥을 갱신했다면 UI 재접속 시 차이를 확인하고 기준 정보를 명시적으로 갱신한다. CSV에서 기존 행을 빠뜨리면 가져오기가 거부되며, 누락 행은 삭제가 아니다. UI는 보관한 조항·요구사항의 삭제 기능을 제공하지 않으므로 보류·제외 처분으로 근거를 보존한다.

검수 CSV는 매번 최신 작업공간에서 다시 내보낸 것을 사용한다. 인수조건의 내용 해시는 검사하지만 검수 판정 자체의 버전은 비교하지 않으므로, 같은 인수조건의 예전 CSV를 가져오면 그 뒤의 판정·근거·빌드를 이전 값으로 바꿀 수 있다. 가져오기 전에 현재 판정과 대조한다. UI를 통한 과거 기록은 이력에 남으며, 이 한계는 [GAP-REQ-001](../04-operations/known-gaps-detail.md#ci-governance)에 기록한다.

작업공간 전체를 백업한다. 중단된 저장은 다음 시작 때 저널과 파일 해시가 맞는 경우에만 복구한다. 외부 수정·손상·알 수 없는 잠금은 자동 덮어쓰지 않는다. 이때 원본·저널·잠금을 보존하고 별도 복사본에서 비교한다. 잠금 파일을 무조건 지우거나 `backlog.json` 한 장으로 기준선 이력을 덮어쓰지 않는다. 화면의 충돌 오류도 작성 중 입력을 지우지 않는다.

전체 저장소 산출물 패키지는 UI 종료 후 기존 명령을 사용한다. 현재 원장·코드가 깨끗한 상태에서 실행하며 원문과 UAT 해시 검증은 동일하게 적용된다.

```powershell
node scripts/export-deliverables-workspace.mjs uat-import --workspace D:\agency-workspaces\project-001 --build-ref BUILD-001
node scripts/export-deliverables.mjs --backlog D:\agency-workspaces\project-001\backlog.json
```

백로그를 포함한 패키지 기본 위치는 `<작업공간>/deliverables/<커밋>`이다. `--out`은 Git 밖의 아직 없는 절대 디렉터리로 지정하며 기존 고객 디렉터리를 덮어쓰지 않는다. 브라우저의 내려받기 파일은 사용자가 정한 다운로드 위치에 저장된다. CLI는 현재 AC의 검수 기록을 보존하고, UI의 누적 이력은 UI를 통한 기록/가져오기를 사용한다.

이전 본문 전용 또는 v2 인수 해시를 가진 기존 백로그는 UI 실행 전 `uat-export --workspace <경로>`로 새 해시와 `pending` 검수표를 만들고 실제 근거·`uatBuildRef`를 확인하여 재검수한다. 과거 기준선 보관 파일을 현재 규칙에 맞춘다고 손으로 바꾸지 않는다. 남은 CLI 잠금은 먼저 해당 PID가 실제로 종료됐는지 확인하고 실행기를 다시 연다. 같은 기계의 종료가 확인된 공용 잠금만 자동 회수하며, 호스트/PID를 확인할 수 없는 잠금은 파일·프로세스 정보를 보존한 채 담당자가 확인한다.

UI 감리 자료와 저장소 전체 패키지는 실제 기관의 최종 감리·도입 승인·운영 전환 절차를 대신하지 않는다. 개인정보 검출 패턴에 걸리지 않은 값도 입력자가 비식별 여부를 확인해야 한다.

## 유지보수 검증

```powershell
npm run test:requirements-workspace
node tools/requirements-workspace/build-styles.mjs --check
```

브라우저 시험 `tools/requirements-workspace/browser-check.mjs`은 반드시 폐기 가능한 빈 합성 작업공간에서 실행한다. 실제 고객 작업공간에 시험 자료를 넣지 않는다. 토큰·실행 비밀·고객 자료를 CI artifact에 올리지 않는다.
