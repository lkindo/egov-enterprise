# 요구사항 작업공간 실행 안내

고객의 요구사항·회의록·관련 산출물을 등록하면 AI가 원문 근거를 가진 요구사항을 만들고, 사람이 쟁점을 결정한 뒤 에픽·스토리·인수조건으로 이어가는 로컬 UI다. 개발 작업 패키지와 검수·감리 자료까지 같은 작업공간에서 관리한다. 기존 [앞단 CLI 플레이북](design-to-deliverables-guide.md#7-요구사항-입구intake통합-전환cutover최종-종료closeout-연결)과 같은 검증기를 사용하며, 비공개 분석에는 민감정보를 별도 안내하는 명시적 옵션을 적용한다. 저장·인수 경계는 [ADR-0050](../02-architecture/decisions/ADR-0050-local-requirements-workspace.md), AI 실행 경계는 [ADR-0051](../02-architecture/decisions/ADR-0051-ai-first-requirements-workflow.md), AI 원본 판독·통합 계획 흐름은 [ADR-0052](../02-architecture/decisions/ADR-0052-ai-document-to-development-plan.md)가 정한다. 민감정보 분석 정책은 [ADR-0053](../02-architecture/decisions/ADR-0053-private-analysis-sensitivity-advisories.md)이 비공개 작업공간에 한해 대체한다.

## 요구사항 스튜디오(기본 화면)

실행기 터미널의 첫 주소(`/studio.html#launch=...`)가 기본 화면이다. 문서를 넣으면 요구사항과 분석·설계 산출물이 쌓이고, 확정한 요구사항에서 에픽·스토리를 만든다. 결정과 한계는 [ADR-0055](../02-architecture/decisions/ADR-0055-requirements-item-store.md)와 [ADR-0056](../02-architecture/decisions/ADR-0056-requirements-wording-notes.md)에 있다. 아래 「화면을 따라 진행하기」부터는 검수·감리를 포함한 이전 화면의 안내다.

1. **자료함**: **문서 추가**에서 파일을 고르고 두 항목(민감정보 분석 방식, 모델 서비스 전송)에 동의한다. 파일을 하나씩 등록한 뒤 이어서 분석한다. 글자 문서(TXT·Markdown·HTML)는 기본으로 AI 판독 없이 이 PC에서 바로 조각으로 나누어 몇 초면 끝나고(문서 요약은 ‘로컬 문서 추출’로만 남는다), 스캔·이미지·PDF·HWP·Office 문서는 AI가 읽어 문서마다 몇 분이 걸릴 수 있다. 글자 문서도 AI가 구조를 읽게 하려면 등록 창에서 그 선택을 끈다. 등록하는 동안 문서마다 대기·읽는 중·완료(조각 수)·실패(사유)와 경과 시간이 보이고, 끝나면 문서별 결과가 남는다. 등록은 이 창이 이어서 보내므로 창을 닫거나 새로 고치면 남은 문서는 등록되지 않는다(분석은 창을 닫아도 계속된다). 등록이나 분석이 도는 동안에는 어느 단계에서든 위쪽 띠에 진행 상황과 경과 시간이 보인다. 문서는 언제든 더 넣을 수 있고, 넣은 문서의 조각만 새로 보낸다. 조각마다 요구사항 여부와 관련 산출물 종류를 표시하며 꺼 둔 산출물의 표시도 남긴다. 분석이 남아 있으면 **AI 분석 진행**으로 이어 간다.
2. **요구사항**: 공공 제안요청서의 요구사항 양식으로 보인다. 새 문서의 내용은 초안에는 덧붙고, 확정된 요구사항에는 **변경 제안**으로(출처만 더하는 경우도 같다), 기존 내용과 함께 성립할 수 없다고 AI가 판정하면 **쟁점**으로 올라온다. 짧은 값이나 표의 같은 행이 문서마다 다르게 적힌 것은 **문서마다 표기가 다른 값** 참고로 접혀 보이며 확정을 막지 않는다. 표현만 다르면 그대로 두고, 내용이 다르면 지금 내용을 유지하거나 다른 문서의 내용으로 바꾼다. 참고는 칸마다 3건까지 남는다. 기록이 길어 앞부분만 비교한 경우에는 초안이라도 변경 제안으로 올라온다. 필수 칸과 출처가 있고 열린 쟁점·질문이 없어야 확정할 수 있다. 질문은 문서가 스스로 결정을 미뤘거나 서로 다른 말을 한 경우에만 붙으며, 답을 적거나 답 없이 닫을 수 있다. ‘새로 추가됨’·‘보강됨’ 표시는 가장 최근 분석이 만들거나 덧붙인 항목을 뜻하며 다음 분석이 시작될 때 지워진다(끝나지 않은 분석을 이어 갈 때는 남는다). 확정할 때 분류별 고유번호(`SFR-001` 등)를 받으며 번호는 다시 쓰지 않는다. **기준선 만들기**는 그때의 확정 기록을 보관하고 이후 변경을 표시한다. 삭제는 없고 제외한 요구사항은 되살릴 수 있다.
3. **분석·설계 산출물**: 작성할 산출물만 켠다. 나중에 켜면 이미 표시해 둔 조각으로 초안을 만든다. 항목마다 빈칸과 완성도가 보이고 **빈칸을 AI로 보강**은 초안의 빈 칸만 채운다. 문서에 없으면 질문으로 남는다. 산출물 사이 점검(연결된 화면이 없는 기능 요구사항, 생성 프로세스가 없는 엔터티 등)은 AI 호출 없이 프로그램 규칙으로 한다. 속성정의서·논리 ERD·CRUD 매트릭스는 엔터티와 프로세스에서 만든다.
4. **에픽·스토리**: 확정된 기능·인터페이스·데이터 요구사항만 스토리가 된다. 성능·보안·품질·제약은 모든 스토리에 붙는 품질 기준이다. 요구사항이 바뀌면 그 요구사항의 스토리만 다시 쓸 대상이 되고, 제외하거나 확정을 취소한 요구사항의 스토리는 다음 반영 때 지운다. **개발 패키지 보기**는 스토리 하나에 필요한 요구사항·인수조건·관련 산출물을 한 문서로 낸다.

문서는 Markdown과 CSV로 내려받는다(요구사항정의서, 요구사항 목록, 요구사항추적표, 산출물별 문서, 에픽·스토리, 개발 패키지). ERD와 업무흐름도는 Markdown 안의 Mermaid 코드다. HWP·Word·Excel 출력은 없다.

한 번의 모델 요청은 조각 24개·28KiB 이하의 묶음 하나 또는 항목 몇 건과 비교 대상(같은 종류의 비슷한 기존 항목 6건 이하)만 싣고, 요청 JSON이 48KiB를 넘으면 줄이지 않고 그 요청을 실패로 센다. 진행 화면은 호출 수와 호출당 최대 입력 크기를 보인다. 분석은 묶음 몇 개를 읽을 때마다 거기서 나온 후보를 기존 요구사항·항목과 대조해 곧바로 초안으로 올린다. 그래서 읽기와 대조를 오가며 진행하고, 문서가 많아도 결과가 처음부터 차례로 쌓이며 대조를 기다리는 후보가 한도(2,000건)까지 밀리지 않는다. 대조 요청은 한 번에 두 건까지 함께 보낸다. 끝난 요청은 곧바로 저장하므로 중지하거나 실패한 뒤 다시 실행하면 남은 부분만 진행하며, 앞선 실행이 남긴 후보를 가장 먼저 대조한다. 한 번의 실행은 AI 호출 600회까지이고, 닿으면 멈추므로 다시 실행해 이어 간다. 실행이 실패로 끝나면 아직 돌던 요청도 함께 멈추고 실패 원인을 그대로 보인다. 실행기를 다시 시작해도 스스로 이어 가지 않는다. 같은 조각이 두 번 답을 받지 못하면 분류 실패로 닫아 문서별로 수를 보이고, 쓸 수 없는 응답이 세 번 이어지면 실행을 멈춘다.

칸의 한도는 이름 120자, 글 칸 2,000자, 목록 30줄, 표 60행(칸마다 300자)이다. 넘는 입력은 저장을 거부하고, AI가 낸 값이 넘으면 일부만 담았다는 질문을 붙여 확정 전에 확인하게 한다. 가득 찬 목록에 더하지 못한 내용은 쟁점으로 남는다. 표를 고칠 때 칸 안의 세로줄은 `\|`로 적는다.

알아 둘 한계: 표현이 전혀 다른 같은 요구는 별개의 초안으로 남을 수 있어 사람이 제외하거나 고친다. 같은 요구로 판정된 두 문서의 목록 조건이 서로 어긋나는지는 모델의 판정에 달려 있으며, 놓치면 두 조건이 함께 남는다. 스튜디오의 스토리는 이전 화면의 작업 패키지·검수표로 넘어가지 않는다. 요구사항 분류와 산출물의 칸은 기본값이며 기관 표준과 다르면 [카탈로그](../../tools/requirements-workspace/studio-catalog.mjs)를 고친다. 작업공간 하나의 상한은 항목 4,000건, 질문·쟁점·참고를 합쳐 4,000건이다. 상한에 닿아 멈춘 실행은 다시 실행해도 같은 자리에서 멈추므로 켜 둔 산출물을 줄이거나 업무 범위를 나누어 별도 작업공간에서 진행한다. 이전 버전이 표기 차이를 쟁점으로 올려 둔 작업공간은 분석을 다시 실행하면 그 쟁점이 참고로 바뀐다.

## 시작

Node 22 이상과 루트·frontend 의존성을 준비한다(`npm ci`, `pnpm -C frontend install --frozen-lockfile`). AI 실행에는 이 PC의 Claude CLI 설치·로그인과 `claude-opus-5-5` 사용 권한이 필요하다. 문서 통합·요구사항·품질 검토·에픽·스토리·작업계획은 `high`로 실행한다. 원본 판독은 기존 `xhigh` 프로필을 유지해 검증된 완료 판독을 재사용하며, 독립 코드 리뷰도 `xhigh`를 유지한다. 과거 `xhigh` 분석 이력은 보존한다. CLI의 기존 인증·요금 조건이 적용된다. 고객 작업공간은 이 저장소뿐 아니라 다른 Git 작업 트리에도 속하면 안 된다.

실행 기록의 추론 수준은 문서 분석 단계를 뜻한다. 같은 실행에서 직접 등록한 본문을 먼저 판독하는 경우에도 판독은 별도 `xhigh`로 실행하고 토큰 사용량은 합산한다. 단계 체크포인트는 같은 분석 수준끼리만 재사용하므로 과거 `xhigh` 분석 결과는 새 `high` 실행에서 다시 생성한다. 업로드한 원본의 판독 캐시는 별도로 검증해 계속 재사용한다. 직접 등록한 본문의 파이프라인 판독은 분석 수준을 전환할 때 한 번 다시 실행한다.

```powershell
node tools/requirements-workspace/server.mjs --workspace D:\agency-workspaces\project-001
```

터미널에 표시된 두 주소 가운데 하나의 전체 주소를 브라우저에서 연다. 첫 주소(`http://127.0.0.1:8792/studio.html#launch=...`)는 요구사항 스튜디오, 둘째 주소(`http://127.0.0.1:8792/#launch=...`)는 이전 화면이며 한 번 연결하면 화면 위의 링크로 오갈 수 있다. 주소의 실행 비밀을 공유하거나 문서에 기록하지 않는다. 연결 후 조각은 제거되며 같은 브라우저의 새로고침은 세션 쿠키로 다시 연결한다. 서버를 재시작하면 새 터미널 주소로 연결한다. 포트가 사용 중이면 `--port 8793`을 지정한다. 종료는 Ctrl+C다.

브라우저 자동 검증은 Chromium 엔진(Chrome·Edge 계열)에서 수행한다. 다른 엔진에서 loopback의 Secure 쿠키가 차단돼 새로고침 뒤 연결이 복원되지 않으면, 터미널의 전체 실행 주소를 다시 열거나 Chromium 계열 브라우저를 사용한다. 쿠키 보안 속성을 끄는 방식으로 우회하지 않는다.

연결 만료 화면의 **실행기 전체 주소 → 다시 연결**에 현재 터미널 주소를 붙여 넣으면 자료를 다시 등록하지 않고 연결한다. 작업 중 연결이 만료된 경우 오류 아래 **실행기 주소로 다시 연결**을 사용한다. 현재 실행기의 같은 주소·포트만 허용하며 주소를 다른 서버로 전송하지 않는다. 기존 화면에서 새 `#launch=...` 주소를 열어도 다시 연결한다. 작성 중인 폼 안에서 재연결하면 파일 선택·입력·동의 상태를 유지하며, 실패 안내도 같은 폼에 표시한다. 다른 작업공간의 실행기로 교체된 경우에는 초안이 섞이지 않도록 재연결을 거부한다. 다른 작업공간이나 포트는 새 창에서 해당 전체 주소로 연다. 연결 복구 뒤 현재 입력과 자료 범위를 확인해 다시 실행한다. 재연결만으로 AI 전송을 시작하지 않는다.

진행 현황과 산출물 수집 상단의 **AI 판독 진행**은 등록된 원본 수·완료 기록 수·현재 자료 순번·구간 진행을 표시한다. 파일 사이의 대기 구간에도 상태를 다시 읽는다. 다음 파일로 넘어가지 않으면 **AI 판독 이어서 진행**을 누르고 자료 범위·원문 분석·모델 전송을 확인한다. 이 버튼은 등록을 완료한 원본만 처리하며, 완료 판독은 재검증 후 재사용한다. 미완료 파일 기록은 따로 표시하고 **남은 파일 추가**에서 원래 파일 목록을 다시 선택한다. 같은 자료 유형·보안 분류의 완료 파일은 중복 검증으로 재사용한다. 아직 전송하지 않은 파일 목록은 창을 닫으면 보관되지 않으므로, 새 창에서 전체 선택 목록을 복구한다고 가정하지 않는다. 현재 판독이나 분석이 실행 중일 때는 중복 실행 버튼을 비활성화한다. 개별 판독은 서버에서 계속되지만, 다음 파일의 전송은 실행한 브라우저 창이 담당하므로 여러 파일 처리 중에는 그 창을 유지한다. 창을 닫았으면 현재 파일이 끝난 뒤 이어서 진행하거나 남은 파일을 추가한다.

기본은 빈 프로젝트다. 실제 고객 자료 대신 예시를 자동 채우지 않는다. 프로젝트 이름·코드·기관·시작 구성을 먼저 입력한다.

AI 실행 대화상자에서도 **실제 저장 진행**은 서버의 완료 원본 수·현재 자료·구간을 계속 조회한다. 중단된 창의 순번은 **이 창의 마지막 요청**으로 구분하므로 다른 창에서 재개한 실제 진행과 혼동하지 않는다. 이 조회는 작성 중인 입력·동의 범위를 바꾸지 않는다. 일반 편집 저장은 폼을 열었을 때의 revision을 유지해, 재연결 중 다른 작성자가 저장한 내용을 덮어쓰지 않는다. 연결이 끊긴 동안에도 재연결 입력을 제공하며, 읽기 실패를 이유로 변경 요청을 자동 재전송하지 않는다.

실패 대화상자를 닫으면 그 창에서 저장한 최신 자료 상태로 재개·미완료 파일 동선을 즉시 다시 그린다. 분석 묶음의 크기는 배열·쉼표를 포함한 UTF-8 JSON 바이트로 계산하고, 같은 묶음 안의 문서 요약·메타데이터는 한 번만 센다. 기존 묶음당 40KiB·32조항, 전체 128묶음·3,000조항 한도는 유지한다. 문서 헤더가 긴 자료도 실제 크기로 판정하며 조항을 생략하지 않는다.

## 화면을 따라 진행하기

문서 통합의 인용은 AI가 제공된 원문 근거를 선택하면 프로그램이 해당 출처·조항·인용문을 연결한다. 한글·줄바꿈·기호를 포함한 원문을 그대로 보존하며, 최종 결과와 과거 기록은 기존 출처·조항 식별자를 유지한다. 잘못된 근거 선택은 검증으로 거부하고, 연결한 인용문 전체를 실제 용량에 포함한다.

문서 통합 단계에서는 행위자·업무 흐름·용어를 찾는 간결한 업무 지도를 만든다. 판독 질문의 실제 공간·개수와 남은 문서의 최소 출처 색인을 예약한다. 인용문을 연결한 실제 누적 크기가 묶음별 간결성 목표를 넘으면 기존 1회 보정 한도에서 다시 요청한다. 보정 후에는 목표보다 크더라도 전체 실제 남은 공간에 들어가면 보존하며, 누적 항목·질문 수도 검증한다. 거부된 증가분은 이전 모델에 반영하지 않는다. 판독 질문과 최소 문서 색인도 담을 수 없는 경우 통합 AI 호출 전에 안내한다. 상세 조건·필드·인수 기준은 다음 요구사항 단계에서 모든 원문 조항을 읽어 작성한다. 변경 없는 설명은 반복하지 않고 새 사실·근거를 기존 모델에 더한다. 미해결 질문과 근거 인용은 유지하며 원본·판독 조항을 축약하거나 삭제하지 않는다. 단일 응답 자체의 실제 용량 초과와 시간 초과는 자동 반복하지 않는다.

1. **AI로 산출물 등록**: 원본을 여러 개 선택한다. 파일 선택은 확장자로 제한하지 않으며 실제 형식·구조를 확인한다. 자료 유형을 모르면 기타로 두면 AI가 문서 역할과 혼합 구성을 판단한다. 민감정보가 포함될 수 있는 원문 분석 방식과 모델 서비스 전송에 동의하면 AI가 판독·문서 구조·핵심 내용·불확실성을 정리한다. 자료 화면은 업무 요약을 먼저 보여 주며 근거 조항은 펼쳐 볼 수 있다. 원본·판독 기록·실제 사용 프롬프트도 내려받는다. **CLI 연결은 오프라인 AI가 아니다.** 기관 반출 허용은 입력자가 확인한다.
2. **AI 전체 분석**: 원본 판독 → 문서 통합 → 요구사항 → 요구사항 품질 검토 → 에픽·스토리·인수조건 → 계획 품질 검토를 자동 진행한다. 기존 로컬 추출 자료도 먼저 원본을 AI로 재판독한다. 동일 원본·분류·유형·지시 버전·모델·근거 본문의 판독은 재사용하며 원본 확인만으로 새 중복 등록 이력을 만들지 않는다. 사람이 보정·처분·근거 연결한 조항과 사유는 재판독으로 교체하지 않고 해석을 별도로 남긴다. 변경 지문이 없는 구형 자료도 기존 조항을 보존하고 새 AI 근거를 별도 ID로 추가한다. 전체 조항의 텍스트·순서가 동일하면 복사본을 더하지 않는다. 변경 없는 미검토 AI 초안만 이전 사본을 보관한 뒤 갱신한다. 바이트가 다른 판본이나 내용이 비슷한 자료는 자동 병합하지 않는다. 이번 민감정보 안내 전환에서는 직전 `2026-11-07.1`의 엄격한 검증을 통과한 완료 판독도 해시·분류·유형·모델·근거가 일치하고 보관 기록이 유효하며 모든 단위가 네이티브 원문이고 판독 불가·변환 누락이 없는 경우만 재사용한다. 구버전의 시각·혼합 판독은 민감값이 생략됐을 가능성이 있어 다시 읽는다. 과거 기록은 수정하지 않는다.
3. **질문과 초안 검토**: 권한·정책·범위·측정 기준의 실제 결정이나 판독 누락이 있으면 **답변하고 계속**에서 답한다. 없는 정책을 AI가 확정하지 않는다. 전체 분석은 문서 해석·업무 지도·원문 인용·요구사항·작업 변경·Green/Red 인수조건·개발 작업계획을 함께 제시한다. 요구사항과 계획을 계산하는 동안 사람의 검토 기록이나 기준선을 만들지 않는다. **단계별 AI 작업 지시**에서 현재 지시를, 실행 기록에서 실제 사용 지시문·버전·해시를 확인한다.
4. **전체 초안 최종 확인**: 근거와 요구사항·계획을 함께 검토해 한 번 확인하면 요구사항·분석 기준선·에픽·스토리·작업 패키지를 같은 저장 거래로 반영한다. 기존 범위 변경이나 작업·인수조건·추적 제외는 변경 전후와 사유를 보여 주고 항목별 확인을 요구한다. 누락을 삭제로 처리하지 않는다. 의미가 같은 기관 판정은 유지하고 영향받은 판정은 재검토한다. 직접 편집, **로컬 자료 등록(보완용)**, 기존 **AI 요구사항 생성**과 기준선 후 별도 에픽 생성도 보완 경로로 사용할 수 있다. 생성된 계획은 개발 완료나 기관 승인이 아니다.
5. **개발 인계**: 개발 준비의 보완 항목을 해결해 `TASK-PACKAGE.md`를 생성·다운로드한다. 에이전트나 개발자가 그 패키지를 받아 기존 SOP의 수직 슬라이스 개발을 수행한다. 화면의 패키지 생성이 코드를 구현하거나 테스트를 실행하지는 않는다. 프로젝트 구성 대조와 검토 CSV 왕복도 이 화면에서 한다.
6. **검수·감리**: 실제 시험 뒤 담당 역할·검증일·대상 빌드·근거 문서번호/해시로 인수 판정을 기록한다. 검수표 CSV를 내보내 검토하고 다시 가져올 수도 있다. 변경 없는 CSV 행은 새 빌드의 확인 기록으로 다시 만들지 않는다. 변경한 행에 이전 빌드가 기본값으로 남아 있으면 가져오기에서 지정한 새 빌드를 적용하며, 행에 이전과 다른 빌드를 직접 적으면 그 행의 값을 사용한다. 인수조건·요구사항·연결 원문·관련 작업 결정·대상 원장 정보가 바뀌면 영향받은 판정만 재검토 상태가 된다. 모듈의 화면·표 개수 같은 집계 변화는 인수를 지우지 않는다. 지적사항을 등록하고 근거를 붙여 조치 기록을 남긴다. 감리 보고서는 공식 승인·서명과 구분하는 초안이다.

## 파일 교환·복구

`backlog.json`과 `context.snapshot.json`은 기존 CLI와 같은 교환 파일이다. `requirements-ui.json`에는 기준선·원장 문맥·AI 작업/결정·파일 등록 이력·보관 파일의 해시 참조가 담긴다. 세 파일은 같은 저장 저널로 보호한다. 원본 파일은 분할 보관하며 큰 기준선·AI 입력/유효한 출력·산출물·오래된 검수 이력은 `records/`의 불변 파일로 보관하고 화면에서 내려받는다. 작업용 임시 사본도 `.scratch/`에만 만든다. 개별 교환/보관 파일의 8MiB 한도를 넘으면 원본을 보존하고 저장을 거부한다. 업무 DB에는 연결하지 않는다.

AI와 문서 판독은 비동기다. 새로고침해도 저장된 상태를 이어서 볼 수 있다. 진행 중 취소하면 해당 자식 프로세스만 종료하며 이미 등록 완료된 파일은 유지한다. 실행기를 재시작하면 실행 중 작업은 중단으로 표시하고 자동 재전송하지 않는다. 입력이 변경된 결과는 적용할 수 없으며 현재 자료로 다시 실행한다. 보관한 AI 결과가 손상되면 해당 제안의 반영을 막고 현재 프로젝트·원문을 보존한다. 원시 CLI 오류·미검증 결과는 로그나 고객 작업공간에 저장하지 않는다. 민감정보 패턴만으로 판독·등록·계획 생성을 중단하지 않는다. 원문과 검증된 결과를 비공개 작업공간에 보관하고, 화면의 별도 안내에 감지 종류·단계·항목 수·최대 20개의 안전한 필드 위치를 표시한다. 실제 값은 안내에 넣지 않는다. 자료별 안내에서 해당 원본을 열 수 있고 문서 속성(metadata)·주석(memos)·본문 블록을 구별한다. 폐기된 AI 응답의 경고는 집계하지 않으며 체크포인트 경고는 의미 검증 후 복원한다. 단계별 반복 감지가 있어 항목 수는 고유 정보나 사람 수가 아니다. 민감정보 감지 자체는 판독 불가나 의사결정 문제가 아니다. 구조·원문 근거 검증에 실패한 결과는 등록하지 않으며, 판독 불가·시간 초과 등 복구 가능한 실패의 원본은 동의 범위에서 보존한다. 이미 있던 원본·사람의 기록을 자동 삭제하지 않는다.

## 지원 자료와 판독 한계

| 형식·구조 | 기본 AI 경로 |
|---|---|
| TXT·Markdown·임의 확장자의 읽을 수 있는 텍스트 | UTF-8 또는 BOM 있는 UTF-16을 보존하고 AI가 역할·구조·업무 의미를 분석한다. CSV·JSON·로그 같은 텍스트도 정해진 문서 양식에 맞출 필요가 없다. |
| HTML | 본문·표 구조를 읽으며 스크립트·외부 리소스를 실행하지 않는다. CSS로만 표시되는 내용이나 외부 이미지가 중요한 경우 화면 PDF·이미지 사본을 함께 등록한다. |
| PDF·스캔·사진·PNG·JPEG·WebP·TIFF | 페이지/프레임을 메타데이터 제거 JPEG로 준비해 AI가 직접 읽는다. PDF 텍스트는 보조 정보이며 로컬 OCR 결과를 필수로 하지 않는다. 텍스트 보조정보의 해시를 남기고 숫자·단위·부정어 등의 누락/불일치는 모델이 확신해도 확인 필요로 올린다. 본문이 있는 쪽을 빈 쪽으로 판독하면 미판독으로 남긴다. 이 대조가 모든 문자나 의미의 일치를 증명하지는 않는다. 복수 페이지도 순서·위치를 유지한다. |
| HWP/HWPX | 로컬 파서와 가능한 페이지 렌더를 사용해 AI가 판독한다. 렌더 실패·누락은 확인할 문제로 표시한다. |
| DOCX·XLS/XLSX·PPTX | 본문·표·시트와 사용 가능한 내장 이미지를 AI에 전달한다. 원래 화면 배치의 완전한 재현은 보장하지 않으며 변환 참고 사항을 남긴다. 차트·수식·SmartArt 등의 완전한 보존을 보장하지 않는다. 중요한 시각 구조는 PDF 사본을 함께 등록한다. |
| 도형·표·여러 단·수기·혼합 문서 | 읽기 순서·행/열·단위·연결 방향을 분석한다. 네이티브 원문, AI 시각 전사, 글자 없는 도형의 **AI 시각 해석 — 원문 전사 아님**을 구별한다. 불확실 구간과 변환 누락은 질문으로 남긴다. |
| 그 밖의 바이너리·구형 DOC·보호/손상 파일 | 성공으로 꾸미거나 일부만 조용히 생략하지 않는다. 안전하게 수용한 실패 원본을 보존하고 사유를 표시한다. 읽을 수 있는 비식별 PDF·이미지·DOCX 사본으로 변환해 등록한다. 실행 파일·스크립트는 실행하지 않는다. |

기본 한도는 파일당 20MiB, 네이티브 본문 512KiB, 준비 단위 200개, PDF/이미지 100쪽, 페이지 이미지 합계 22MiB다. 모델 전송은 호출당 이미지 4개 이하·입력 단위 8개 이하·본문 약 40KiB로 나눈다. 개별 이미지 5MiB, CLI 시각 자료 합계 20MiB이며 파일당 판독은 최대 128묶음이다. 로컬 준비 시간 3분, AI 호출 15분의 제한을 둔다. 초과하면 자료를 임의로 빼지 않고 명시적으로 중단한다. 모든 바이너리 형식과 문서 구조를 판독할 수 있다는 보장은 아니다.

요구사항의 저장·검토 단위는 조항 32개·원문 약 40KiB 이하의 묶음이며, 이전 저장점과 조항 순서를 유지한다. 네 묶음 이상인 자료는 요청 크기가 허용하면 인접한 최대 3묶음을 한 CLI 호출로 처리한다(합계 96조항·원문 96KiB 이하). 전체 요청이 760KiB를 넘으면 함께 처리할 묶음을 줄여 768KiB 전송 상한과 보정용 여유를 지킨다. 원문 묶음이 하나뿐인 자료는 이전과 같이 근거 번호 변환 후 요청 768KiB까지 한 번에 처리하고, 그보다 클 때만 아래의 누적 기록 대조를 쓴다. 하나의 묶음도 전송 상한을 넘으면 원문·이전 의미를 잘라내지 않고 저장점을 유지한 채 중단한다. 이미지·PDF를 직접 전송하는 개별 분석은 첨부 한도를 유지하기 위해 한 묶음씩 처리한다. 합친 호출이 시간·응답 크기·구조 검증 때문에 실패하면 같은 호출을 자동 반복하지 않고 단일 묶음 처리 정책을 기록한다. 같은 입력·프로필로 명시적으로 재개하면 저장된 완료 지점부터 한 묶음씩 처리하며, 첫 묶음에서 실패해 저장점이 없어도 이 정책은 유지한다. 완료 수는 함께 처리한 묶음 수만큼 증가하며 전체 묶음 수는 변하지 않는다. 신규 ID를 묶음별로 구분하고 변경 없는 요구사항·인용·미해결 질문을 보존한다.

통합은 문서 4개, 요구사항 검토는 최대 6개와 인용되지 않은 조항 최대 32개, 계획은 원칙적으로 요구사항 4개(기존 하위 작업이 연결한 요구사항은 같은 묶음에 보존), 계획 검토는 하위 작업 최대 8개씩 처리한다. 검토·계획은 근거 번호 변환 후 실제 요청과 스키마의 UTF-8 크기를 재어 720KiB 안에 맞게 독립 그룹을 더 나눈다. 공유 하위 작업·인수조건의 연결 범위는 나누지 않는다. 공통 문맥의 한 구간 때문에 요구사항을 다시 나누어도 다른 구간 창이 이미 다루는 공통 기록은 반복하지 않는다. 같은 계획 그룹을 여러 창으로 나누면 첫 창이 작업·인수조건을 만들고, 뒤 창은 그 항목을 보며 추가하거나 바꿀 것만 반환한다(없으면 빈 결과). 전역 제약과 명시적으로 연결된 다른 요구사항의 전체 의미 및 분석 질문을 검토·계획에 전달하며, 다른 묶음의 실행 범위로 잘못 편입하지 않는다. 질문의 본문은 유지하고 인용은 해당 창의 전체 원문에 들어 있는 부분만 반복 전송한다. 전체 질문·근거는 정식 원장에 보존하고 모든 원문 조항은 별도 검토한다. 한 요구사항의 검토 근거가 큰 경우 의미 본문을 매 구간에 제공하고 연결된 모든 원문 조항을 나눠 검토하며, 기존 인용은 프로그램이 전부 보존한다. 동일 조항에서 겹치는 계획 근거는 겹친 구간만 합쳐 모든 인용을 포함한다. 쟁점·공유 범위 등 더 나눌 수 없는 한 입력 자체가 한도를 넘으면 원문과 저장점을 보존하고 용량 오류로 안내한다. 합성 업무 지도는 160KiB, 실행당 최대 1,024회 모델 호출, 요청 JSON 768KiB, 개별 모델 출력 1MiB·새 쟁점 100개를 유지한다. 원문 조항 3,000개·요구사항 150개·개별 응답 항목당 인용 128개를 유지한다. 기존 최대 96조항 전송 묶음이 한 업무 목적에 해당해도 인용 30개 때문에 요구사항을 억지로 분할하지 않도록 응답 항목당 선택 한도를 128개로 두고, 응답 전체 1MiB 제한과 원문 검증을 함께 유지한다. 검증된 근거를 누적한 요구사항·쟁점은 항목당 인용 3,000개와 프로젝트 4MiB 보관 한도를 별도로 적용한다. 검증된 개별 응답을 합친 프로젝트 제안은 별도로 쟁점 1,000개·4MiB 이내이며 최종 감사 보관 기록은 8MiB 이내다. 프로젝트 한도를 이유로 개별 응답의 형식·근거·크기 검증을 완화하지 않는다. 전체 질문의 의미를 나누어 전송하고 원문 인용 전체를 저장하며, 질문의 종류·선택지·대상 요구사항이 다른 항목은 질문 문구가 같아도 버리지 않는다. 질문 목록과 답변 창은 20개씩 표시한다. 페이지를 이동해도 작성 중 답변을 이 창에서 유지하며, 모든 결정 필요 질문에 답한 뒤 전체 답변을 반영한다. 닫거나 새로고침하면 미제출 답변은 보관되지 않으므로 주의한다. 질문의 페이지 이동은 결정이나 승인 기록을 생성하지 않는다. 문서 통합과 요구사항 초안의 실제 쟁점 합계가 프로젝트 한도를 넘으면 완료 묶음을 저장한 직후 남은 분석 전에 중단하고, 같은 입력으로 재개할 때도 추가 호출 전에 검사한다. 입력·출력·저장 한도 안에 들어가도록 질문·조건·예외를 임의로 삭제하거나 요약하지 않는다.

요구사항 생성 묶음은 앞서 저장한 전체 요구사항의 의미·조건·질문을 확인하며 순서대로 처리한다. 같은 요구를 서로 다른 새 ID로 중복 생성할 위험 때문에 공유 초안을 기준으로 동시에 생성하지 않는다. 기존 조건·예외·미해결 질문·원문 조항을 삭제해 속도를 맞추지 않는다. 요구사항 품질 검토는 다른 요구사항의 전체 의미도 확인하므로 순서대로 실행하며, 앞 그룹에서 보완한 조건을 다음 그룹에 전달한다. 공통 요구사항·질문·자료 관계는 완전한 의미 기록 단위로 나누어 모든 창을 방문하고, 각 호출 직전에 최신 초안과 실제 전송 바이트를 다시 확인한다. 계획 생성·계획 검토에도 같은 공통 문맥 분할을 적용한다. 공유 에픽·인수조건의 전체 업무 범위는 유지한다. 문서 판독·업무 통합과 공유 에픽을 수정하는 계획 검토도 의존 순서를 유지한다.

누적 초안 때문에 요청이 커지면 현재 원문에서 임시 요구사항 후보를 먼저 작성하고, 기존 요구사항·질문·업무 통합 질문의 완전한 의미와 앞서 완료했거나 이미 인용된 조항의 보관 판독 본문 전체를 크기에 맞춰 대조한다. 과거 짧은 인용 밖의 조건과 제외·배경 조항도 제공하며 원본 판독을 다시 호출하지 않는다. 나중에 들어온 정의·참고 자료는 새 기능을 억지로 만들지 않고 근거를 선택해 기존 요구사항에 연결한다. 대표 근거만 선택하거나 조건·예외를 요약해 버리지 않는다. 기존 의미와 원문 조항의 연결을 유지하고, 통합할 한 후보의 근거가 큰 경우 같은 의미 본문을 반복해 모든 근거 페이지를 방문한다. 후보와 기존 ID의 연결 및 신규 정식 ID 발급은 전체 대조가 검증된 뒤 결정한다. 임시 ID는 최종 요구사항 식별자로 게시하지 않는다. 같은 업무의 기존 ID가 하나면 그 ID로 통합하며, 여러 기존 ID에 동시에 대응하면 모두 보존하고 차단 질문을 남긴다. 동일 업무·명시적 정의의 지지 근거만 요구사항에 합친다. 관련 자료는 별도 관계 기록으로, 상충 자료는 양쪽 원문을 갖춘 차단 질문으로 남겨 지지 근거와 섞지 않는다. 이 사실 연계 기록은 정책 질문 개수에 포함하지 않으며 전체 제안 보관 한도 안에서 검증한다. 필수 참조 값을 현재 자료에서 확인할 수 없으면 잠정 질문을 만들고, 전체 역사 대조에서 찾은 답들을 원문·조건·범위에 따라 다시 판단한다. 근거로 해소한 새 잠정 질문은 답과 원래 질문을 별도 감사 기록에 보관한다. 답이 없거나 상충하면 질문을 유지하며 기존 정식·사람 질문을 자동 해소하지 않는다. 기존·신규 근거는 프로그램이 합쳐 보존하고 전체 원문 범위·참조·원문 인용 검증을 거친 뒤에만 해당 논리 묶음의 완료 수를 늘린다. 검증된 후보·대조·통합 응답도 따로 저장하므로 새 실행 ID로 재시작해도 같은 자료·업무 문맥의 완료 소단계를 재호출하지 않는다. 예전 완료 분석 저장점은 먼저 원래 전체 범위 검증을 거쳐 재사용한다. 실행당 호출 한도에 도달하면 저장 결과를 유지하며 재실행으로 남은 작업을 진행한다. 단순한 속도 배수나 캐시 적중을 보장하지 않으며, 근거가 많으면 전체 대조에 추가 호출이 필요하다.

요구사항·검토·계획 단계의 전송에서는 원문 인용을 제공된 근거 번호로 선택하고 프로그램이 저장된 정확한 인용문을 복원한다. 현재 묶음 원문과 이전 요구사항의 의미·조건·예외·쟁점은 그대로 제공한다. `stored-evidence-v3`는 전체 본문이 이번 입력에 있는 조항의 인용 선택지만 해당 본문의 UTF-16 `[시작, 끝)` 위치로 표현하여 같은 글자를 다시 전송하지 않는다. 여러 발췌가 있는 조항은 모델이 문자 수를 세지 않고 본문을 찾도록 앞뒤 구절 힌트도 함께 제공한다. 힌트가 같은 조항 안에서 반복되어 모호하면 해당 인용문 전체를 제공한다. 이번 입력에 전체 본문이 없는 과거 인용문은 전부 문자열로 제공한다. 원문이 입력에서 사라지거나 요약되는 방식이 아니며, 이전 설명에서 누락된 조건·예외·수치도 대조할 수 있다. 누적 기록을 나눠 대조하는 호출에서는 기존 요구사항의 전체 의미와 과거 인용을 모두 포함하는 원문 조항을 함께 제공하고 공유 조항은 한 번만 전송한다. 근거 통합에도 해당 원문과 정확한 인용 객체를 제공한다. 일반 추출·후속 검토에서는 근거 번호 선택으로 응답의 본문 재생성을 줄인다. 이번 호출에 과거 원문을 반복하지 않았다는 이유만으로 앞서 보존·대조한 기존 규칙을 미확인 사실로 바꾸지 않는다. 선택 구간은 문장·줄 경계를 우선하며 긴 구간에만 창을 적용한다. 번호 형식의 부가 정보 때문에 요청 상한을 넘지만 기존의 전체 원문 계약이 상한 안에 들어가면, 원문을 빼지 않고 기존 입력·출력 형식으로 처리한다. 복원 후 기존 구조·원문 인용·조항별 검토·전체 범위 검증을 모두 수행한다. 변하지 않는 업무 모델·모듈·결정을 변하는 분석 초안·현재 원문보다 앞에 배치하여 공통 프롬프트 캐시 사용 여지를 두되 캐시 적중·시간 절감은 실제 측정값으로 판단한다. 현재 묶음의 문서 역할·형식은 별도 currentMaterialProfile로 명시하여 상황별 지시를 적용할 범위를 유지한다. 계획 생성 시 현재 연결 그룹의 상세 계획과 공유 에픽을 제공하고 전체 작업 ID·의존성 색인을 유지한다. 공유 인수조건이 연결하는 요구사항도 같은 그룹으로 묶으며, 최종 계획은 전체 범위로 검증한다.

진행 화면은 실제 응답 대기 중인 단계·묶음·대기 시간과 저장 완료 묶음을 구분한다. 실행 측정값은 실제 호출·보정·저장 결과 재사용·최대 동시 호출·요청 JSON 바이트 합계와 측정 가능한 응답 JSON 바이트를 표시한다. 요청 크기는 원본 파일 크기가 아니며, 동시 호출 대기 시간의 합계를 실제 소요 시간이나 절감 시간으로 표시하지 않는다. 공급자가 보고한 캐시 읽기·생성 토큰과 보고 횟수도 표시하며, 보고가 없으면 미보고로 안내한다. 측정값이 없는 과거 실행에는 추정치를 만들지 않는다.

실행 확인 창에서 자료 범위·호출 비용·완료 단계 재사용을 안내한다. 개별 요구사항 분석도 완료 묶음을 저장하고, 입력·프롬프트·추론 수준·실제 시각 자료 직접 전송 정책·상위 업무 문맥이 같은 가장 많이 완료된 저장점을 검증해 재사용한다. 전체 처리의 분석 저장점을 개별 분석에서 사용할 때는 검증된 문서 통합 문맥도 함께 사용하고 그 질문을 보존한다. 전체 처리로 돌아올 때는 상위 업무 문맥이 호환되는 후보를 고르며, 완료 분석 범위가 같으면 후속 검토·계획 저장점이 더 깊은 기록을 우선한다. 단일 묶음의 완료도 재사용 범위에 포함한다. 개별 요구사항 분석의 기본은 등록된 본문과 검증된 AI 판독·통합 문맥 활용이다. 이미지·PDF 직접 재전송은 사용자가 별도로 선택하며 해당 방식의 저장점만 재사용한다. 전체 처리의 분석 단계와 본문 전용 개별 분석은 직접 첨부하지 않는 같은 정책으로 비교한다. 정책은 실행 기록에 보관하고 구형 이력은 실제 전송 경로로 해석한다. 두 경로 모두 완료 결과 재사용은 기본 선택이며 해제하면 새로 처리한다. 중단 뒤 명시적으로 재실행에 동의하면 입력·프롬프트·상위 결과가 같은 검증 완료 단계와 요구사항 묶음을 재사용한다. 예전 대표 인용 생성 오류만 남은 문서 통합 기록은 업무 모델을 먼저 검증하고 현재 원문으로 대표 인용을 재구성해 전체 문서 정보를 다시 검증한다. 검증된 모델과 원본 판독은 재호출하지 않으며 이전 보관 이력도 유지한다. 모델·자료 정보·보관 무결성의 불일치는 계속 거부한다. 요구사항 검토는 완료 그룹마다, 계획은 생성 전체 검증 뒤와 계획 검토 그룹마다 저장하여 후속 실패 시 앞선 유효 결과를 반복 호출하지 않는다. 같은 요구사항을 나눈 검토 창은 앞선 의미 수정이 다음 창에 전달되도록 직렬 처리한다. 통합 응답은 모듈·범위·근거·커버리지의 전체 조합을 검증한 뒤 임시 저장점에 보관하며, 범위 변경 제안의 기존 사람 확인 절차는 유지한다. 재개한 그룹도 같은 원문·범위·최종 검증을 다시 거친다. 정식 완료 저장점은 전체 범위·무결성 검증 실패 시 재사용하지 않는다. 현재 묶음의 비정식 후보·대조·통합 저장점만 손상됐거나 처리 정책이 바뀌었으면 그 임시 결과만 폐기하고, 검증된 완료 묶음과 판독·업무 통합 결과는 유지한다. 화면에 재구성 사유와 유지한 완료 묶음 수를 안내한다. 합쳐진 현재 후보 생성 자체가 크기·시간·출력 검증에서 실패하면 다음 실행은 논리 묶음 한 개씩 처리한다. 업무 판독·분석의 의미 지시 버전(`PROMPT_VERSION`)·원본·현재 근거·결정이 바뀌면 관련 캐시를 무효화한다. 근거 번호 등 전송 표현은 별도 계약 버전(`EVIDENCE_PROTOCOL`)으로 관리하고 실제 전송 지시·스키마 해시를 기록한다. 표현만 바뀐 경우에도 과거의 정식 결과는 현재의 같은 업무·원문·범위 검증을 모두 통과해야 재사용한다. 원본 판독 정책을 바꾸지 않는 전송 형식 변경으로 완료 판독을 재실행하지 않는다. 실행기 재시작은 자동 전송하지 않는다. 판독 지시는 문서 역할에 맞춰 조정하며 실제 지시문도 기록한다.

파일 선택·여러 파일 등록·기존 원본 판독 대기열을 완료할 때까지 UI를 열어 둔다. 서버에서 시작한 개별 판독과 전체 AI 분석은 비동기로 실행되고 새로고침 후 진행 상태를 볼 수 있다. 문서 통합의 대표 인용은 원문에서 그대로 발췌하고 인용 검증을 통과하는 구간만 선택한다. 장식·공백 조항도 전체 원문과 후속 요구사항 분석에는 보존한다. 문서 통합 입력은 모델 호출 전에 검증하며, 통합 결과의 구조·근거 오류는 묶음당 한 번만 원본 입력과 값 없는 위반 종류·위치로 재생성한다. 폐기된 통합 초안 자체는 재전송하거나 저장하지 않는다. 시간 초과·취소·용량 오류는 자동 재시도하지 않으며 전체 호출·입력 상한도 유지한다. 요구사항 묶음 분석의 구조·인용·참조 오류는 묶음마다 최대 한 번 원래 입력과 안전한 위반 종류·위치만으로 재생성한다. 폐기된 묶음 응답 본문은 형식과 무관하게 재전송하거나 저장하지 않는다. 앞 묶음의 보정 이력은 다음 묶음이나 체크포인트 재개의 보정 기회를 소모하지 않는다. 같은 묶음의 보정 응답과 최종 전체 검증은 보정 기회를 공유한다. 단일 응답 크기·시간 초과·취소·실제 용량 실패는 자동 반복하지 않는다. 실패하면 최대 10개의 값 없는 검증 종류·알려진 필드 위치를 보관·안내하며, 원시 오류나 임의 객체 키·값은 안내에 넣지 않는다. 전체 분석의 검증 완료 묶음은 재실행 동의 후 재사용한다. 전체 분석의 단일 묶음도 폐기된 응답 없이 원본 입력과 안전한 위반 정보만으로 한 번 보정한다. 보완용 개별 요구사항 분석도 같은 값 없는 보정과 완료 묶음 저장을 사용한다. 개별 분해의 보정에는 기존 형식 검증을 통과한 비공개 초안 전송 계약을 유지한다. 실패 결과는 기존 확정 자료를 덮어쓰지 않는다.

기존 로컬 보완 경로의 OCR은 첫 실행에 해시로 검증한 공개 PP-OCRv5 모델을 내려받을 수 있다. 모델 다운로드에 문서 내용을 보내지 않는다. 캐시는 기본적으로 사용자 홈의 .cache/kordoc/models/ppocr이며 KORDOC_OFFLINE=1은 이 로컬 경로용 설정이다. 기본 AI 경로는 모델 서비스 접속이 필요하다. 개인정보 패턴 검사는 완전한 비식별 검사나 이미지 내용 검사가 아니므로 입력자가 속성·주석·이미지까지 확인한다.

UI가 열려 있는 동안 CLI와 다른 UI는 같은 작업공간에 쓸 수 없다. CLI로 작업할 때는 UI 실행기를 먼저 종료한다. CLI가 문맥을 갱신했다면 UI 재접속 시 차이를 확인하고 기준 정보를 명시적으로 갱신한다. CSV에서 기존 행을 빠뜨리면 가져오기가 거부되며, 누락 행은 삭제가 아니다. UI는 보관한 조항·요구사항의 삭제 기능을 제공하지 않으므로 보류·제외 처분으로 근거를 보존한다.

검수 CSV는 매번 최신 작업공간에서 다시 내보낸 것을 사용한다. 내보낼 때 각 인수조건의 현재 판정·근거·빌드 상태를 `uatBaseDecisionHash` 열(14열 필수 머리글)에 기록하고, 가져오기(`uat-import` 및 UI 검수 CSV 반영) 때 현재 판정 상태와 대조한다. `uatBaseDecisionHash` 열이 없는 예전 13열 CSV는 머리글 검증에서 거부되며, 내보낸 뒤 다른 검수 판정이 기록된 상태에서 예전 CSV로 판정을 바꾸려 하면 `uatBaseDecisionHash` 불일치로 거부하여 최신 판정 덮어쓰기를 막는다(판정 변경이 없는 행은 통과한다). 최신 작업공간에서 `uat-export`로 검수표를 다시 내려받아 반영하는 것이 기본 절차이며, 불가피하게 이전 검수 시트 전체에 대해 판정 해시 불일치 차단을 풀고 덮어써야 할 때만 CLI `uat-import --allow-decision-overwrite`를 사용한다. UI를 통한 판정·가져오기 기록은 누적 이력에 남는다.

작업공간 전체를 백업한다. 이 버전은 경고 메타데이터를 추가하므로 구버전 도구가 새 작업공간을 열지 못할 수 있다. 첫 실행 전에 전체 작업공간의 별도 백업을 보존한다. 구버전으로 돌아가야 하면 백업 복사본에서 검증하고, 현재 JSON 키나 과거 기록을 손으로 지워 호환시키지 않는다. 중단된 저장은 다음 시작 때 저널과 파일 해시가 맞는 경우에만 복구한다. 외부 수정·손상·알 수 없는 잠금은 자동 덮어쓰지 않는다. 이때 원본·저널·잠금을 보존하고 별도 복사본에서 비교한다. 잠금 파일을 무조건 지우거나 `backlog.json` 한 장으로 기준선 이력을 덮어쓰지 않는다. 화면의 충돌 오류도 작성 중 입력을 지우지 않는다.

비공개 UI의 판독 기록·검토 CSV·작업 패키지 다운로드는 원문을 포함할 수 있으므로 공유 전에 검토한다. 생성 파일마다 감지 내역을 별도로 표시하며, 패턴이 있는 Markdown 패키지에는 값 없는 안내를 넣는다. CSV 헤더와 본문은 왕복 형식을 유지한다. 기본 공유 검증기와 저장소 CLI는 민감정보를 계속 오류로 처리한다. UI 작업공간 원본을 직접 마스킹해 근거 해시를 바꾸지 말고 검토한 별도 사본을 준비한다. 마스킹으로 근거·인수조건 해시가 바뀌면 다시 검증하며 기존 기관 판정을 새 사본의 승인으로 이월하지 않는다. 전체 저장소 산출물 패키지는 UI 종료 후 기존 명령을 사용한다. 현재 원장·코드가 깨끗한 상태에서 실행하며 원문과 UAT 해시 검증은 동일하게 적용된다.

```powershell
node scripts/export-deliverables-workspace.mjs uat-import --workspace D:\agency-workspaces\project-001 --build-ref BUILD-001
node scripts/export-deliverables.mjs --backlog D:\agency-workspaces\project-001\backlog.json
```

백로그를 포함한 패키지 기본 위치는 `<작업공간>/deliverables/<커밋>`이다. `--out`은 Git 밖의 아직 없는 절대 디렉터리로 지정하며 기존 고객 디렉터리를 덮어쓰지 않는다. 브라우저의 내려받기 파일은 사용자가 정한 다운로드 위치에 저장된다. CLI는 현재 AC의 검수 기록을 보존하고, UI의 누적 이력은 UI를 통한 기록/가져오기를 사용한다.

이전 본문 전용 또는 v2 인수 해시를 가진 기존 백로그는 UI 실행 전 `uat-export --workspace <경로>`로 새 해시와 `pending` 검수표를 만들고 실제 근거·`uatBuildRef`를 확인하여 재검수한다. 과거 기준선 보관 파일을 현재 규칙에 맞춘다고 손으로 바꾸지 않는다. 남은 CLI 잠금은 먼저 해당 PID가 실제로 종료됐는지 확인하고 실행기를 다시 연다. 같은 기계의 종료가 확인된 공용 잠금만 자동 회수하며, 호스트/PID를 확인할 수 없는 잠금은 파일·프로세스 정보를 보존한 채 담당자가 확인한다.

UI 감리 자료와 저장소 전체 패키지는 실제 기관의 최종 감리·도입 승인·운영 전환 절차를 대신하지 않는다. 개인정보 검출 패턴에 걸리지 않은 값도 입력자가 비식별 여부를 확인해야 한다.
