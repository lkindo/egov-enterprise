# 요구사항 작업공간 실행 안내

고객 자료의 조항을 요구사항과 연결하고 에픽·스토리·인수조건을 작성한 뒤 개발 작업 패키지와 검수·감리 자료를 만드는 로컬 UI다. 기존 [앞단 CLI 플레이북](design-to-deliverables-guide.md#7-요구사항-입구intake통합-전환cutover최종-종료closeout-연결)과 같은 검증기를 사용한다. 설계 경계는 [ADR-0050](../02-architecture/decisions/ADR-0050-local-requirements-workspace.md)이 정한다.

## 시작

Node 22 이상과 저장소 의존성을 준비한 뒤 실행한다. 고객 작업공간은 이 저장소뿐 아니라 다른 Git 작업 트리에도 속하면 안 된다.

```powershell
node tools/requirements-workspace/server.mjs --workspace D:\agency-workspaces\project-001
```

터미널에 표시된 `http://127.0.0.1:8792/#launch=...` 전체 주소를 브라우저에서 연다. 주소의 실행 비밀을 공유하거나 문서에 기록하지 않는다. 연결 후 조각은 제거되며 같은 브라우저의 새로고침은 세션 쿠키로 다시 연결한다. 서버를 재시작하면 새 터미널 주소로 연결한다. 포트가 사용 중이면 `--port 8793`을 지정한다. 종료는 Ctrl+C다.

기본은 빈 프로젝트다. 실제 고객 자료 대신 예시를 자동 채우지 않는다. 프로젝트 이름·코드·기관·시작 구성을 먼저 입력한다.

## 화면을 따라 진행하기

1. **산출물 수집**: 비식별 TXT·Markdown을 불러오거나 원문을 직접 기록한다. 자료 분류·원문 위치·조항·처분과 사유를 작성한다. HWP·PDF·이미지는 별도 도구에서 비식별 발췌한 텍스트로 입력한다. 이 도구는 OCR이나 외부 AI를 호출하지 않는다.
2. **요구사항 검토**: 원문 조항을 선택해 원자 요구사항을 만든다. 기능·비기능 유형, 포함·보류·제외 범위와 Fit·설정·추가 개발·혼합 판정을 각각 정한다. 질문을 해결하고 비기능·데이터·제약의 측정값·목표·검증 방법을 기입한다. 현재 내용을 검토했다고 명시한다. 매칭은 후보·원장 관측일 뿐 기관 적합성 판정은 아니다.
3. **분석 기준선**: 남은 조항·범위·질문·검토 항목을 해결하고 기준선을 확정한다. 요구사항이나 연결 원문이 바뀌면 해당 요구사항을 검토하고 새 기준선을 만든다. 개발로 저장소 문맥이 달라지면 추적 대상의 차이를 확인하고 갱신한다. 업무 요구사항 자체가 같으면 기존 분석 기준선을 유지하고, 관련 대상이 바뀐 인수조건만 재검수한다.
4. **에픽·스토리**: 포함 요구사항을 에픽 아래 스토리·구성·검증·기반 작업으로 상세화한다. 역할·행동·가치, 의존 작업, D-1~D-5 결정 카드, Green/Red 인수조건을 작성한다. 권한 거부(403)와 입력 거부(400)는 분리한다. 역량·화면·API·표·게이트·이관 매핑의 후보/계획/기존 링크를 기록한다.
5. **개발 인계**: 개발 준비의 보완 항목을 해결해 `TASK-PACKAGE.md`를 생성·다운로드한다. 에이전트나 개발자가 그 패키지를 받아 기존 SOP의 수직 슬라이스 개발을 수행한다. 화면의 패키지 생성이 코드를 구현하거나 테스트를 실행하지는 않는다. 프로젝트 구성 대조와 검토 CSV 왕복도 이 화면에서 한다.
6. **검수·감리**: 실제 시험 뒤 담당 역할·검증일·대상 빌드·근거 문서번호/해시로 인수 판정을 기록한다. 검수표 CSV를 내보내 검토하고 다시 가져올 수도 있다. 변경 없는 CSV 행은 새 빌드의 확인 기록으로 다시 만들지 않는다. 변경한 행에 이전 빌드가 기본값으로 남아 있으면 가져오기에서 지정한 새 빌드를 적용하며, 행에 이전과 다른 빌드를 직접 적으면 그 행의 값을 사용한다. 인수조건·요구사항·연결 원문·관련 작업 결정·대상 원장 정보가 바뀌면 영향받은 판정만 재검토 상태가 된다. 모듈의 화면·표 개수 같은 집계 변화는 인수를 지우지 않는다. 지적사항을 등록하고 근거를 붙여 조치 기록을 남긴다. 감리 보고서는 공식 승인·서명과 구분하는 초안이다.

## 파일 교환·복구

`backlog.json`과 `context.snapshot.json`은 기존 CLI와 같은 교환 파일이다. `requirements-ui.json`에는 기준선·원장 문맥·이력·보관 파일의 해시 참조가 담긴다. 세 파일은 같은 저장 저널로 보호한다. 큰 기준선과 산출물, 오래된 검수 이력은 작업공간의 `records/`에 불변 파일로 보관하고 화면에서 내려받는다. 작업용 임시 사본도 작업공간의 `.scratch/`에만 만든다. 파일당 8MiB 한도를 넘으면 원본을 보존하고 저장을 거부한다.

UI가 열려 있는 동안 CLI와 다른 UI는 같은 작업공간에 쓸 수 없다. CLI로 작업할 때는 UI 실행기를 먼저 종료한다. CLI가 문맥을 갱신했다면 UI 재접속 시 차이를 확인하고 기준 정보를 명시적으로 갱신한다. CSV에서 기존 행을 빠뜨리면 가져오기가 거부되며, 누락 행은 삭제가 아니다. UI는 보관한 조항·요구사항의 삭제 기능을 제공하지 않으므로 보류·제외 처분으로 근거를 보존한다.

검수 CSV는 매번 최신 작업공간에서 다시 내보낸 것을 사용한다. 인수조건의 내용 해시는 검사하지만 검수 판정 자체의 버전은 비교하지 않으므로, 같은 인수조건의 예전 CSV를 가져오면 그 뒤의 판정·근거·빌드를 이전 값으로 바꿀 수 있다. 가져오기 전에 현재 판정과 대조한다. UI를 통한 과거 기록은 이력에 남으며, 이 한계는 [GAP-REQ-001](../04-operations/known-gaps-detail.md#ci-governance)에 기록한다.

작업공간 전체를 백업한다. 중단된 저장은 다음 시작 때 저널과 파일 해시가 맞는 경우에만 복구한다. 외부 수정·손상·알 수 없는 잠금은 자동 덮어쓰지 않는다. 이때 원본·저널·잠금을 보존하고 별도 복사본에서 비교한다. 잠금 파일을 무조건 지우거나 `backlog.json` 한 장으로 기준선 이력을 덮어쓰지 않는다. 화면의 충돌 오류도 작성 중 입력을 지우지 않는다.

전체 저장소 산출물 패키지는 UI 종료 후 기존 명령을 사용한다. 현재 원장·코드가 깨끗한 상태에서 실행하며 원문과 UAT 해시 검증은 동일하게 적용된다.

```powershell
node scripts/export-deliverables-workspace.mjs uat-import --workspace D:\agency-workspaces\project-001 --build-ref BUILD-001
node scripts/export-deliverables.mjs --backlog D:\agency-workspaces\project-001\backlog.json
```

백로그를 포함한 패키지 기본 위치는 `<작업공간>/deliverables/<커밋>`이다. `--out`은 Git 밖의 아직 없는 절대 디렉터리로 지정하며 기존 고객 디렉터리를 덮어쓰지 않는다. 브라우저의 내려받기 파일은 사용자가 정한 다운로드 위치에 저장된다. CLI는 현재 AC의 검수 기록을 보존하고, UI의 누적 이력은 UI를 통한 기록/가져오기를 사용한다.

이전 본문 전용 또는 v2 인수 해시를 가진 기존 백로그는 UI 실행 전 `uat-export --workspace <경로>`로 새 해시와 `pending` 검수표를 만들고 실제 근거·`uatBuildRef`를 확인하여 재검수한다. 과거 기준선 보관 파일을 현재 규칙에 맞춘다고 손으로 바꾸지 않는다. 남은 CLI 잠금은 먼저 해당 PID가 실제로 종료됐는지 확인하고 실행기를 다시 연다. 같은 기계의 종료가 확인된 공용 잠금만 자동 회수하며, 호스트/PID를 확인할 수 없는 잠금은 파일·프로세스 정보를 보존한 채 담당자가 확인한다.

UI 감리 자료와 저장소 전체 패키지는 실제 기관의 최종 감리·도입 승인·운영 전환 절차를 대신하지 않는다. 개인정보 검출 패턴에 걸리지 않은 값도 입력자가 비식별 여부를 확인해야 한다.

## 유지보수 검증

```powershell
npm run test:requirements-workspace
node tools/requirements-workspace/build-styles.mjs --check
```

브라우저 시험 `tools/requirements-workspace/browser-check.mjs`은 반드시 폐기 가능한 빈 합성 작업공간에서 실행한다. 실제 고객 작업공간에 시험 자료를 넣지 않는다. 토큰·실행 비밀·고객 자료를 CI artifact에 올리지 않는다.
