# 콘텐츠 운영 안내

기관 운영자(콘텐츠 담당자)와 도입 담당자가 읽는 안내다. 사용자에게 보이는 글·이미지·파일을 어느 화면에 올리는지, 콘텐츠 페이지를 어떻게 쓰고 게시하고 내리는지, 개인정보를 잘못 게시했을 때 무엇을 하는지를 적는다. 제품 결정은 [ADR-0039](../02-architecture/decisions/ADR-0039-cms-content-pages-first-scope.md)(콘텐츠 페이지 1차 범위)와 [ADR-0042](../02-architecture/decisions/ADR-0042-cms-operations-follow-up.md)(운영 보완)가 정본이고, 이 문서는 그 결정을 따르는 운영 절차의 정본이다. 이 문서와 화면의 확인 단계는 기관의 콘텐츠 운영 승인이나 개인정보 게시 검토를 대신하지 않는다.

메뉴 위치는 제품 기본 메뉴([메뉴 스냅숏](../../config/project-composer-menus.json)) 기준이다. 기관이 메뉴 관리에서 옮겼으면 그 위치를 따른다. 권한은 화면에 보이는 이름과 코드(`CMS_UPDATE` 등)를 함께 적고, 기본 배정은 [권한 원장](../../config/governance/permission-catalog.json)이 정본이다.

## 무엇을 어디에 올리나

| 올릴 것 | 관리 화면 | 기본 메뉴 위치 | 사용자가 보는 곳 | 내용 형식 |
|---|---|---|---|---|
| 콘텐츠 페이지(안내 페이지·업무 홈 소개) | `/admin/system/content-pages` | 관리 센터 > 콘텐츠 운영 > 콘텐츠 페이지 | `/pages/<주소>`, 안내 페이지 목록(`/pages`), 업무 홈 맨 위 소개, 기관이 연결한 메뉴 | 영역·단으로 짠 문서(본문·표, 이미지, 바로가기, 내려받기 파일) |
| 도움말 콘텐츠 | `/admin/system/hpcm` | 관리 센터 > 콘텐츠 운영 > 도움말 콘텐츠 관리 | 도움말 센터(`/help`)의 '도움말' 탭 | 분류 구분·명칭·설명. 그림·링크 없는 일반 글이며 줄바꿈은 지킨다(설명 4,000자) |
| 온라인 매뉴얼 | `/admin/uss/olh/online-manual` | 소통·지식 > 온라인 매뉴얼 관리 | 도움말 센터의 '온라인 매뉴얼' 탭 | 명칭·구분 코드·리소스 경로·설명. 일반 글이며 리소스 경로는 글자로만 보인다 |
| 위키·FAQ·Q&A | `/admin/help/faq?tab=WIKI`·`FAQ`·`QNA` | 소통·지식 > 엔터프라이즈 위키·자주 묻는 질문(FAQ)·질의응답(Q&A) | 같은 지식 허브 화면(로그인 사용자 누구나). FAQ·Q&A는 도움말 센터 탭에도 보인다 | 게시판 글 |
| 공지사항 | 공지 게시판 글쓰기(게시판 운영은 `/admin/community/boards/master`) | 관리 센터 > 콘텐츠 운영 > 게시판 관리 | 업무 홈 '최근 공지사항', 공지 게시판 목록 | 게시판 글 |
| 배너·팝업 | `/admin/system/banner` | 관리 센터 > 시스템 설정 > 배너 및 팝업 관리 | 업무 홈 아래쪽 배너, 업무 홈에 뜨는 공지 팝업 | 이미지·노출 기간 |
| 개인정보처리방침·이용약관 | `/admin/system/policies` | 관리 센터 > 권한·보안 > 개인정보처리방침·이용약관 | 일반 사용자가 읽는 화면이 아직 없다(아래) | 정책 유형 코드·제목·본문(4,000자) |

고르는 기준은 다음과 같다.

- 그림·내려받을 서식·바로가기를 섞거나 여러 단으로 배치해야 하는 안내, 업무 홈 맨 위 소개는 **콘텐츠 페이지**에 쓴다.
- 기능·용어 하나를 짧게 설명하는 글은 **도움말 콘텐츠**, 화면 사용 설명서 항목은 **온라인 매뉴얼**에 쓴다. 둘 다 그림·링크를 넣을 수 없는 일반 글이다.
- 묻고 답하는 짧은 글은 **FAQ**, 여럿이 함께 고쳐 가는 업무 지식은 **위키**, 사용자 문의와 답변은 **Q&A**에 쓴다.
- 날짜가 의미 있는 알림(일정 변경, 점검 안내)은 **공지사항**에 쓴다. 상단 고정·예약 게시는 게시판 기능([ADR-0040](../02-architecture/decisions/ADR-0040-board-operations-management.md))을 쓴다.
- 기간을 정해 눈에 띄게 알리는 홍보는 **배너·팝업**에 쓴다.

**개인정보처리방침·이용약관:** 정책 관리 화면에 쓴 본문은 지금 정책 조회 권한(`POLICY_READ`, 기본 관리자·시스템 그룹)이 있어야 읽는다. `/help/policies/<유형>` 화면이 있지만 관리자 조회 경로를 쓰므로 일반 사용자에게는 본문 대신 권한 안내가 보이고, 바닥글에도 링크가 없다. 공개 조회 경로를 여는 일은 별도 결정이다. 법령상 공개해야 하는 고지문은 기관이 공개 방법을 따로 정한다 — 콘텐츠 페이지도 로그인한 사용자에게만 보이므로 대신할 수 없다.

**메뉴 위치가 흩어져 있다.** 콘텐츠 페이지·도움말 콘텐츠·게시판 관리는 관리 센터 > 콘텐츠 운영, 배너·팝업은 관리 센터 > 시스템 설정, 정책은 관리 센터 > 권한·보안, 온라인 매뉴얼 관리와 위키·FAQ·Q&A는 소통·지식에 있다. 도움말 콘텐츠와 온라인 매뉴얼은 같은 도움말 권한(`HELP_CREATE`·`HELP_UPDATE`·`HELP_DELETE`)으로 관리하고 같은 도움말 센터에 보이지만 메뉴 영역이 다르다. ADR-0042는 메뉴 위치를 바꾸지 않았다 — 메뉴를 옮기는 일은 메뉴 데이터 변경이라 사용자 승인 대상이고, 이번에는 승인하지 않았다. 도입한 기관은 메뉴 관리에서 자기 메뉴를 옮길 수 있다.

## 콘텐츠 페이지 운영

### 상태와 관리 목록

| 상태 | 뜻 | 사용자에게 |
|---|---|---|
| 초안 | 한 번도 게시하지 않은 페이지 | 보이지 않는다 |
| 게시 중 | 지금 게시본이 있다 | 로그인한 사용자 누구나 읽는다 |
| 게시 중지 | 게시한 적이 있지만 내렸다. 주소가 고정돼 있고 그 주소로 가는 메뉴가 남아 있을 수 있다 | 없는 주소와 같은 화면('없거나 게시되지 않은 페이지입니다')이 보인다 |
| 보관 | 정리해 둔 페이지. 고치거나 게시하려면 보관을 먼저 해제한다 | 보이지 않는다 |

게시 중인 페이지도 초안을 고쳐 저장할 수 있다. 저장한 초안은 다시 게시하기 전까지 사용자에게 보이지 않고, 화면은 '게시본과 다른 저장 초안'이 있다고 표시한다.

관리 목록은 전체(보관 제외)·게시 대기·초안·게시 중·게시 중지·보관으로 거른다. **게시 대기**는 한 번도 게시하지 않은 초안과, 게시 중인데 저장한 초안이 게시본과 다른 페이지다(제목·요약·본문을 비교한다). 게시를 중지한 페이지는 고쳐 저장해도 게시 대기에 들지 않으므로 '게시 중지'에서 찾는다.

### 작성

1. **새 페이지:** 제목(256자)·주소·요약(4,000자, 제목 아래와 안내 페이지 목록에 보인다)을 정하고 시작 양식(빈 페이지·업무 안내·업무 홈 소개)을 고른다. 주소는 `/pages/` 뒤에 붙는 영문 소문자·숫자·하이픈(100자)이며 다른 페이지가 쓰는 주소는 쓸 수 없다. 처음 게시하면 주소가 고정된다 — 메뉴와 이미 나눈 링크를 지키기 위해서다.
2. **영역과 칸:** 페이지는 위에서 아래로 쌓는 영역(최대 50개)이다. 영역마다 단 구성(1단·2단 같은 너비·2단 왼쪽 좁게·3단)과 배경(기본·옅은 배경·강조 배경)·간격(좁게·보통·넓게)을 고른다. 칸마다 내용 하나를 둔다: 본문·표(표는 100행·20칸까지), 이미지, 바로가기(1~12개), 내려받기 파일. 좁은 화면에서는 영역 순서대로, 영역 안에서는 왼쪽 칸부터 한 줄로 보인다. 영역은 바로 아래에 새로 더하거나 복제할 수 있다. 복제한 영역에는 이미지·파일이 따라가지 않으므로 다시 올린다.
3. **링크 규칙:** 바로가기와 본문 링크는 `https` 주소, `/`로 시작하는 사이트 안 경로(예: `/pages/apply-guide`), `mailto:`, `tel:`만 쓸 수 있다. `http` 주소와 계정 정보가 든 주소는 받지 않는다.
4. **초안 저장:** 미완성 칸이 있어도 저장한다 — 고르지 않은 이미지, 설명 없는 이미지, 이름·주소가 빈 바로가기, 파일이 없는 내려받기 칸. 채운 값의 형식(링크 규칙·길이)은 초안에서도 검사하므로 허용하지 않는 주소는 초안이라도 저장되지 않는다. 초안을 저장해도 게시본은 바뀌지 않는다.
5. **미리보기:** 저장하지 않은 변경까지 넓은 화면·휴대전화 폭으로 바꿔 본다. 미완성 칸은 관리 미리보기에서만 점선 자리로 보이고, 사용자 화면에는 빈 칸·빈 바로가기를 그리지 않는다.
6. **여럿이 고칠 때:** 다른 사람이 먼저 저장했으면 저장·게시가 막히고 이 화면의 입력은 그대로 남는다. 필요한 부분을 따로 옮겨 둔 뒤 최신 내용을 불러온다.
7. **지난 본 되살리기:** 게시 이력에서 지난 게시본을 보고 '이 내용으로 편집하기'로 초안에 불러온다. 저장하기 전에는 아무것도 바뀌지 않고 주소·업무 홈 지정도 그대로다.
8. **열람 화면에서 고치기:** 관리 권한이 있으면 게시된 페이지의 '이 페이지 편집'으로 관리 화면의 그 페이지를 바로 연다.

### 게시 전 확인

게시는 **저장된 초안**을 새 게시본으로 만든다. 저장하지 않은 변경이 있으면 먼저 저장한다. 게시 검사는 모든 칸이 완성돼야 통과하고, 화면은 고칠 칸을 한 번에 표시한다.

- 이미지 칸: 이미지를 골랐고, 이미지 설명(대체 텍스트)을 썼거나 장식 이미지로 지정했다.
- 바로가기: 항목마다 이름과 주소가 있다.
- 내려받기 파일 칸: 파일이 1~10개이고 항목마다 표시 이름이 있다.
- 페이지에 보이는 내용이 하나 이상 있다.
- 게시 중인 페이지라면 지금 게시본과 내용이 다르다.

게시 단추를 누르기 전에 사람이 확인할 것은 다음과 같다.

1. **공개 범위:** 게시하면 로그인한 모든 사용자가 읽는다. 그룹·부서별로 가릴 수 없고, 메뉴 표시를 끈다고 숨겨지지 않는다 — 안내 페이지 목록과 주소로 닿는다.
2. **개인정보·내부 전용 내용:** 본문·표뿐 아니라 이미지 속 글자, 내려받기 파일 안의 내용과 파일 이름까지 본다. 개인 연락처·주민등록번호 같은 개인정보와 내부 결재 문서처럼 기관 안에서만 써야 할 자료를 올리지 않는다.
3. **시작 양식의 안내 문장:** '안내할 내용을 작성해 주세요.'처럼 시작 양식이 넣은 문장이 남아 있으면 화면이 알린다. 지우거나 실제 내용으로 바꾼다.
4. **변경 설명:** 게시할 때 적는 변경 설명(예: 문의처를 바꿈)은 게시 이력에 남아 관리 화면 조회 권한자가 본다. 개인정보를 적지 않는다.
5. **업무 홈 소개라면:** 모든 사용자의 업무 홈 맨 위에 보이므로 휴대전화 폭 미리보기까지 확인한다.

### 게시 뒤 사용자가 닿게 하기

- **주소:** 게시한 페이지는 `/pages/<주소>`로 열린다.
- **안내 페이지 목록:** 게시 중인 페이지는 메뉴에 걸지 않아도 `/pages` 목록에 최근 게시 순으로 보인다(제목·요약·게시일, 제목·요약 검색). 사용자는 바닥글의 링크로 들어온다. 통합 검색에는 나오지 않는다.
- **메뉴:** 일반 사용자 사이드바에 두려면 다음 순서를 따른다.
  1. 게시 중인 페이지의 편집 화면에서 '메뉴에 추가'로 메뉴 관리를 열고 둘 위치를 고른다. 메뉴 만들기·수정 권한(`MENU_CREATE`·`MENU_UPDATE`)이 필요하다.
  2. 일반 사용자 그룹이 보는 영역 아래에 둔다. 제품 기본 메뉴에서 나의 업무·소통·지식·참여는 일반 사용자 그룹(ROLE_USER)에도 보이지만, 관리 센터는 관리자 그룹(ROLE_ADMIN)에만 보인다. 상위 메뉴가 숨으면 하위 메뉴도 숨으므로 관리 센터 아래에 둔 메뉴는 일반 사용자에게 보이지 않는다.
  3. 메뉴 관리에서 그 메뉴를 보일 그룹마다 '메뉴 표시'를 켜고 저장한다. 새 메뉴는 저장 전에는 어느 그룹에도 보이지 않고, 저장하면 관리자 그룹(ROLE_ADMIN)에만 자동으로 보인다(상위 메뉴가 모두 보일 때). 표시를 바꾸려면 메뉴 수정 권한과 권한 설정 권한이 모두 필요하다.
  4. 메뉴 관리의 그룹 미리보기나 권한 그룹 관리의 '메뉴 미리보기'로 그 그룹의 사이드바에 보이는지 확인한다. 편집 화면도 이 주소로 가는 메뉴가 있는지, 관리자 그룹 밖의 그룹에 보이는지 알려 준다(메뉴·권한 그룹 조회 권한이 있을 때).

  메뉴 표시는 열람 권한이 아니다. 페이지 열람은 로그인만 요구하고 메뉴는 길 안내일 뿐이다. 메뉴를 저장할 때 페이지 게시 여부를 검사하지 않으므로, 게시를 중지하거나 파기한 페이지로 가는 메뉴는 메뉴 관리에서 직접 정리한다. 메뉴 관리와 권한 작업대의 화면 흐름은 [과업 흐름 안내](ui-ux-task-flow-optimization.md)에 있다.
- **업무 홈 소개:** 게시 중인 페이지 하나를 업무 홈 맨 위 소개로 지정한다(업무 홈 지정 권한 `CMS_HOME_UPDATE`). 업무 홈을 대체하지 않고 맨 위 조각으로만 보인다. 게시를 중지하면 소개에서도 내려가고, 다시 게시해도 저절로 돌아오지 않으므로 다시 지정한다.

### 게시 중지·보관·초안 삭제·파기의 차이

| 동작 | 할 수 있는 페이지 | 권한 | 사용자에게 | 남는 것 | 되돌리기 |
|---|---|---|---|---|---|
| 게시 중지 | 게시 중 | 게시(`CMS_PUBLISH`) | 바로 보이지 않는다. 업무 홈 소개와 안내 페이지 목록에서도 빠진다 | 초안·게시 이력·첨부·주소. 그 주소로 가는 메뉴도 남는다 | 다시 게시 |
| 보관 | 초안·게시 중지(게시 중이면 먼저 게시 중지) | 게시(`CMS_PUBLISH`) | 보이지 않는다 | 모두 남는다. 기본 목록에서 빠지고 고치거나 게시할 수 없다 | 보관 해제 |
| 초안 삭제 | 한 번도 게시하지 않은 페이지 | 작성(`CMS_UPDATE`) | 보인 적이 없다 | 남지 않는다. 주소를 다시 쓸 수 있고 첨부는 페이지에서 풀린다 | 없다 |
| 파기 | 게시 중이 아닌 페이지, 또는 지금 보이지 않는 지난 게시본 | 파기(`CMS_PURGE`) | — | 남지 않는다([사고 대응](#사고-대응--개인정보를-잘못-게시했을-때)) | 없다 |

게시를 중지해도 초안·게시 이력·첨부는 관리 화면 조회 권한자에게 계속 보인다. 게시한 적이 있는 페이지는 삭제할 수 없다 — 보관하거나, 지워야 할 내용이 있으면 파기 권한자에게 요청한다.

### 작성과 게시를 나눠 맡기기

| 권한 묶음 | 권한 | 맡기는 일 |
|---|---|---|
| 콘텐츠 페이지 작성 | `CMS_ADMIN_READ`·`CMS_UPDATE`·`FILE_UPLOAD` | 초안 작성·저장, 이미지·파일 올리기, 한 번도 게시하지 않은 페이지 삭제 |
| 콘텐츠 페이지 관리 | 위 셋과 `CMS_PUBLISH`·`CMS_HOME_UPDATE` | 위 일과 게시·게시 중지·보관, 업무 홈 소개 지정 |

기본으로는 관리자·시스템 그룹(ROLE_ADMIN·ROLE_SYSTEM)에 관리 화면 조회·작성·게시·업무 홈 지정 권한이 있다. 다른 담당자에게 맡기려면 권한 그룹 관리(`/admin/security/authority`)에서 그 담당자가 속한 그룹을 골라 '권한 묶음 적용'으로 묶음을 더하고 '권한 변경 저장'으로 저장한다. 묶음은 그룹이 아니고 사용자에게 바로 배정되지 않는다 — 그룹 구성원 모두가 권한을 받는다.

작성과 게시를 나누면 다음처럼 일한다.

1. 작성자가 초안을 쓰고 저장한다. 작성 권한만 있는 사람에게 편집 화면은 게시는 게시 권한자가 한다는 것과 저장한 초안이 게시 대기 목록에 보인다는 것을 알린다.
2. 게시 요청 상태나 알림은 없다. 작성자는 기관이 정한 방법(쪽지·메일 등)으로 게시자에게 알린다.
3. 게시자는 목록의 '게시 대기'에서 페이지를 열어 미리보기와 [게시 전 확인](#게시-전-확인)을 한 뒤 게시한다.
4. 고칠 점이 있으면 게시자가 직접 고치거나 작성자에게 돌려보낸다. 페이지당 초안은 하나라 두 사람이 같은 초안을 고친다.

## 사고 대응 — 개인정보를 잘못 게시했을 때

먼저 사용자에게서 내리고, 그다음 지운다. 파기는 되돌릴 수 없다.

1. **바로 내린다.** 게시 권한자가 그 페이지를 게시 중지하거나, 문제 내용을 뺀 본을 저장해 다시 게시한다(다시 게시한 본이 지금 보이는 게시본이 된다). 게시를 중지하면 업무 홈 소개에서도 내려간다. 이 단계만으로는 지난 게시본·초안·첨부가 남아 관리 화면 조회 권한자가 계속 볼 수 있다. 사용자가 이미 내려받은 파일은 회수할 수 없다.
2. **초안도 고친다.** 다시 게시했다면 초안은 이미 고친 본이다. 게시 중지만 했고 페이지를 파기하지 않을 거라면 초안에서 문제 내용을 빼고 저장한다. 초안에서 뺀 이미지·파일은 어느 게시본도 쓰지 않을 때 저장과 함께 페이지에서 풀린다.
3. **처리 근거 번호를 받는다.** 기관의 사고·민원 접수 번호 같은 번호다. 영문·숫자와 `.`·`_`·`-`만 쓰고, 첫 글자는 영문이나 숫자이며, 200자 이내다. 감사에는 이 번호만 남고 사유 글은 남지 않으므로 경위·사유는 그 번호로 기관 대장에 적는다. 번호에 이름이나 개인정보를 넣지 않는다.
4. **파기 권한을 잠시 준다.** `CMS_PURGE`(콘텐츠 페이지 · 파기)는 기본 그룹도 권한 묶음도 없다. 권한 그룹 관리에서 그룹을 골라 '기능별 권한' 탭에서 이 권한을 더하고 '권한 변경 저장'으로 저장한다. 그룹에 준 권한은 구성원 모두가 받으므로 처리 담당자만 든 그룹에 준다. 파기는 콘텐츠 페이지 관리 화면에서 하므로 담당자에게 관리 화면 조회 권한(`CMS_ADMIN_READ`)도 있어야 한다. 권한 변경은 권한 변경 이력에 남는다.
5. **파기한다.**
   - **지난 게시본 파기:** 문제 내용이 지난 게시본에만 남았을 때(고친 본을 다시 게시한 경우) 쓴다. 게시 이력에서 그 판을 골라 처리 근거 번호와 함께 파기한다. 지금 사용자에게 보이는 게시본은 파기할 수 없다 — 고친 본을 다시 게시하거나 게시를 중지한 뒤 한다. 그 게시본만 쓰던 이미지·파일은 초안도 쓰지 않으면 함께 지운다. 파기한 판보다 뒤의 판 번호는 하나씩 당겨진다(예: 5판 가운데 3판을 파기하면 4판이 3판, 5판이 4판이 된다). 여러 판을 파기할 때는 한 판씩 지우고 번호를 다시 확인한다.
   - **페이지 파기:** 페이지가 통째로 필요 없을 때 쓴다. 게시 중이면 먼저 게시를 중지한다. 확인을 위해 주소(`/pages/` 뒤)를 한 번 더 입력하고 처리 근거 번호와 함께 파기한다. 초안·모든 게시본·페이지의 이미지·파일이 지워지고, 업무 홈 지정이 남아 있으면 함께 풀린다. 주소는 다른 페이지가 다시 쓸 수 있게 된다. 그 주소로 가는 메뉴는 남으므로 메뉴 관리에서 지운다.
6. **권한을 회수한다.** 같은 화면에서 `CMS_PURGE`를 빼고 저장한다.
7. **확인한다.** 관리 목록과 게시 이력에 지울 판이 남지 않았는지 본다.

알아 둘 점은 다음과 같다.

- **되돌릴 수 없다.** 휴지통이 없다. 화면이 읽은 뒤 다른 사람이 먼저 바꿨으면 파기가 막힐 뿐, 확정된 파기는 복구하지 않는다.
- **감사에는 근거 번호만 남는다.** 파기는 민감 작업 감사에 작업 종류(페이지 파기 `CMS_PAGE_PURGE`, 게시본 파기 `CMS_REVISION_PURGE`)·대상 번호·처리 근거 번호·처리자·시각으로 남는다. 사유 본문은 받지 않는다. 게시·게시 중지·업무 홈 변경·초안 삭제도 민감 작업 감사에 남는다. 감사 기록 화면(`/admin/system/logs/audit`)은 감사 조회 권한(`ADT_LOG_READ`, 기본 그룹 없음)이 필요하다.
- **다른 업무가 같은 첨부를 쓰면 파일은 남는다.** 페이지에서 풀린 이미지·파일은 다른 업무 참조(게시판 글 등)가 하나도 없을 때만 지운다. 참조를 확인하지 못해도 지우지 않는다. 남은 파일은 그 업무 화면에서 따로 지운다.
- **실물 파일은 파기가 확정된 뒤 지운다.** 저장소의 실물 삭제는 후속 작업으로 돌고 실패하면 다시 시도한다. 끝내 실패한 작업은 [후속 작업 재처리](../04-operations/durable-work-recovery.md)를 따른다.
- **백업에는 남는다.** 파기 전에 받은 DB·첨부 백업 세트에는 그 내용이 남는다. 백업 보존·파기는 기관 백업 통제가 정한다([백업·복원 런북](../04-operations/backup-and-restore-runbook.md)).
- **노출 범위:** 이미지·파일을 내려받은 기록은 개인정보 접속기록에 남는다([첨부](#첨부-이미지와-내려받기-파일)). 노출 범위를 따질 때 기관 절차에 따라 참고한다.

## 첨부: 이미지와 내려받기 파일

| 구분 | 이미지 칸 | 내려받기 파일 칸 |
|---|---|---|
| 형식 | png·jpg·jpeg·gif | pdf·hwp·doc·docx·xls·xlsx·ppt·pptx·txt |
| 사용자에게 | 본문 안에 그림으로 보인다 | 이름 목록으로 보이고 골라서 내려받는다 |
| 게시 조건 | 이미지를 고르고 설명(대체 텍스트, 300자)을 쓰거나 장식 이미지로 지정한다. 캡션은 선택이다 | 칸마다 1~10개, 항목마다 표시 이름(200자) |
| 받지 않는 형식 | SVG(문서 안에 스크립트를 실을 수 있다), webp(일반 업로드가 받지 않는다), bmp | 압축 파일(안을 볼 수 없다) |

두 칸에 공통인 규칙은 다음과 같다.

- **올리기:** 파일 올리기 권한(`FILE_UPLOAD`)이 필요하고 한 번에 파일 하나씩 올린다. 파일 하나는 기본 10MB까지다(배포 설정 `FILE_UPLOAD_MAX_SIZE`).
- **페이지에 붙는 때:** 올린 사람 본인이 초안을 저장할 때 그 페이지에 붙는다. 다른 사람이 올린 파일은 붙일 수 없다.
- **한 첨부는 한 페이지에만:** 다른 페이지가 쓰는 파일은 쓸 수 없으므로 새로 올린다. 한 페이지 안에서도 같은 파일을 두 칸에 쓰거나 이미지와 내려받기 파일로 함께 쓰지 않는다. 영역을 복제하거나 다른 내용을 시작점으로 쓰면 첨부가 빠진다.
- **정리:** 초안에서 뺀 첨부는 어느 게시본도 쓰지 않으면 저장할 때 페이지에서 풀리고, 다른 업무도 쓰지 않으면 파일까지 지워진다. 게시본이 쓰는 첨부는 그 게시본이 남아 있는 동안 남는다 — 지난 게시본을 편집기로 불러와도 그림이 그대로 열린다. 페이지가 쓰는 파일은 일반 파일 화면에서 지울 수 없다.
- **누가 여나:** 지금 게시본이 쓰는 이미지·파일은 로그인 사용자가 연다. 다만 파일 열람·내려받기 권한(`FILE_READ`·`FILE_DOWNLOAD`, 기본 사용자 그룹에 있다)이 없는 그룹에게는 본문만 보이고 이미지 자리는 대체 표시가 된다. 초안·지난 게시본·게시 중지 페이지의 첨부는 관리 화면 조회 권한자(`CMS_ADMIN_READ`)와 첨부 전체 열람 권한자(`FILE_READ_ALL`)만 연다.
- **열람 기록과 화면 캐시:** 이미지를 그리거나 파일을 내려받을 때마다 일반 파일 경로의 기존 정책대로 개인정보 접속기록이 남는다(관리 센터 > 로그·모니터링 > 개인정보 조회 로그). ADR-0042는 이 정책을 바꾸지 않았다. 대신 화면은 로그인한 동안 이미 받은 이미지를 다시 받지 않으므로(ADR-0042 결정 8), 같은 그림을 여러 번 봐도 그만큼 기록이 거듭 쌓이지 않는다. 다른 브라우저나 기기에서 열면 다시 받고 다시 남는다.

## 도입 담당자가 정할 것

- **기능 선택:** 콘텐츠 페이지는 선택 기능 `cms`다. 빼면 관리 화면·열람 화면·권한·업무 홈 소개·안내 페이지 목록과 바닥글 링크가 함께 빠진다([ADR-0039](../02-architecture/decisions/ADR-0039-cms-content-pages-first-scope.md) 결정 1).
- **담당자와 권한:** 작성과 게시를 누구에게 맡길지, 파기 권한을 받을 사람과 처리 근거 번호 체계, 감사 기록을 볼 담당자를 정한다. `CMS_PURGE`·`ADT_LOG_READ`는 기본 그룹이 없다.
- **메뉴:** 일반 사용자 메뉴에서 안내 페이지를 둘 위치를 정한다. 제품 기본 메뉴에는 콘텐츠 페이지로 가는 일반 사용자 메뉴가 없다.
- **공지·FAQ 게시판:** 공지 게시판과 FAQ 게시판에 글을 쓰려면 각각 `NOTICE_EDIT`·`FAQ_EDIT`가 필요하고, 새로 설치하면 두 권한 모두 기본 그룹이 없다. 제품 기본 설정은 데모 시드에 맞춰 공지 게시판과 FAQ 게시판을 같은 게시판(`BBSMSTR_AAAAAAAAAAAA`)으로 두므로 그 게시판에 쓰려면 두 권한이 모두 필요하다. 서버 설정(`nuri.boards.notice-id`·`nuri.boards.faq-id`)과 화면 대응([board-ids.ts](../../frontend/src/config/board-ids.ts))을 함께 바꿔 나눌지 정한다.
- **정책 고지문:** 개인정보처리방침 등 공개 고지문을 사용자에게 보이는 방법을 정한다(위 [무엇을 어디에 올리나](#무엇을-어디에-올리나)).
- **링크:** 내부망 `http` 주소는 받지 않는다. 기관 요구가 확인되면 별도 결정으로 연다(ADR-0039 결정 6).

## 지금 하지 않는 것

권한 그룹별 열람, 로그인 없는 공개, 예약·승인 게시(게시 요청 상태·알림), 통합 검색 편입, 업무 홈 전체 대체, 문서 안 공지·도움말 목록, 콘텐츠 운영 메뉴 재배치, 페이지 조회 수 통계는 두지 않는다. 범위와 이유는 [ADR-0042](../02-architecture/decisions/ADR-0042-cms-operations-follow-up.md)의 남은 유보와 [ADR-0039](../02-architecture/decisions/ADR-0039-cms-content-pages-first-scope.md)의 유보에 있다.
