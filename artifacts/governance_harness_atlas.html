🛸 eGov Enterprise 거버넌스 철학 (Governance Philosophy)

eGov Enterprise 프로젝트는 "도구에 의한 강제성(Harness-driven Constraint)"을 근간으로 삼습니다. 에이전트가 코드를 작성하거나 수정할 때, 임의의 편의성에 의존하지 않고 사전에 정립된 3대 헌법과 8대 독점 스킬이 상호 맞물려 동작하도록 규율합니다. 본 포털 아틀라스는 에이전트와 엔지니어 모두가 참조하는 단일 진실의 원천(SSOT) 역할을 수행합니다.

Why Harness? (왜 하네스인가?)

LLM의 본질적 환각(Hallucination) 한계를 극복하고 엔터프라이즈급 코드 무결성을 담보하기 위한 필연적 선택

Problem

AI의 맹신과 컨텍스트 오염

자율 에이전트는 뛰어난 코딩 능력을 가지지만, 때로는 과거의 잘못된 기억에 의존하거나 임의의 로직을 추측하여 작성하는 '환각 현상'이 발생합니다. 이는 곧 치명적인 프로덕션 장애로 이어집니다.

Mechanism

도구에 의한 절대적 통제

하네스(Harness)는 에이전트에게 코딩 자율성을 주되, 결코 벗어날 수 없는 '안전 벨트(Safety Guardrails)'를 채우는 인프라입니다. 모든 수정은 헌법 검증과 스킬 오딧을 강제 통과해야만 허용됩니다.

Solution

증거 기반 자율 복구

하네스는 에이전트가 "완료했습니다"라는 말을 금지시킵니다. 오직 JVM 에러 로그, Playwright E2E 성공 증거, 픽셀 렌더링 검증 결과만을 진실로 취급하며, 실패 시 Ralph Loop를 통해 스스로 치유합니다.

💎 하네스가 제공하는 3대 궁극적 가치 (Core Values)

Zero Downtime DB 마이그레이션, 아키텍처 개편 등 위험도 높은 L2 태스크 수행 시 DDL Lock이나 하위 호환성 단절로 인한 서비스 중단(Downtime)을 100% 원천 차단합니다.
Cross-Module Type Safety Next.js 프론트엔드와 Spring Boot 백엔드 간의 느슨한 API 계약을 강력하게 결속시켜, 백엔드 DTO 변경 시 프론트엔드 타입 에러를 컴파일 타임에 완전 방어합니다.
Docs-as-Code Sync 시스템 로직이 변경되면 관련 아키텍처 다이어그램과 Markdown 사양이 동시에 자율적으로 업데이트되어, 코드와 문서 간의 노후화 및 부채(Drift)를 제로화합니다.

01. 3대 기술 헌법

프로젝트의 아키텍처적 일관성과 안정성을 담보하는 세 가지 불가침 법령

⚖️ 헌법별 핵심 통제 조항 해설 (Key Constitutional Articles)

DB 제7조 & 제8조

무중단 이행 & 논리삭제 원칙

모든 테이블 변경은 Expand-and-Contract (확장 후 축소) DDL 단계를 무조건 준수해야 하며, 데이터 삭제는 USE_YN = 'N' 등의 Soft Delete(논리삭제)로만 이행됩니다.

BE 제16조 & 제17조

돌연변이 85% & Validation 거울 동기화

백엔드 테스트 보장을 위해 돌연변이 테스트 Score 85% 이상을 만족해야 하며, DB 컬럼 제약조건 ➔ BE DTO 어노테이션 ➔ FE Zod 스키마로 이어지는 Validation 단방향 거울 동기화를 강제합니다.

FE 제1조 & 제4조

Hydration 방어 & 프리미엄 UI

서버/클라이언트 간 렌더링 불일치로 인한 Hydration 오류를 방지하기 위해 dynamic loading을 적용하고, 아틀라스가 정의한 HSL 그라데이션, 글래스모피즘 등의 프리미엄 디자인 토큰을 엄격히 준수합니다.

🚨 헌법 불가침 원칙 (Constitutional Absolute Protection)

위 3대 기술 헌법 파일(`constitution.md`)은 사용자의 명시적이고 독점적인 승인 없이는 에이전트가 단독으로 절대 수정할 수 없습니다. 위반 사례 발견 시 파이프라인 상의 api-contract-guardian 및 owasp-security-auditor가 빌드 진행을 즉시 중단(Hard-Stop)시킵니다.

02. GEMINI.md 규칙 (GEMINI.md Ruleset)

프로젝트 개발 시 에이전트가 최우선으로 참고하는 법령 및 Gotchas

핵심 운영 명령어 매트릭스

명령어 위치 목적 관련 스킬

💡 에이전트 트러블슈팅 매트릭스 (Gotchas)

🧹 로컬 브릿지 및 리소스 위생 규칙

포트 충돌(8080/3001) 발생 시 즉시 백그라운드 좀비 프로세스를 킬(KILL)하고 자가 수리합니다. 개발 디바이스의 네트워크 및 프로세스 무결성은 `resilience-debugger` 스킬이 독점적으로 통제합니다.

또한, 철저한 논리삭제 원칙 하에서도 테스트 환경(`test_` 접두사 등)에서 발생한 가비지 데이터의 클린업(물리 삭제)은 에이전트의 기동성을 위해 자율 수행이 예외적으로 허용됩니다.

🔑 401 인증 장애 해결을 위한 쿠키-헤더 동기화 매핑 도식

백엔드 Spring Security의 Stateless JWT 필터와 프론트엔드 Next.js 미들웨어 간 쿠키/헤더 위상 매핑 구조입니다. 401 발생 시 이 결속망을 대조합니다.

├── 1. Bearer Token JWT Parse & Validation

03. Strict Orchestration Protocol (SOP)

메인 에이전트와 서브에이전트 간의 정형화된 오케스트레이션 파이프라인

태스크 등급 분류 체계 (Task Grading)

에이전트는 작업 수신 즉시 아래 명세에 따라 작업 강도를 객관적으로 판정하여 사용자에게 TASK PROPOSAL을 발행해야 합니다.

등급 정의 통과 경로 기동 스킬셋
L0 (Trivial) 단순 오타, 주석 수정, 단순 CSS 스타일 보완 Fast-Track (사용자 승인 생략 가능) caveman
L1 (Standard) 단일 로직 수정, 컴포넌트 추가, 버그 패치 Standard Path (Task Specification 발행 및 감사) gstack-review
L2 (Critical) DB 스키마 개정, 아키텍처 개편, 다중 모듈 수정, 보안 로직 Strict SOP Full-Pipeline (서술형 감사 및 헌법 대조) deep-context-mapper, zero-downtime-migration-planner

04. 거버넌스 작동 워크플로우

명령 접수부터 검증 완료까지, 헌법과 스킬이 작동하는 엔터프라이즈 오케스트레이션 파이프라인

Step 1. 사용자 명령 수신 및 작업 등급 판정

사용자의 요구사항을 수신하면, GEMINI.md의 Task Grading 규칙에 따라 작업의 위험도를 평가(L0/L1/L2)하고 TASK PROPOSAL을 출력하여 작업의 투명성을 확보합니다.

Step 2. 헌법 준수 모드 (Guardian Mode) 가동

.agent/knowledge/ 에 위치한 3대 기술 헌법(DB/BE/FE)을 사전 조회하여, 논리삭제 여부, 데이터 제약조건, Zod 스키마 명명 규칙 등의 프로젝트 메타 제약조건(SSOT)을 에이전트의 뇌에 장착시킵니다.

Step 3. 도메인 맞춤형 스킬 발동 (Skill Dispatch)

분석된 작업 성격에 따라 8대 독점 스킬을 선택적으로 교차 호출하여 코드를 작성합니다.
[DB] Zero-Downtime Planner (무중단 4단계 이행)
[BE] API Contract Guardian (단방향 거울 동기화 검증)
[FE] Visual Auditor (픽셀 및 애니메이션 검증)

Step 4. 증명 및 자가 성찰 (Ralph Loop 2.0)

코드 구현이 완료되면 즉시 Mutation Testing (85% 검증) 및 Playwright E2E 테스트를 실행합니다. 오류 감지 시 무작위 추측을 엄격히 금지하고, Resilience Debugger를 통해 물리적 증거 기반의 4단계 자가 복구 루프를 가동합니다.

Step 5. 진실의 원천 동기화 (Docs-as-Code Sync)

모든 무결성 방어막을 통과하면, docs-as-code-sync 엔진이 관련 마크다운 가이드와 아키텍처 다이어그램을 최신 상태로 자율 동기화하고, 최종 무결성 증명 리포트를 제출합니다.

프롬프트가 입력되었을 때 에이전트가 어떤 순서와 도구를 활용해 무결성을 통제하고 자동 수행하는지 보여주는 역동적 시뮬레이터

07. Database Governance & Safety Bridge

엄격하게 분리된 물리 스키마 사양과 자율 탐색 기동성을 보장하는 OCI PostgreSQL 17 보안 접근 구조

📊 물리 데이터베이스 스키마 카탈로그 (Database Physical Inventory)

`egov-enterprise` 프로젝트의 OCI PostgreSQL 17 스키마는 헌법 제2조에 의거하여 아래와 같이 철저히 분류 및 통제됩니다. 임의의 테이블 생성 및 약어 네이밍은 파이프라인에서 원천 거부됩니다.

테이블 카테고리 테이블 명칭 표준 (Naming Standard) 물리 개수 메타 거버넌스 무결성 보증 규정
표준 비즈니스 테이블 tb_[도메인]_[업무주체] (소문자 Snake Case) 93개 [3대 메타 표준 강제 적용] 컬럼명은 반드시 meta_standard_words로 구성하고, 데이터 타입은 meta_standard_domains에 바인딩된 사양을 100% 동일하게 이행함.
표준 메타 테이블 meta_standard_[사전종류] 3개 전사 진실의 단일 원천(SSOT). meta_standard_words(단어 사전), meta_standard_terms(용어 사전), meta_standard_domains(도메인 사전)으로 구성됨.
인프라 관리용 테이블 flyway_*, ids, revinfo, ecopseq 4개 Flyway 스키마 이력 관리, eGov 프레임워크 표준 ID 제네레이터 및 Hibernate 감사 로그 레코드 인프라 테이블.
물리 스키마 총합 - 100개 무중단 이행 지침 및 헌법에 따라 형상 관리되는 eGov Enterprise v5 완결 데이터 모델.

08. 자가 성찰 오류 복구 프로토콜 (Ralph Loop 2.0)

오류 감지 시 무작위 수정을 배제하고 근본적인 물리 원인을 찾아 치유하는 4단계 복구 서클

1단계: 멈춤 및 가설 수립 (Formulate Hypothesis)
에러 감지 즉시 코드 변경을 중단하고 "어떤 가정이 잘못되었는가?"에 대한 근본 가설 정립
2단계: 표적 조사 및 증거 수집 (Target Investigation)
resilience-debugger 가동 및 Playwright 스크린샷/WebP 비디오와 JVM 로그 교차 검증 (교차검증 의무)
3단계: 성찰 리포트 출력 (Report Generation)
수정 개시 전 [SELF-REFLECTION REPORT] 형식의 초정밀 오류 원인 보고 의무 출력

에이전트가 동일한 오류 또는 빌드 컴파일 실패에 대해 3회 연속 성찰 루프를 돌았음에도 해결하지 못한 경우, 자가 치유 한계를 선언하고 무작위적인 삽질 수정을 영원히 방지하기 위해 즉시 인간 엔지니어에게 **에스컬레이션(보고 및 중단)**을 선언합니다.

[에스컬레이션 단계별 수행 프로토콜]
  1. 자가 수정 영구 Hard-Stop: 즉시 소스코드 변경 시도를 영구히 중지합니다.
  2. 브레인 덤프(Brain Dump) 아카이빙: 지금까지 거쳐온 3회의 성찰 보고서 히스토리와 오류 메시지를 요약합니다.
  3. Playwright 시각적 증거 영구 보존: artifacts 디렉토리에 실패한 브라우저의 DOM 덤프, 스크린샷 및 WebP 세션 동영상 영구 복사 및 보존.
  4. 엔지니어 알람: 사용자 대화창에 [SYSTEM ESCALATION REPORT] 블록을 띄워 트레이드오프 및 인간 개입을 공식적으로 요청합니다.
