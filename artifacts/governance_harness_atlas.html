🛸 eGov Enterprise 거버넌스 철학 (Governance Philosophy)

eGov Enterprise 프로젝트는 "도구에 의한 강제성(Harness-driven Constraint)"을 근간으로 삼습니다. 에이전트가 코드를 작성하거나 수정할 때, 임의의 편의성에 의존하지 않고 사전에 정립된 3대 헌법과 8대 독점 스킬이 상호 맞물려 동작하도록 규율합니다. 본 포털 아틀라스는 에이전트와 엔지니어 모두가 참조하는 단일 진실의 원천(SSOT) 역할을 수행합니다.

01. 3대 기술 헌법 (The 3 Constitutions)

프로젝트의 아키텍처적 일관성과 안정성을 담보하는 세 가지 불가침 법령

Database

DB 표준화 헌법 (8조)

  • 물리 테이블 표준 접두사 필행 (`tb_`)
  • `meta_standard_words` 메타 테이블 준수
  • 모든 플래그 컬럼은 `CHAR(1)` 타입 고정
  • 인덱스/제약조건 네이밍 표준화 이행
Backend

백엔드 API 헌법 (15조)

  • 컨트롤러에서 DB 엔티티 반환 절대 금지
  • Unified Response 래퍼 클래스 필수 사용
  • 서비스 레이어 내 JWT 기반 2차 인가 검증
  • 트랜잭션 격리수준 및 읽기전용 최적화
Frontend

프론트엔드 UX 헌법 (12조)

  • Server Component 우선주의 (SSR 최적화)
  • 하드코딩 배제 및 정의된 CSS 디자인 토큰 준수
  • API 호출 시 Next.js App Router 최적 통신
  • 반응형 및 프리미엄 글래스모피즘 에스테틱

🚨 헌법 불가침 원칙 (Constitutional Absolute Protection)

위 3대 기술 헌법 파일(`constitution.md`)은 사용자의 명시적이고 독점적인 승인 없이는 **에이전트가 단독으로 절대 수정할 수 없습니다.** 위반 사례 발견 시 파이프라인 상의 api-contract-guardian 및 owasp-security-auditor가 빌드 진행을 즉시 중단(Hard-Stop)시킵니다.

02. GEMINI.md 규칙 (GEMINI.md Ruleset)

프로젝트 개발 시 에이전트가 최우선으로 참고하는 법령 및 Gotchas

핵심 운영 명령어 매트릭스

명령어 위치 목적 관련 스킬
npm run dev Root 전체 로컬 개발 서버 동시 구동 (Port 8080 / 3001) resilience-debugger
npm run codegen:ts frontend/ Swagger OpenAPI 명세 기반 프론트엔드 TS 타입 자동 생성 api-contract-guardian
npm run test:e2e frontend/ Playwright 기반 E2E 전체 Tiers 자동 테스트 visual-auditor
make coverage Root Jacoco 통합 백엔드 테스트 커버리지 리포트 생성 mutation-testing-auditor

💡 에이전트 트러블슈팅 매트릭스 (Gotchas)

  • 🔒 인증(401) 장애: `AuthContext`의 `accessToken`과 브라우저 쿠키의 동기화 상태를 디버깅 시 최우선 확인.
  • ⚙️ 타입 에러: DTO 수정 시 반드시 `npm run codegen:ts`를 자동 선행 가동하여 `generated-api.d.ts`를 갱신.
  • 🌀 컴포넌트 렌더링: 훅(Hook) 사용 여부에 따라 `'use client'` 필요 위치를 명확히 진단. 기본은 Server Component.

🧹 로컬 브릿지 및 리소스 위생 규칙

포트 충돌(8080/3001) 발생 시 즉시 백그라운드 좀비 프로세스를 킬(KILL)하고 자가 수리합니다. 개발 디바이스의 네트워크 및 프로세스 무결성은 `resilience-debugger` 스킬이 독점적으로 통제합니다.

03. Strict Orchestration Protocol (SOP)

메인 에이전트와 서브에이전트 간의 정형화된 오케스트레이션 파이프라인

태스크 등급 분류 체계 (Task Grading)

등급 정의 통과 경로 기동 스킬셋
L0 (Trivial) 단순 오타, 주석 수정, 단순 CSS 스타일 보완 Fast-Track (사용자 승인 생략 가능) caveman
L1 (Standard) 단일 로직 수정, 컴포넌트 추가, 버그 패치 Standard Path (Task Specification 발행 및 감사) gstack-review
L2 (Critical) DB 스키마 개정, 아키텍처 개편, 다중 모듈 수정, 보안 로직 Strict SOP Full-Pipeline (서술형 감사 및 헌법 대조) deep-context-mapper, zero-downtime-migration-planner

프롬프트가 입력되었을 때 에이전트가 어떤 순서와 도구를 활용해 무결성을 통제하고 자동 수행하는지 보여주는 역동적 시뮬레이터

05. 8대 네이티브 고성능 엔진 (8-Pillar Skills Engine)

구 프롬프트 방식의 오버헤드를 탈피하여 안티그래비티 런타임에 완벽히 장착된 8가지 고유 독점 스킬

Skill 01

Deep Context Mapper

1M+ 대용량 토큰 샌드박스를 활용하여 복잡한 다중 Gradle 모듈 및 PostgreSQL 물리 스키마의 상관 위상(Topology) 지도를 구성하여 완벽한 컴파일 안정성을 달성합니다.

Skill 02

Visual Auditor

browser_subagent 네이티브를 연동하여 프론트엔드 픽셀 및 반응형 레이아웃 깨짐을 실시간으로 비교 검증하고 WebP 시각 아티팩트를 자동 수립합니다.

Skill 03

Resilience Debugger

포트 충돌 등 런타임 예외 감지 시 DB Bridge 연동 및 로컬 프로세스 기동성을 자동 복구 및 포트 정리하여 자가 치유(Self-Healing)를 가동합니다.

Skill 04

API Contract Guardian

Spring Boot DTO/Controller와 Next.js 타입 간의 Breaking Change를 OpenAPI 명세 대조를 통해 사전에 100% 추론 및 파괴를 완전 방어합니다.

Skill 05

OWASP Security Auditor

JWT 설정 및 Spring Security 체인 변경 시 Red Team 공격자 관점에서 취약점 정밀 정적 분석 및 침투 검증 시나리오를 자율 실행합니다.

Skill 06

Docs-as-Code Sync

로직이 수정될 때마다 아키텍처 문서 및 Mermaid 다이어그램을 코드를 기반으로 자율 역추적하여 최신화하여 문서 노후화를 방지합니다.

Skill 07

Mutation Testing Auditor

테스트의 강건성을 검증하기 위해 실제 비즈니스 코드에 의도적으로 미세한 논리 돌연변이(버그)를 삽입해 테스트 코드가 실패하는지 수학적으로 검증합니다.

Skill 08

Zero-Downtime Planner

PostgreSQL 스키마 변경 시 DDL Lock으로 인한 다운타임을 원천 차단하기 위해 phased 'Expand and Contract' SQL 설계 패턴을 강제 이행시킵니다.

06. Database Governance & Safety Bridge

엄격하게 분리된 물리 스키마 사양과 자율 탐색 기동성을 보장하는 OCI PostgreSQL 17 보안 접근 구조

📊 물리 데이터베이스 스키마 카탈로그 (Database Physical Inventory)

`egov-enterprise` 프로젝트의 OCI PostgreSQL 17 스키마는 헌법 제2조에 의거하여 아래와 같이 철저히 분류 및 통제됩니다. 임의의 테이블 생성 및 약어 네이밍은 파이프라인에서 원천 거부됩니다.

테이블 카테고리 테이블 명칭 표준 (Naming Standard) 물리 개수 메타 거버넌스 무결성 보증 규정
표준 비즈니스 테이블 tb_[도메인]_[업무주체] (소문자 Snake Case) 93개 [3대 메타 표준 강제 적용] 컬럼명은 반드시 meta_standard_words로 구성하고, 데이터 타입은 meta_standard_domains에 바인딩된 사양을 100% 동일하게 이행함.
표준 메타 테이블 meta_standard_[사전종류] 3개 전사 진실의 단일 원천(SSOT). meta_standard_words(단어 사전), meta_standard_terms(용어 사전), meta_standard_domains(도메인 사전)으로 구성됨.
인프라 관리용 테이블 flyway_*, ids, revinfo, ecopseq 4개 Flyway 스키마 이력 관리, eGov 프레임워크 표준 ID 제네레이터 및 Hibernate 감사 로그 레코드 인프라 테이블.
물리 스키마 총합 - 100개 무중단 이행 지침 및 헌법에 따라 형상 관리되는 eGov Enterprise v5 완결 데이터 모델.

⚖️ OCI PostgreSQL 17 이중 필터 권한 통제 매트릭스

에이전트가 PostgreSQL에 접속 시 실행하는 모든 쿼리는 안전 브릿지에 의해 검증되며, 파괴적인 행위와 단순 조회 행위로 엄격하게 분류됩니다.

권한 분류 대상 쿼리 / 데이터 조작 권한 등급 보안 메커니즘 및 면책 사유
면책 특권 (Exemption) SELECT ... FROM meta_standard_* 및 스키마 구조 조회 자율 실행 (무승인) 거버넌스 정렬을 위해 메타 사전을 조회하는 행위는 탐색의 기동성 및 무결성 조회를 위해 사용자의 사전 개입을 배제하고 무제한 보장함.
진단 특권 (Diagnosis) 오류 복구(Ralph Loop 2.0) 중 DB 상태 확인을 위한 단순 SELECT 자율 실행 (무승인) 자가 치유(Self-Healing) 단계에서 장애 상황을 진단하기 위해 테이블을 읽는 행위는 에이전트 자율성 보장 범위에 포함됨.
DML 통제 대상 실제 업무 데이터에 대한 INSERT, UPDATE, DELETE 사전 승인 필수 운영 및 코어 비즈니스 데이터의 상태를 변조하는 작업은 글로벌 룰셋 §5(파괴적 작업 경계)에 따라 사용자 승인이 강제 통제됨.
DDL 통제 대상 스키마 객체 구조를 변경하는 ALTER, DROP, CREATE 사전 승인 필수 무중단 스키마 이행 지침(Zero-Downtime Migration Planner) 통과 의무가 있으며 최종 이행 전 무조건 사용자 하드락 승인이 요구됨.

07. 자가 성찰 오류 복구 프로토콜 (Ralph Loop 2.0)

오류 감지 시 무작위 수정을 배제하고 근본적인 물리 원인을 찾아 치유하는 4단계 복구 서클

1단계: 멈춤 및 가설 수립 (Formulate Hypothesis)
에러 감지 즉시 코드 변경을 중단하고 "어떤 가정이 잘못되었는가?"에 대한 근본 가설 정립
2단계: 표적 조사 및 증거 수집 (Target Investigation)
resilience-debugger 가동 및 Playwright 스크린샷/WebP 비디오와 JVM 로그 교차 검증 (교차검증 의무)
3단계: 성찰 리포트 출력 (Report Generation)
수정 개시 전 [SELF-REFLECTION REPORT] 형식의 초정밀 오류 원인 보고 의무 출력
4단계: 초정밀 수정 및 재검증 (Precision Fix & Re-Verify)
최소 범위의 코드만 정밀 패치하고 빌드/테스트 재실행 (3회 연속 실패 시 인간 에스컬레이션)

성찰 보고서 표준 템플릿

### 🔍 [SELF-REFLECTION REPORT] ###
- **오판 진단(False Assumption)**: {내가 맞다고 착각했던 아키텍처적 전제 조건}
- **근본 원인(Root Cause)**: {수집된 JVM/Playwright 물리 증거에 기반한 진짜 오류 원인}
- **해결 가설(New Hypothesis)**: {이를 콤팩트하게 파괴하지 않고 우회/교정할 대안}
- **부작용 검토(Side-Effect Check)**: {이 정밀 패치가 API 계약 및 타 레이어에 미칠 사이드이펙트 분석}
