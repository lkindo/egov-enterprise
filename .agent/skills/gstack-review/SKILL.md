# GStack Persona Review Protocol

본 스킬은 복잡한 리팩토링이나 신규 기능 구현 전, 세 가지 전문 페르소나의 관점에서 계획을 비판적으로 검토하여 품질을 극대화한다.

## 1. 페르소나 정의 및 체크리스트

### 👤 CEO (Product & Strategy)
**"가장 단순하고 가치 있는 해결책인가?"**
- [ ] 현재 계획이 문제의 핵심을 관통하는가, 아니면 겉핥기인가?
- [ ] 더 단순한(Simple) 대안은 없는가? (YAGNI 원칙 준수 여부)
- [ ] 리팩토링의 ROI(투자 대비 효과)가 확실한가?

### 👤 Engineering Manager (Architecture & Scope)
**"시스템적으로 올바르고 유지보수 가능한가?"**
- [ ] 현재 프로젝트의 아키텍처 규칙(`GEMINI.md`)을 준수하는가?
- [ ] 데이터 모델링 및 인터페이스 정의가 명확하고 일관적인가?
- [ ] 작업 범위(Scope)가 적절하게 쪼개져 있는가? (과도한 변경 방지)

### 👤 Paranoid Senior Engineer (Edge Cases & Safety)
**"어디가 터질 것인가? 무엇이 잘못될 수 있는가?"**
- [ ] **데이터 유실**: 마이그레이션이나 DB 변경 시 데이터 소실 위험은 없는가?
- [ ] **성능**: 대용량 데이터 환경에서도 인덱스나 쿼리가 효율적인가?
- [ ] **보안/권한**: 인증되지 않은 접근이나 권한 누출 가능성은 없는가?
- [ ] **롤백**: 실패했을 때 안전하게 되돌릴 수 있는가?

## 2. 실행 절차 (Light Version)

1.  계획 초안 수립 후 본 스킬을 호출한다.
2.  각 페르소나의 의견을 **핵심 1문장**으로 요약한다.
3.  전체 결과를 아래와 같이 콤팩트하게 보고한다.

```markdown
### 🔍 GStack Lite Review
- **Product(CEO)**: [가치/단순성 관점 핵심 1줄]
- **Arch(EM)**: [구조/범위 관점 핵심 1줄]
- **Safety(Paranoid)**: [리스크/엣지케이스 핵심 1줄]
- **Action**: [계획에 반영된 최종 한 줄]
```
