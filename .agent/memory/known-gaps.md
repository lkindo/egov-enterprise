# 공용 활성 Gap 인덱스

## 범위·상태 정의

이 파일은 현재 코드나 외부 실측으로 재현 가능한 미해결 위험의 얇은 인덱스다. 상세 원장은 링크된 문서·코드이며, 완료 이력은 Git에 남긴다.

- 우선순위: `P0` 즉시 안전/false-green, `P1` 높은 회귀·운영 위험, `P2` 계획 필요, `P3` 개선.
- 상태: `open`, `blocked-external`, `deferred`, `accepted-risk`, `needs-revalidation`.
- 추측이나 과거 task의 unchecked 항목만으로 새 gap을 만들지 않는다.

`GAP-OPS-002`(백업·DR), `GAP-SEC-001`(자격 회전), `GAP-DATA-001`(레거시 암호문), `GAP-AUTH-003`(인가 배포 검증)은 2026-09-21 사용자 결정으로 **기관 채택 수명으로 이전**했다(DEC-OPS-107). 원본 저장소에는 운영 환경이 없어 그 증거를 만들 대상 자체가 없고, 의무의 수신자가 원본이 아니라 채택 기관이다. 앞의 셋은 온라인 승인 통제 [`backup-recovery`·`crypto-lifecycle`](../../docs/03-guides/governance-review-lifecycle.md#3-온라인-제품의-기관-도입)로 옮겼고, `GAP-AUTH-003`은 새 통제를 만들지 않고 기존 `authorization` 통제의 검토 내용에 배포 시점 확인(앱 버전·구 writer 종료·로그인·복수 그룹·권한 회수·메뉴)으로 편입했다. [승인 검증기](../../scripts/adoption-review.mjs)가 근거 없는 승인을 거부하며, 이전 전 5통제 집합이 더 이상 승인되지 않는 것을 [계약](../../scripts/governance-review.test.mjs)이 대조군으로 고정한다. 원본에서 닫히지 않았다는 사실이 채택 환경에서 면제된다는 뜻은 아니다.

`GAP-SEC-003`(첨부 provenance census), `GAP-STORAGE-001`(정기 첨부 점검의 운영 실행·경보), `GAP-OPS-001`(운영 규모 부하·NVD 전량·인증 ZAP)은 2026-09-23 사용자 결정으로 같은 패턴을 따라 **기관 채택 수명으로 이전**했다(DEC-OPS-111). 온라인 승인 통제 [`attachment-operations`·`operational-assurance`](../../docs/03-guides/governance-review-lifecycle.md#3-온라인-제품의-기관-도입)가 그 증거를 요구하며, 이전 전 7통제 집합이 더 이상 승인되지 않는 것을 [계약](../../scripts/governance-review.test.mjs)이 대조군으로 고정한다. 원본에 남는 것은 증거가 아니라 설계 결정 둘이다 — 직접 DB 쓰기·import 경로에 첨부 provenance 강제를 둘지, 인증 ZAP context 를 compose seed-dev 계정에 결속할지(저장소 안에서 가능한 별건). 후자는 2026-09-24 주간 ZAP 이 개발 시드 관리자로 로그인해 OpenAPI 로 API 를 스캔하게 되며 닫혔다(DEC-OPS-126).

## 해결 규칙

gap을 해결하면 정본 코드·문서·테스트를 먼저 갱신하고, 회귀 방지 실행 경로와 red 증거를 확인한 뒤 활성 표에서 제거한다. 장기 결정이 생기면 ADR 또는 [decisions.md](decisions.md)에 링크하고 상세 이력은 중복 복사하지 않는다.
